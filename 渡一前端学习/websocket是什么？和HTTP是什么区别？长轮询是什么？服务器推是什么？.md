## 💻 服务器向客户端推送消息的几种方案

当需要在用户不主动操作（如点击或刷新）的情况下，网页（客户端）能实时收到服务器端更新的消息并发生变更时，主要有以下几种实现方式：

### 1. 轮询 (Polling) / 定时轮询 (HTTP Polling)

- **原理：** 客户端（浏览器）使用 JavaScript **定时**向服务器发送 **HTTP 请求**来询问是否有新的数据。
    
- **应用场景：** 最常见于简单场景，如早期的扫码登录。
    
- **问题/缺点：**
    
    1. **资源浪费：** 频繁发送请求会消耗带宽，增加服务器负担。
        
    2. **延迟：** 客户端收到消息的时间取决于轮询的间隔（例如 1-2 秒），在最坏情况下，用户会感受到明显的延迟或卡顿。
        

### 2. 长轮询 (Long Polling) / 伪服务器推

- **原理：**
    
    1. 客户端发起 HTTP 请求。
        
    2. 服务器不立即响应，而是将该请求“挂起”。
        
    3. 服务器在设定的最大超时时间内（例如 30 秒内）如果收到新数据，会**立即**响应客户端。
        
    4. 如果超时仍无数据，服务器会发送一个“无更新”的响应。
        
    5. 客户端收到响应后，**立即**发起下一个长轮询请求。
        
- **优点：** 减少了 HTTP 请求的次数，并且在服务器有数据时能及时响应，响应速度比普通轮询快。
    
- **本质：** 轮询和长轮询**本质上**都是客户端向服务端发起请求，而不是服务器主动推送。

## ⚡ WebSocket

WebSocket 是一种更优的解决方案，用于实现客户端和服务器之间的**全双工**、**实时**通信。

### 1. 全双工 (Full-Duplex) 通信

- **定义：** 在 TCP 连接的两端，客户端和服务器可以**同时、独立地**向对方发送数据。
    
- **区别于 HTTP/1.1：** HTTP/1.1 协议基于 TCP，但其通信模型是**半双工**，即在同一时间，客户端和服务器只能有一方发送数据（请求/响应模型）。WebSocket 实现了全双工，更适合实时应用（如游戏、聊天）。
    

### 2. WebSocket 协议建立流程（握手）

WebSocket 连接的建立过程利用了 HTTP 协议进行“协议升级”：

1. **TCP 三次握手：** 客户端和服务器先建立 TCP 连接。
    
2. **客户端发起 HTTP 升级请求：**
    
    - 客户端发送一个带有特殊 Header 的 HTTP 请求。
        
    - **关键 Header:**
        
        - `Connection: Upgrade` (表明浏览器想升级协议)
            
        - `Upgrade: websocket` (表示要升级成 WebSocket 协议)
            
        - `Sec-WebSocket-Key: [一段 Base64 随机码]`
            
3. **服务器响应协议切换：**
    
    - 如果服务器支持 WebSocket，它会返回一个特殊的 HTTP 响应。
        
    - **关键响应:**
        
        - **状态码:** `HTTP/1.1 101 Switching Protocols` (表示协议切换)
            
        - **关键 Header:**
            
            - `Upgrade: websocket`
                
            - `Connection: Upgrade`
                
            - `Sec-WebSocket-Accept: [一段经过算法转换的新字符串]`
                
4. **协议切换完成：**
    
    - 客户端使用**公开算法**对自己的 `Sec-WebSocket-Key` 进行转换，如果结果与服务器返回的 `Sec-WebSocket-Accept` 相同，则验证通过，协议切换成功。
        
    - 握手完成后，底层 TCP 连接保持开放，双方开始使用 **WebSocket 协议**进行全双工通信。
        

### 3. WebSocket 数据格式 (数据帧)

- **数据传输：** WebSocket 的数据传输单位称为“帧”（Frame）。
    
- **格式：** WebSocket 帧包括**消息头**和**消息体**，解决了直接使用 TCP 传输可能出现的**粘包问题**。
    
- **消息头重要字段 (Opcode)：** 标志数据帧的类型：
    
    - `1`: Text 类型数据包 (字符串)
        
    - `2`: 二进制数据类型
        
    - `8`: 关闭连接信号
        

---

## 🔑 核心结论

- **WebSocket 是一个独立的应用层协议**，它**不是**基于 HTTP 的新协议。它**只在建立连接（握手）时**利用了 HTTP 的升级机制，一旦握手成功，后续的数据传输完全基于 WebSocket 协议进行。
    
- WebSocket 提供了**全双工**通信能力，是实现**服务器主动推送**和**实时应用**的最佳选择。
