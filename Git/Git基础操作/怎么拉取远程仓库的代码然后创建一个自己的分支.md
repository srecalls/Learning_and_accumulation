## git clone +远程地址是默认在本地master分支吗
是的，当你使用`git clone +远程地址`命令克隆一个远程仓库时，默认情况下会将远程仓库的`master`分支克隆到本地。也就是说，克隆下来的仓库会有一个名为`master`的本地分支，它与远程仓库的`master`分支对应。

在克隆完成后，你可以使用`git branch`命令查看本地仓库的分支列表，例如：

```bash
git branch
```

该命令会列出当前仓库的所有本地分支，其中带有`*`符号的是当前所在的分支。

如果你想要在克隆时指定要克隆的分支名称，可以使用`git clone -b 分支名称 +远程地址`命令，例如：

```bash
git clone -b develop/hbzs https://github.com/example/repo.git my-repo
```

上述命令会将远程仓库的`develop/hbzs`分支克隆到本地，并创建一个名为`my-repo`的本地目录。在克隆完成后，你可以使用`git branch`命令查看本地仓库的分支列表，确认已经成功克隆了指定的分支。


## 如果主分支是develop/hbzs 我要创一个自己的分支dev/hbzs/srecalls怎么办
如果主分支是`develop/hbzs`，你可以通过以下命令在本地创建一个名为`dev/hbzs/srecalls`的分支，并将其推送到远程仓库：

```bash
# 从 develop/hbzs 分支创建并切换到 dev/hbzs/srecalls 分支
git checkout -b dev/hbzs/srecalls develop/hbzs

# 将 dev/hbzs/srecalls 分支推送到远程仓库
git push -u origin dev/hbzs/srecalls
```

上述命令中，`checkout`命令使用`-b`选项来创建新分支，并从`develop/hbzs`分支切换到`dev/hbzs/srecalls`分支。然后，`push`命令将新分支推送到远程仓库，并使用`-u`选项将本地分支和远程分支关联起来。

现在，你就可以在`dev/hbzs/srecalls`分支上进行开发工作了。在开发过程中，可以使用`git add`、`git commit`等命令提交代码修改。当需要将自己的分支合并到`develop/hbzs`分支时，可以使用以下命令：

```bash
# 切换到 develop/hbzs 分支
git checkout develop/hbzs

# 合并 dev/hbzs/srecalls 分支到 develop/hbzs 分支
git merge dev/hbzs/srecalls
```

上述命令将`dev/hbzs/srecalls`分支的修改合并到`develop/hbzs`分支中。如果存在冲突，需要手动解决冲突后再提交合并结果。

需要注意的是，如果其他人也在`develop/hbzs`分支上进行了修改，你需要先将`develop/hbzs`分支的最新修改 拉取到本地，再进行合并操作。可以使用以下命令拉取最新修改：

```bash
# 切换到 develop/hbzs 分支
git checkout develop/hbzs

# 拉取远程 develop/hbzs 分支的最新修改
git pull origin develop/hbzs
```

上述命令将远程仓库的`develop/hbzs`分支最新修改拉取到本地，可以避免与他人的修改产生冲突。

 ## error: src refspec dev/hbzs/sRecalls does not match any  error: failed to push some refs to '[https://code.cwoa.net/rd-fy16-canway-source/cmp.git](https://code.cwoa.net/rd-fy16-canway-source/cmp.git)'
这个错误提示通常出现在你尝试将一个不存在的分支推送到远程仓库时。具体原因可能有以下几种：

本地分支不存在：在执行`git push`命令时，如果指定的本地分支不存在，就会出现该错误。你需要先创建一个本地分支，并将其与远程分支关联起来，然后再执行推送操作。例如，可以使用以下命令创建并切换到一个名为`dev/hbzs/sRecalls`的本地分支，并将其与远程分支关联起来：

   ```bash
   git checkout -b dev/hbzs/sRecalls
   git push -u origin dev/hbzs/sRecalls
   ```

2. 分支名称拼写错误：在执行`git push`命令时，如果指定的分支名称拼写错误，就会出现该错误。你需要确认分支名称是否正确，并重新执行推送操作。

3. 远程分支不存在：在执行`git push`命令时，如果指定的远程分支不存在，就会出现该错误。你需要先在远程仓库中创建一个与本地分支同名的远程分支，然后再执行推送操作。例如，可以使用以下命令创建一个名为`dev/hbzs/sRecalls`的远程分支：
```bash
git push -u origin dev/hbzs/sRecalls
```




如果出现上述错误，可以使用`git branch`命令查看本地分支列表，使用`git remote -v`命令查看远程仓库信息，确认分支名称和远程仓库信息是否正确。如果需要创建新分支或远程分支，请使用`git checkout -b`或`git push`命令进行操作。

这段输出信息表示在执行 `git checkout -b` 命令时，Git 工具尝试创建一个名为 `front-dev/sRecalls` 的新分支，但是由于存在名为 `front-dev` 的分支，创建失败了。

这个错误通常是由于分支命名不规范或者命名冲突导致的。在 Git 中，分支名称应该只包含数字、字母、下划线和短横线，并且不能以下划线或短横线开头。另外，如果你想在一个已存在的分支上创建一个新的子分支，应该在分支名称中使用 `/` 符号来表示层级关系，而不是直接使用分支名称作为子分支名称。

为了解决这个问题，你可以采取以下几个步骤：

1. 确认当前本地仓库中存在哪些分支，以及它们的状态。

   ```````
   git branch
   git status
   ````

2. 选择一个合适的分支作为父分支，并切换到该分支。

   `````
   git checkout parent-branch
   ``````

   其中 `parent-branch` 是你想要作为父分支的分支名称。

3. 在父分支上创建一个新的子分支。

   `````
   git checkout -b child-branch
   ``````

   其中 `child-branch` 是你想要创建的子分支名称。

需要注意的是，在创建子分支之前，建议先使用 `git status` 命令查看当前分支的状态，以确保没有未提交或者未保存的更改。如果当前分支中存在未提交或者未保存的更改，创建子分支可能会导致数据丢失或者冲突。

在 Git 中，还有其他一些与分支相关的操作，比如删除分支、合并分支等，这些操作可以帮助你更好地管理代码。如果你想深入了解 Git 分支相关的操作，可以参考 Git 官方文档或者其他相关教程。
