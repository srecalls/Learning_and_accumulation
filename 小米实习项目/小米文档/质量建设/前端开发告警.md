2. # 前端事件收集
    

前端代码使用 `[@elastic/apm-rum](https://www.elastic.co/guide/en/apm/agent/rum-js/current/intro.html)` 对端上的错误和事件进行收集

1. ## **接入方式：**
    

> 参数详见 [@elastic/apm-rum 官方文档](https://www.elastic.co/guide/en/apm/agent/rum-js/current/intro.html) 和 [Elastic APM 接入文档](https://xiaomi.f.mioffice.cn/docs/dock46leyX4DnHOIPOrQpYKMR9d#)

```JavaScript
import { init as initApm } from '@elastic/apm-rum';

const apm = initApm({
    serverUrl: '//apm-rum.inf.miui.com',  // 集团APM服务地址
    serviceName: 'appstore-developer-web-fe',  // 数据上报字段，用于区分不同项目
    serviceVersion: require('../package.json').version,  // 数据上报字段，用于区分开发者站不同版本
    environment: 'production',  // 数据上报字段，用于表示当前环境
    active: true,
  });

  apm.addLabels({
    group: 'mig2-appstore-dev-web',  // 数据label，用于区分不同业务线
  });
```

2. ## **事件类型：**
    

`@elastic/apm-rum` 初始化后，会自动监听JS执行的错误以及前端的各种事件（比如点击事件、HTTP请求），并将各种事件封装成对应的数据格式上报给线上 APM 服务。主要的几种事件包括：

- **JS****抛出的异常：**
    

`@elastic/apm-rum`内部通过 addEventListener 方法监听了全局未捕获的 error 事件

```JavaScript
window.addEventListener('error', errorEvent =>
  this.logErrorEvent(errorEvent)
)
```

- **未处理的 Promise 异常**：
    

`@elastic/apm-rum` 内部通过 addEventListener 方法监听了全局的 unhandledrejection 事件

```JavaScript
window.addEventListener('unhandledrejection', promiseRejectionEvent =>
  this.logPromiseEvent(promiseRejectionEvent)
)
```

- **HTTP请求：**
    

`@elastic/apm-rum` 内部通过对 `fetch` 方法和 `XMLHttpRequest` 对象进行了劫持和改写，从而监听了所有的 HTTP 请求

- **CLICK事件：**
    

`@elastic/apm-rum`内部通过事件代理，在 window 上通过 addEventListener 方法监听了所有 DOM 元素的点击事件

```JavaScript
const clickHandler = () => {} 
window.addEventListener('click', clickHandler, true)  // 捕获阶段出发
```

6. # 告警规则
    

Elastalert 每隔五分钟会对线上数据进行一次扫描，如果匹配上了预先配置的触发场景，则会发起告警

目前开发者站配置了3种告警触发场景：

1. ## 首次出现的错误
    

Elastalert 会根据我们指定的一系列错误信息字段的组合，对各种错误类型进行唯一性标记。每种类型的错误在第一次发生时会触发 Elastalert 告警，之后 Elastalert 会将这种错误记录下来，之后遇到同类型错误将不再告警。

**规则配置详解：**

```YAML
# index表示APM打点数据储存的空间，APM上报的不同事件信息存储在不同的index中
# 这里指定了Elastalert检查所有的error记录
index: apm-*-error-*
# type 表示告警类型，new_term 表示【每当有新的错误类型出现时进行告警】
type: new_term
# fields 事一系列字段的集合，所有字段的值都相同得错误日志会被认为是同一种错误类型
# service.name 和 service.environment 分别指定了项目名称和环境（比如：开发者站-生产环境）
# error.grouping_key 是 @elastic/apm-rum 在前端捕获到错误后，根据错误信息以及当时的上下文环境自动生成的
fields:
  - [service.name, service.environment, error.grouping_key]
# 错误日志查询的筛选条件
# 这里指定被命中的错误必须满足：labels.group 为 mig2-appstore-dev-web
# 同时，排除掉了一些浏览器插件抛出的错误以及网络请求错误
filter:
- query_string:
    query: 'labels.group: mig2-appstore-dev-web
      AND NOT error.culprit: (
        "(inline script)"
        OR chrome-extension\:*
        OR safari-extension\:*
        OR moz-extension\:*
      )
      AND NOT error.exception.message: (
        "Network Error"
        OR "Request failed"
        OR "timeout of 0ms exceeded"
      )'
# 告警方式的相关配置
alert:
# 飞书告警
  - elastalert_modules.my_alerts.FeishuAlerter:
      alert_text_type: alert_text_only
      feishu_webhook_url: https://open.f.mioffice.cn/open-apis/bot/v2/hook/627c1a9a-55a1-4b2c-9764-f35ba8e11c38
```

  

2. ## 同一错误发生频率 > 5次/分钟
    

> 配置文件源码地址：https://git.n.xiaomi.com/fe/elastic-k8s/-/blob/master/elastalert-rules/c3/apm-error-mig2-appstore-dev-web-frequency.yaml

如果同一种类型的错误发生的频率超过5次/分钟，会触发告警。是否是同一种错误的判断依据是错误的 `group_key` 属性，`@elastic/apm-rum` 在前端捕获到错误后，会根据错误信息以及当时的上下文环境自动生成 `group_key`

**规则配置详解：**

```YAML
# index表示APM打点数据储存的空间，APM上报的不同事件信息存储在不同的index中
# 这里指定了Elastalert检查所有的error记录
index: apm-*-error-*
# type 表示告警类型，frequency 表示根据事件出现的频率阈值触发告警
type: frequency
# 当一定时间内事件发生次数超过 num_events 会触发告警
num_events: 5
# 事件计数周期（每 1 分钟内，次数超过 num_events ，则触发告警）
timeframe:
  minutes: 1
# 重复告警间隔（同一类型的事件触发告警后，下次告警的最小间隔，每次告警后间隔会翻倍）
realert:
  minutes: 5
# 重复告警最大间隔（同一类型的事件每次触发告警后，告警间隔会翻倍，最大不超过 exponential_realert）
exponential_realert:
  hours: 24
# 如何定义同一类型的事件，这里采用了 error.grouping_key 作为错误事件的唯一标识
query_key:
  - error.grouping_key
# 错误日志查询的筛选条件
# 这里指定被命中的错误必须满足：labels.group 为 mig2-appstore-dev-web
# 同时，排除掉了一些浏览器插件抛出的错误以及网络请求错误
filter:
- query_string:
    query: 'labels.group: mig2-appstore-dev-web
      AND NOT error.culprit: (
        "(inline script)"
        OR chrome-extension\:*
        OR safari-extension\:*
        OR moz-extension\:*
      )
      AND NOT error.exception.message: (
        "Network Error"
        OR "Request failed"
        OR "timeout of 0ms exceeded"
      )'
# 告警方式的相关配置
alert:
# 飞书告警
  - elastalert_modules.my_alerts.FeishuAlerter:
      alert_text_type: alert_text_only
      feishu_webhook_url: https://open.f.mioffice.cn/open-apis/bot/v2/hook/627c1a9a-55a1-4b2c-9764-f35ba8e11c38
# 告警标题参数
alert_subject_args:
  - labels.group
  - service.name
# 告警内容参数
alert_text_args:
  - error.exception[0]message
  - error.culprit
  - url.full
  - service.name
  - error.grouping_key
  - service.environment
# 告警标题
alert_subject: '[开发者站监控][{0}] 一分钟报错大于五次 {1}'
# 告警内容
alert_text: |-
  {0}
  {1}
  {2}
  https://${KIBANA_HOST}/app/apm#/services/{3}/errors/{4}?rangeFrom=now-7d&rangeTo=now&environment={5}
```

  

3. ## 慢请求/失败请求占比超过50%
    

> 配置文件源码地址：https://git.n.xiaomi.com/fe/elastic-k8s/-/blob/master/elastalert-rules/c3/apm-span-mig2-appstore-dev-web-fetch.yaml

每五分钟检查一次，如果在当前的时间窗口内，对某一个接口的HTTP请求，异常的请求占比超过了 50% ，会触发告警。异常请求是指请求失败（请求未响应、http响应码不为2xx）或请求响应时间大于 5s 的请求。

**规则配置详解：**

```YAML
# index表示APM打点数据储存的空间，APM上报的不同事件信息存储在不同的index中
# 这里指定了Elastalert检查所有的error记录
index: apm-*-span-*
# type 表示告警类型，percentage_match 表示根据某一类型事件触发占比触发告警
type: percentage_match
# 事件的过滤条件
# 这里指定了有效的事件必须满足 labels.group 为 mig2-appstore-dev-web 且为 http 请求事件（span.subtype: "http"）
# 同时过滤掉了一些用于打点相关的 http 请求
filter:
- query_string:
    query: 'labels.group: mig2-appstore-dev-web
      AND span.subtype: "http"
      AND NOT span.name: (
        *data.game.xiaomi.com*
        OR *tracking.miui.com*
        OR *sentry.micloud.d.xiaomi.net*
      )'
# 满足以下条件的事件的发生次数占总事件次数的百分比会触发告警：
# 请求失败（event.outcome : "failure"）或者响应时间大于 5s(span.duration.us >= 5000000)
match_bucket_filter:
- query_string:
    query: 'event.outcome : "failure" OR span.duration.us >= 5000000'
# 百分比阈值，占比超过 max_percentage 会触发告警
max_percentage: 50
# 每次检计算占比的时间窗口
buffer_time:  
  minutes: 5
# 重复告警间隔（同一类型的事件触发告警后，下次告警的最小间隔，每次告警后间隔会翻倍）
realert:
  minutes: 5
# 重复告警最大间隔（同一类型的事件每次触发告警后，告警间隔会翻倍，最大不超过 exponential_realert）
exponential_realert:
  hours: 24
# 如何定义同一类型的事件
# 只有 service.name 和 span.name 都相同的事件，会被视为同一类型的事件
query_key:
  - service.name
  - span.name
# 告警方式的相关配置
alert:
# 飞书告警
  - elastalert_modules.my_alerts.FeishuAlerter:
      alert_text_type: alert_text_only
      feishu_webhook_url: https://open.f.mioffice.cn/open-apis/bot/v2/hook/627c1a9a-55a1-4b2c-9764-f35ba8e11c38
# 告警标题参数
alert_subject_args:
  - labels.group
  - service.name
  - service.environment
  - span.name
# 告警内容参数
alert_text_args:
  - span.name
  - event.outcome
  - span.duration.us
  - service.name
  - service.environment
# 告警标题
alert_subject: '[开发者站监控][{0}] 网络请求告警 {1} {2} {3}'
# 告警内容
alert_text: |-
  {0}
  5分钟内请求异常比例大于50%（请求失败或响应时间大于5s）: 
  请求结果: {1}
  响应时间: {2}
  https://${KIBANA_HOST}/app/discover#/?_g=(filters:!(),query:(language:kuery,query:'service.name:%20%22appstore-developer-web-fe%22%20and%20span.name:{0}'),refreshInterval:(pause:!t,value:0),time:(from:now%2Fd,to:now%2Fd))&_a=h@cd786cb
```
