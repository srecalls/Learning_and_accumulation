## 从js和css方面检测
排除了 ` 网络问题 ` 以后，如果还是白屏，那一般都是 `css和js` 加载造成的`；css和js` 会造成`阻塞渲染`。比如不正确的引入`css和js` ， 就会导致它们的加载速度过长，从而导致白屏现象。
正确的引入方式是：

1. 在 `<head>` 标签中引入`css`：因为在加载`HTML` 前不先渲染`css` 的话，整个页面会乱掉；
2. 在 `</body>` 标签之前`、body` 标签中`html` 内容的`后面` ，引入 `js `因为浏览器加载`script` 标签时，处理内部代码的顺序都是从上到下 依次执行的，如果在 `html` 内容前就引入`js` 的话，那么就会导致，在所有的代码处理完毕之前，会阻塞其他资源的加载；会导致页面的其他内容都无法显示，因此如果不规范引入js的话，会对页面的其他内容带来影响。

#### 补充说明：
script 标签里可以`添加async或defer` 属性，如果`不添加` 这个属性，浏览器就会**立即加载并执行**脚本；也就是在渲染script 标签之前，不等后续的文档加载前执行；他们的区别在于：

	1. async：加载和渲染后续文档元素的过程将和 script.js的加载与执行并行进步（异步）
	2. defer: 加载后续文档元素的过程中和script.js的加载与执行并行进步（异步）。但是script.js的执行要在所有元素解析完成之后，DOMContentLoaded 事件触发之前完成。
**defer 和async 在网络读取（下载） 方面是一样的，都是异步的 ；区别在于脚本下载完成之后什么时候开始执行。**

## URL错误与路由错误的区别
假设有一个前端应用程序，使用 Vue.js 框架实现路由功能。该应用程序包含两个页面，分别是首页和商品详情页。其中，首页的路径为 `/`，商品详情页的路径为 `/product/:id`，其中的 `:id` 表示商品的 ID。现在用户在浏览器中输入了以下两个 URL：

1. `http://example.com/`：期望访问首页。
2. `http://example.com/product/123`：期望访问 ID 为 `123` 的商品详情页。

在这种情况下，如果用户访问的 URL 地址错误，那么可能会出现以下情况：

1. 如果用户输入的 URL 地址为 `http://example.com/home`（而不是 `http://example.com/`），那么可能会出现 404 错误，提示用户访问的页面不存在。
2. 如果用户输入的 URL 地址为 `http://example.com/product`（而不是 `http://example.com/product/123`），那么可能会出现 404 错误，提示用户访问的页面不存在。

在这种情况下，如果用户访问的路由的 path 属性配置错误，那么可能会出现以下情况：

1. 如果首页的 path 属性配置错误，比如配置为 `/home`，那么用户访问 `http://example.com/` 时会出现 404 错误，提示用户访问的页面不存在。
2. 如果商品详情页的 path 属性配置错误，比如配置为 `/product`，那么用户访问 `http://example.com/product/123` 时会出现 404 错误，提示用户访问的页面不存在。

因此，在进行网络方面的检测时，需要同时检查 URL 地址和路由的 path 属性是否正确，并根据具体的情况进行排查和修复。

1. 确保您的网络连接稳定，可以访问其他网站。如果您的网络连接不稳定，可能会导致页面加载缓慢或失败。

## 如果我访问的url是正确的，但是是因为路由配置错误导致了进去到了错误的组件，我要怎么排查是这个原因导致的
如果您访问的URL地址是正确的，但是仍然进入了错误的组件，很可能是因为路由配置错误导致的。以下是一些排查路由配置错误的方法：

1. 检查路由配置文件

在您的应用程序中，路由配置文件可能会包含有关URL地址和对应组件的映射信息。您可以检查路由配置文件，以确保URL地址和对应组件的映射正确。

2. 检查路由参数

路由参数是URL地址中的变量，并且可以用于动态生成URL地址。如果路由参数不正确，可能会导致路由错误。您可以检查路由参数，以确保它们与组件的期望参数匹配。

3. 检查组件引用

如果组件引用错误，则可能会导致路由错误。您可以检查组件引用，以确保它们与路由配置文件中的组件名称匹配。

4. 检查组件导入

如果组件导入错误，则可能会导致路由错误。您可以检查组件导入，以确保它们与路由配置文件中的组件名称匹配，并且导入的路径正确。

5. 检查路由守卫

路由守卫是在路由跳转前执行的一段代码。如果路由守卫返回了错误的结果，可能会导致路由错误。您可以检查路由守卫，以确保它们返回正确的结果。

通过检查上述内容，您可以确定是否存在路由配置错误，并尝试进行相应的修复。如果您仍然无法解决问题，可以在控制台中查看错误消息或警告，以获取更多关于路由错误的信息。
