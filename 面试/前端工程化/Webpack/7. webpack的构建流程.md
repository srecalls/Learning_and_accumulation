## version 1 

	Webpack的运行流程是一个串行的过程，从启动到结束会依次执行以下流程:
	1．初始化参数:从配置文件和Shell语句中读取与合并参数，得出最终的参数;
	2．开始编译:用上一步得到的参数初始化Compiler对象，加载所有配置的插件，执行对象的run方法开始执行编译;
	3．确定入口:根据配置中的entry 找出所有的入口文件;
	4．编译模块:从入口文件出发，调用所有配置的Loader对模块进行翻译，再找出该模块依赖的模块，再递归本步骤直到所有入口依赖的文件都经过了本步骤的处理;
	5.完成模块编译:在经过第4步使用Loader翻译完所有模块后，得到了每个模块被翻译后的最终内容以及它们之间的依赖关系;
	6．输出资源:根据入口和模块之间的依赖关系，组装成一个个包含多个模块的Chunk，再把每个Chunk转换成一个单独的文件加入到输出列表，这步是可以修改输出内容的最后机会;
	7．输出完成:在确定好输出内容后，根据配置确定输出的路径和文件名，把文件内容写入到文件系统。
	在以上过程中，Webpack 会在特定的时间点广播出特定的事件，插件在监听到感兴趣的事件后会执行特定的逻辑，并且插件可以调用Webpack提供的API改变Webpack的运行结果。


### 例子
假设我们有一个简单的 Webpack 项目，包含一个入口文件 `index.js` 和一个依赖文件 `module.js`，其中 `index.js` 依赖于 `module.js`，并且需要进行 ES6 转换和样式加载。那么整个 Webpack 的运行流程如下：

1. 初始化参数：从配置文件 `webpack.config.js` 中读取参数，并与命令行参数进行合并，得出最终的参数。
   以下是一个示例，演示如何从 `webpack.config.js` 配置文件和命令行参数中读取参数，并将它们合并为最终的参数：

```javascript
const path = require('path');
const webpack = require('webpack');
const yargs = require('yargs');

// 从配置文件中读取参数
const configPath = path.resolve(__dirname, 'webpack.config.js');
const config = require(configPath);

// 从命令行参数中读取参数
const argv = yargs.argv;
const commandLineArgs = {
  mode: argv.mode || 'development',
  outputDir: argv.outputDir || 'dist',
};

// 合并参数
const finalConfig = {
  ...config,
  mode: commandLineArgs.mode,
  output: {
    ...config.output,
    path: path.resolve(__dirname, commandLineArgs.outputDir),
  },
};

// 使用最终的参数来构建 webpack 配置
webpack(finalConfig, (err, stats) => {
  if (err) {
    console.error(err);
  } else {
    console.log(stats.toString({ colors: true }));
  }
});
```

在这个示例中，假设我们有一个名为 `webpack.config.js` 的配置文件，其中包含一些 webpack 的配置选项，如 `entry`、`output` 等。通过 `require` 函数将配置文件加载为一个对象。

我们还使用了 `yargs` 库来解析命令行参数。在命令行中，可以使用 `--mode` 和 `--outputDir` 参数来覆盖默认的模式和输出目录。

首先，我们读取配置文件中的参数，并将它们存储在 `config` 对象中。然后，使用 `yargs.argv` 读取命令行参数，并将它们存储在 `commandLineArgs` 对象中。

接下来，我们使用对象展开运算符 (`...`) 将配置文件中的参数和命令行参数合并到 `finalConfig` 对象中。我们还根据命令行参数更新 `output.path`，以确保输出目录路径正确。

最后，我们使用最终的参数 `finalConfig` 来构建 webpack 配置，并进行构建操作。在构建完成后，我们可以根据需要处理构建结果。

这个示例展示了如何从配置文件和命令行参数中读取参数，并将它们合并为最终的参数。你可以根据自己的需求和项目的配置文件结构进行相应的修改和扩展。

2. 开始编译：用上一步得到的参数初始化 `Compiler` 对象，加载所有配置的插件，执行对象的 `run` 方法开始执行编译。
   
   
在 webpack 中，可以使用上一步中得到的参数来初始化 `Compiler` 对象，并执行编译过程。以下是一个示例：

```javascript
const webpack = require('webpack');

// 使用上一步得到的参数初始化 Compiler 对象
const compiler = webpack(finalConfig);

// 加载所有配置的插件
compiler.hooks.afterPlugins.tap('AfterPlugins', () => {
  // 在这里可以执行其他插件相关的操作
});

// 执行编译
compiler.run((err, stats) => {
  if (err) {
    console.error(err);
  } else {
    console.log(stats.toString({ colors: true }));
  }
});
```

在这个示例中，我们使用 `finalConfig` 对象（上一步中得到的最终参数）来初始化 `Compiler` 对象。`Compiler` 对象是 webpack 的核心编译器，负责管理整个编译过程。

然后，我们可以通过 `compiler.hooks.afterPlugins` 钩子来加载所有配置的插件。这个钩子会在插件加载完成后被触发，你可以在其中执行其他插件相关的操作。

最后，我们调用 `compiler.run` 方法来执行编译过程。在编译完成后，`run` 方法的回调函数中会接收到一个 `stats` 对象，它包含有关编译过程的统计信息。我们可以使用 `toString` 方法将统计信息以彩色的形式打印到控制台。

请注意，上述示例中的代码片段仅涵盖了主要的步骤，并没有包括完整的 webpack 配置和插件的加载过程。根据你的具体需求和项目的配置，你可能需要进行更多的配置和插件加载操作。

3. 确定入口：根据配置中的 `entry` 找出所有的入口文件，我们这里只有一个入口文件 `index.js`。

根据配置中的 `entry`，可以确定 webpack 的入口文件。在这个示例中，我们假设配置文件中只有一个入口文件 `index.js`。

```javascript
const path = require('path');
const webpack = require('webpack');

// 从配置文件中读取参数
const configPath = path.resolve(__dirname, 'webpack.config.js');
const config = require(configPath);

// 获取入口文件
const entry = config.entry;

// 确定入口文件路径
const entryPath = path.resolve(__dirname, entry);

// 使用入口文件路径来构建 webpack 配置
const finalConfig = {
  ...config,
  entry: entryPath,
};

// 创建 Compiler 对象并执行编译
const compiler = webpack(finalConfig);
compiler.run((err, stats) => {
  if (err) {
    console.error(err);
  } else {
    console.log(stats.toString({ colors: true }));
  }
});
```

在这个示例中，我们假设 `webpack.config.js` 配置文件中有一个 `entry` 属性，其值为入口文件的相对路径（例如 `index.js`）。

首先，我们从配置文件中读取 `entry` 参数，并将其存储在 `entry` 变量中。

接下来，我们使用 `path.resolve` 方法将入口文件的相对路径解析为绝对路径，并将其存储在 `entryPath` 变量中。

然后，我们将入口文件路径更新到 `finalConfig` 对象的 `entry` 属性中。

最后，我们使用更新后的 `finalConfig` 对象来创建 `Compiler` 对象，并执行编译过程。

请注意，这只是一个示例，假设只有一个入口文件。实际上，webpack 支持多个入口文件，并且可以通过对象或数组的形式进行配置。你可以根据你的实际需求在配置文件中定义多个入口文件，并相应地调整代码来确定所有的入口文件。



4. 编译模块：从入口文件 `index.js` 出发，调用所有配置的 `Loader` 对模块进行翻译，再找出该模块依赖的模块，即 `module.js`，再递归本步骤直到所有入口依赖的文件都经过了本步骤的处理。在这里，`babel-loader` 会对 `index.js` 和 `module.js` 进行 ES6 转换，`style-loader` 和 `css-loader` 会对 `index.js` 进行样式加载。
在 webpack 中，可以通过配置 `Loader` 来对模块进行翻译和处理。在你的示例中，`babel-loader` 用于对 `index.js` 和 `module.js` 进行 ES6 转换，`style-loader` 和 `css-loader` 用于对 `index.js` 进行样式加载。以下是一个示例：

```javascript
const path = require('path');
const webpack = require('webpack');

// 从配置文件中读取参数
const configPath = path.resolve(__dirname, 'webpack.config.js');
const config = require(configPath);

// 获取入口文件
const entry = config.entry;

// 确定入口文件路径
const entryPath = path.resolve(__dirname, entry);

// 使用入口文件路径来构建 webpack 配置
const finalConfig = {
  ...config,
  entry: entryPath,
};

// 创建 Compiler 对象并执行编译
const compiler = webpack(finalConfig);
compiler.run((err, stats) => {
  if (err) {
    console.error(err);
  } else {
    console.log(stats.toString({ colors: true }));
  }
});
```

在上述示例中，我们假设 `webpack.config.js` 配置文件中已经配置了相应的 `Loader`，包括 `babel-loader`、`style-loader` 和 `css-loader`。

当执行编译时，webpack 会从入口文件 `index.js` 开始，根据配置文件中的 `Loader` 进行模块的翻译和处理。

对于 ES6 转换，我们可以在配置文件中添加以下配置：

```javascript
module.exports = {
  // ...
  module: {
    rules: [
      {
        test: /\.js$/, // 匹配以 .js 结尾的文件
        exclude: /node_modules/, // 排除 node_modules 目录
        use: {
          loader: 'babel-loader',
          options: {
            presets: ['@babel/preset-env'], // 使用 @babel/preset-env 进行转换
          },
        },
      },
    ],
  },
  // ...
};
```

对于样式加载，我们可以在配置文件中添加以下配置：

```javascript
module.exports = {
  // ...
  module: {
    rules: [
      {
        test: /\.css$/, // 匹配以 .css 结尾的文件
        use: ['style-loader', 'css-loader'], // 应用 style-loader 和 css-loader
      },
    ],
  },
  // ...
};
```

通过配置适当的 `test`、`exclude` 和 `use`，可以根据文件的类型和路径匹配相应的 `Loader` 进行处理。

请注意，在配置文件中可以定义多个 `Loader` 规则，用于处理不同类型的文件。你可以根据实际需求添加和配置适当的 `Loader` 来处理模块的翻译和加载。



5. 完成模块编译：在经过第4步使用 `Loader` 翻译完所有模块后，得到了每个模块被翻译后的最终内容以及它们之间的依赖关系。
在 webpack 中，经过第 4 步使用 `Loader` 翻译完所有模块后，你可以得到每个模块被翻译后的最终内容以及它们之间的依赖关系。这些信息可以通过 webpack 的编译结果对象（`stats`）来获取。

以下是一个示例，展示如何获取模块的最终内容和依赖关系：

```javascript
const path = require('path');
const webpack = require('webpack');

// 从配置文件中读取参数
const configPath = path.resolve(__dirname, 'webpack.config.js');
const config = require(configPath);

// 获取入口文件
const entry = config.entry;

// 确定入口文件路径
const entryPath = path.resolve(__dirname, entry);

// 使用入口文件路径来构建 webpack 配置
const finalConfig = {
  ...config,
  entry: entryPath,
};

// 创建 Compiler 对象并执行编译
const compiler = webpack(finalConfig);
compiler.run((err, stats) => {
  if (err) {
    console.error(err);
  } else {
    const modules = stats.toJson().modules;

    // 遍历每个模块
    modules.forEach((module) => {
      // 获取模块的最终内容
      const transformedCode = module.source;

      // 获取模块的依赖关系
      const dependencies = module.dependencies;

      console.log('Module:', module.name);
      console.log('Transformed Code:', transformedCode);
      console.log('Dependencies:', dependencies);
      console.log('----------------------');
    });
  }
});
```

在上述示例中，我们获取了编译结果对象 `stats`，并通过 `stats.toJson().modules` 获取了所有模块的信息。

然后，我们遍历每个模块，通过 `module.source` 获取模块的最终内容，通过 `module.dependencies` 获取模块的依赖关系。

你可以根据需要进一步处理模块的最终内容和依赖关系，例如输出到文件、进行进一步的处理等。

请注意，`stats` 对象提供了丰富的信息，除了模块的最终内容和依赖关系，还包括编译时间、编译警告、错误等。你可以根据实际需求，进一步探索和利用 `stats` 对象中的其他属性和方法。



6. 输出资源：根据入口和模块之间的依赖关系，组装成一个个包含多个模块的 `Chunk`，即将 `index.js` 和 `module.js` 打包成一个 `Chunk`，再把每个 `Chunk` 转换成一个单独的文件加入到输出列表，这步是可以修改输出内容的最后机会。在这里，我们得到了一个名为 `bundle.js` 的文件，其中包含了经过编译后的 `index.js` 和 `module.js`。
在 webpack 中，根据入口和模块之间的依赖关系，可以将它们组装成一个个包含多个模块的 `Chunk`，然后将每个 `Chunk` 转换成一个单独的文件，并将其加入到输出列表。这样，你可以得到一个名为 `bundle.js` 的文件，其中包含了经过编译后的 `index.js` 和 `module.js`。

以下是一个示例，展示如何配置 webpack 来实现输出资源的处理：

```javascript
const path = require('path');
const webpack = require('webpack');

// 从配置文件中读取参数
const configPath = path.resolve(__dirname, 'webpack.config.js');
const config = require(configPath);

// 获取入口文件
const entry = config.entry;

// 确定入口文件路径
const entryPath = path.resolve(__dirname, entry);

// 使用入口文件路径来构建 webpack 配置
const finalConfig = {
  ...config,
  entry: entryPath,
  output: {
    filename: 'bundle.js', // 输出文件名为 bundle.js
    path: path.resolve(__dirname, 'dist'), // 输出路径为 dist 目录
  },
};

// 创建 Compiler 对象并执行编译
const compiler = webpack(finalConfig);
compiler.run((err, stats) => {
  if (err) {
    console.error(err);
  } else {
    console.log(stats.toString({ colors: true }));
  }
});
```

在上述示例中，我们通过配置 `output` 属性来指定输出文件的名称和路径。在这里，我们将输出文件名设置为 `bundle.js`，输出路径设置为 `dist` 目录（需要事先创建该目录）。

当执行编译时，webpack 会根据入口和模块之间的依赖关系，将它们组装成 `Chunk`，然后将每个 `Chunk` 转换成一个单独的文件，并将其加入到输出列表中。在最终的输出结果中，你将得到一个名为 `bundle.js` 的文件，其中包含了经过编译后的 `index.js` 和 `module.js`。

请注意，输出文件的名称和路径可以根据你的实际需求进行配置。你可以根据需要修改输出文件名、输出路径以及其他相关的输出配置，以满足你的项目需求。



7. 输出完成：在确定好输出内容后，根据配置确定输出的路径和文件名，把文件内容写入到文件系统。在这里，我们将 `bundle.js` 输出到 `dist` 目录下。

在以上过程中，Webpack 会在特定的时间点广播出特定的事件，插件在监听到感兴趣的事件后会执行特定的逻辑，并且插件可以调用Webpack提供的API改变Webpack的运行结果。例如，`html-webpack-plugin` 插件会监听到 `emit` 事件，然后根据模板生成 HTML 文件，并将打包后的 JS 自动注入到 HTML 文件中。

## version 2
从entry开始，递归解析entry依赖的所有module,  
  
再根据module.rules里配置的loader进行相应的转换处理，对model转换后在解析出module依赖的其他模块，解析出一个一个的chunk(model进行分组)，最后所有的chunk会转换成文件输出的output.  
  
在整个构建流程中，webpack会在恰当的时机执行plugin里 定义的那些插件。从而完成plugin插件里的任务

entry :模块入口，使得源文件加入到构建流程中
output:
配置如何输出最终大代码
module:.配置各种类型的模块的处理规则
plugin: .配置扩展插件的
devServer:实现本地服务:包括。http.。 模块替换，. source . mag等服务
