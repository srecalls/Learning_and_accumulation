## （1）JSON.stringify()
- JSON.parse(JSON.stringify(obj)) 是目前比较常用的深拷贝方法之一，它的原理就是利用 JSON.stringify 将 js 对象序列化 JSON字符串)，再使用 JSON.parse 来反序列化(还原) js 对象
- 这个方法可以简单粗暴的实现深拷贝，但是还存在问题，拷贝的对象中如果有函数，undefined，symbol, 当使用过 JSON.stringify() 进行处理之后，都会消失。

```js
let obj1 = { a: 0,
				b: {
					c: 0,
					d: 0
				}
			}
let obj2 = JSON.parse(JSON.stringify(obj1));
obj1.a = 1;
obj1.b.c = 1;
console.log(obj1); // {a: 1, b: {c: 1, d: undefined}}
console.log(obj2); // {a: 0, b: {c: 0}}
```


## （2）函数库lodash的_.cloneDeep方法
该函数库也有提供 .cloneDeep用来做 Deep Copy
```js
var _ = require('lodash');
var obj1 = {
	a: 1,
	b: { f: { g: 1 } },
	c: [1, 2, 3]
}
var obj2 = _.cloneDeep(obj1);
console.log(obj1.b.f === obj2.b.f);// false
```


## （3）手写深拷贝函数
```js
// 深拷贝的实现
/*
object: { a: 0,
	b: {
		c: 0,
		d: undefined
	}
}
*/
function deepCopy(object) {
	if (!object || typeof object !== 'object' return);
	
	let newObject = Array.isArray(object) ? [] || {}
	for (let key in object)	{
		if (object.hasOwnProperty(key)) {
			newObject[key] =
				typeof object[key] === 'object' ?deepCopy(object[key]) : object[key]
		}
	}
	return newObject
}
```



## 为什么JSON.stringify()不能拷贝函数、undefined、symbol
在JavaScript中，`JSON.stringify()`方法用于将一个JavaScript对象序列化为一个JSON字符串。当对象中包含函数、undefined或Symbol类型的属性时，`JSON.stringify()`方法会忽略这些属性，并将它们排除在序列化的过程之外。

具体来说，对于函数类型的属性，`JSON.stringify()`方法会将其忽略掉，并在序列化后的JSON字符串中不包含该属性。对于undefined和Symbol类型的属性，`JSON.stringify()`方法会将其序列化为null。因此，当使用`JSON.stringify()`方法进行处理时，这些属性会消失。

需要注意的是，`JSON.stringify()`方法只能序列化JavaScript对象中的可枚举属性，而不能序列化对象的原型链上的属性、方法或不可枚举属性。这也是使用`JSON.stringify()`方法进行深拷贝的一个限制。

因此，虽然使用`JSON.stringify()`方法可以简单粗暴地实现深拷贝，但是它并不是一个完全可靠的方案，尤其是在处理包含函数、undefined或Symbol类型属性的对象时。通常，我们建议使用专门的深拷贝方法，例如Lodash库中的`cloneDeep()`方法，以确保正确地进行深拷贝。
