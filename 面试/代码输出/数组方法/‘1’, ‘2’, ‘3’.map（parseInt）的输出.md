```js
['1', '2', '3'].map(parseInt)
```

这个结果可能会令人困惑，原因在于 `Array.prototype.map()` 函数会传递三个参数给回调函数：当前元素的值、当前元素的索引和被遍历的数组。而 `parseInt()` 函数接受两个参数：要转换为整数的字符串和表示要转换的数字的基数。当 `map()` 函数将当前元素的值作为第一个参数传递给 `parseInt()` 函数时，`parseInt()` 函数会将其解析为数字，但是当第二个参数（即基数）缺失或者为0，则默认使用10作为基数。因此，`parseInt('1')`、`parseInt('2')`、`parseInt('3')` 的结果分别为 `1`、`NaN`、`NaN`。

当使用 `parseInt()` 函数时，如果第二个参数（即基数）缺失或者为0，则默认使用10作为基数。因此在 `['1', '2', '3'].map(parseInt)` 的例子中，`parseInt()` 函数会将字符串 `'1'`、`'2'`、`'3'` 分别解析为十进制数，因为我们没有明确指定基数。因此，调用 `parseInt('2', 10)` 的结果将会是数字2。

那么为什么 `['1', '2', '3'].map(parseInt)` 的输出结果中，第二个和第三个元素被映射为 `NaN` 呢？这是因为，在 `map()` 方法中，回调函数的第二个参数表示当前元素在数组中的索引。而当我们传递 `parseInt` 函数作为回调函数时，由于 `map()` 方法会将当前元素的值作为第一个参数传递给回调函数，而 `parseInt` 函数又接受两个参数，因此实际上 `parseInt` 函数会将第二个参数（即当前元素在数组中的索引）作为基数来解析当前元素的值。这就解释了为什么 `['1', '2', '3'].map(parseInt)` 的结果中，第二个和第三个元素被映射为 `NaN`。因为在十进制中，数字2和数字3都无法用基数为2或3的方式正确解析，所以返回了 `NaN`。

因此，为了避免这种情况，我们可以使用箭头函数或者 `Function.prototype.bind()` 来绑定 `parseInt()` 函数的第二个参数，从而避免将当前元素的索引作为基数的问题，如下所示：

```js
['1', '2', '3'].map((num) => parseInt(num)); // [1, 2, 3]
['1', '2', '3'].map(parseInt.bind(null, 10)); // [1, 2, 3]
```

因此，最终的输出结果为 `[1, NaN, NaN]`


首先，让我们回顾一下 `Array.prototype.map()` 函数。这个函数接受一个回调函数作为参数，并为数组中的每个元素调用该回调函数。回调函数可以接受三个参数：当前元素的值、当前元素的索引和被遍历的数组。而 `Array.prototype.map()` 函数返回一个新数组，该数组包含回调函数返回的值。

接下来，让我们看一下 `parseInt()` 函数。`parseInt()` 函数用于解析一个字符串并返回一个整数。它可以接受两个参数：要转换为整数的字符串和表示要转换的数字的基数。如果基数缺失或者为0，则默认使用10作为基数。

现在，让我们结合上述两个函数来解释为什么 `[‘1’, ‘2’, ‘3’].map(parseInt)` 的输出为 `[1, NaN, NaN]`。

当 `map()` 函数遍历到第一个元素 `'1'` 时，它将其传递给 `parseInt()` 函数。由于没有指定基数，`parseInt()` 函数默认使用10作为基数，因此它将字符串 `'1'` 转换为数字 `1`，并将其作为回调函数的返回值。因此，数组的第一个元素被映射为数字1。

当 `map()` 函数遍历到第二个元素 `'2'` 时，它将其传递给 `parseInt()` 函数。同样，由于没有指定基数，`parseInt()` 函数默认使用10作为基数，因此它尝试将字符串 `'2'` 转换为数字。然而，由于在基数为10的情况下，字符串 `'2'` 并不是一个合法的数字，因此 `parseInt()` 函数返回 `NaN`。因此，数组的第二个元素被映射为 `NaN`。

当 `map()` 函数遍历到第三个元素 `'3'` 时，它将其传递给 `parseInt()` 函数。同样，由于没有指定基数，`parseInt()` 函数默认使用10作为基数，因此它尝试将字符串 `'3'` 转换为数字。然而，由于在基数为10的情况下，字符串 `'3'` 并不是一个合法的数字，因此 `parseInt()` 函数返回 `NaN`。因此，数组的第三个元素被映射为 `NaN`。

最终，`map()` 函数返回一个新数组，其中第一个元素被映射为数字1，而第二个和第三个元素被映射为 `NaN`。因此，`[‘1’, ‘2’, ‘3’].map(parseInt)` 的输出为 `[1, NaN, NaN]`。

## 参数穿透
是的，如果使用类似于 `['1', '2', '3'].map(parseInt)` 这样的方法时，由于 `parseInt` 函数接受两个参数，而 `map` 方法会将当前元素的值作为第一个参数传递给回调函数，因此在调用 `map` 方法时，除了当前元素的值之外，还会将该元素在数组中的索引和原始数组作为 `parseInt` 函数的第二个参数和第三个参数传递进去。

例如，`['1', '2', '3'].map(parseInt)` 会将数组中的每个元素 `'1'`、`'2'` 和 `'3'` 作为第一个参数传递给 `parseInt` 函数。然而，由于 `map` 方法还会将当前元素在数组中的索引和原始数组作为第二个参数和第三个参数传递给 `parseInt` 函数，因此实际上会执行以下代码：

```js
parseInt('1', 0, ['1', '2', '3']); // 1
parseInt('2', 1, ['1', '2', '3']); // NaN
parseInt('3', 2, ['1', '2', '3']); // NaN
```

在上面的代码中，第二个参数表示要解析的数字的基数，而第三个参数表示要解析的字符串。由于基数为1或2时，字符串 `'2'` 和 `'3'` 都不是合法的数字，因此 `parseInt` 函数返回 `NaN`。

因此，如果要避免这种穿透问题，我们可以使用箭头函数或者 `Function.prototype.bind()` 来绑定 `parseInt` 函数的第二个参数（即要解析的数字的基数），如下所示：

```js
['1', '2', '3'].map((num) => parseInt(num)); // [1, 2, 3]
['1', '2', '3'].map(parseInt.bind(null, 10)); // [1, 2, 3]
```

在上面的代码中，我们分别使用箭头函数和 `Function.prototype.bind()` 来绑定 `parseInt` 函数的第二个参数为 `10`，从而避免了穿透问题。
