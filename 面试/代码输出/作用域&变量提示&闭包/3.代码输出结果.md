## 函数的变量提升
在JavaScript中，函数会被提升到当前作用域的顶部，这被称为函数提升。这意味着，即使在定义之前调用函数，函数仍然可以正常工作。

以下是一个例子：

```js
foo(); // 可以正常工作，因为函数被提升了

function foo() {
  console.log("hello world");
}
```

在这个例子中，函数`foo`在调用之前被定义，但是调用仍然可以正常工作，因为函数被提升到了当前作用域的顶部。这意味着，你可以在函数定义之前调用函数，而不会出现错误。

需要注意的是，只有函数声明会被提升，函数表达式不会被提升。例如：

```js
bar(); // TypeError: bar is not a function

var bar = function() {
  console.log("hello world");
}
```

在这个例子中，函数`bar`是通过函数表达式定义的，而不是函数声明，因此在定义之前调用它会导致错误。


## 
函数表达式不会被提升的原因是因为它们实际上是变量赋值表达式。在JavaScript中，变量声明会被提升到当前作用域的顶部，但是变量赋值表达式不会被提升。

考虑以下代码：

```js
console.log(foo); // undefined

var foo = function() {
  console.log("hello world");
}
```

在这个例子中，变量`foo`被声明并赋值一个函数表达式。在变量赋值表达式之前，`foo`的值为`undefined`。因此，当我们尝试在`console.log(foo)`中使用`foo`时，它的值为`undefined`，而不是函数。

相比之下，函数声明会被提升到当前作用域的顶部。因此，即使在函数声明之前调用函数，它也可以正常工作。例如：

```js
foo(); // 可以正常工作，因为函数被提升了

function foo() {
  console.log("hello world");
}
```

在这个例子中，函数`foo`的声明会被提升到当前作用域的顶部，因此在声明之前调用函数并不会导致错误。

总之，函数声明和函数表达式都可以创建函数，但是它们的行为略有不同。函数声明会被提升到当前作用域的顶部，而函数表达式不会被提升。


## 函数表达式不会被提升的原因
在JavaScript中，变量提升是指变量和函数声明在代码执行之前被移动到当前作用域的顶部。这意味着在当前作用域中的任何位置都可以访问这些声明。

函数声明是一种语句，它的语法是使用`function`关键字和一个标识符来定义一个函数，例如：

```js
function add(a, b) {
  return a + b;
}
```

当JavaScript引擎在编译代码时，会先扫描整个函数作用域，将所有函数声明都提升到当前作用域的顶部。这意味着在函数声明之前调用函数是可行的，因为在编译代码时，JavaScript引擎会为函数声明分配一个内存空间，使其在整个作用域中都可用。

相比之下，函数表达式是一种赋值表达式，它的语法是将一个函数赋值给一个变量，例如：

```js
var add = function(a, b) {
  return a + b;
};
```

当JavaScript引擎在编译代码时，它会按照代码的顺序执行，并将函数表达式中的函数定义赋值给变量。因此，如果在函数表达式之前调用该变量，JavaScript解释器会抛出一个未定义的错误。

因此，函数声明可以被提升，因为它们是语句而不是表达式，而且在编译代码时就已经被解析和处理。但是，函数表达式不能被提升，因为它们是赋值表达式，只有在执行代码时才会被解析和处理。
