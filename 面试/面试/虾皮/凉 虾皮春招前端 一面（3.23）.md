9. 301重定向后使用什么请求方法  
```js
当发生 301 重定向时，根据 HTTP 协议规范，浏览器应该使用 GET 方法来进行重定向后的请求。

301 是 HTTP 状态码之一，表示永久移动（Moved Permanently）。当服务器返回 301 状态码时，它会同时提供一个新的 URL（重定向目标），指示客户端将请求重定向到该 URL。

根据 HTTP 规范，浏览器在收到 301 响应后，会自动将请求方法更改为 GET，并重新发起请求到重定向目标 URL。这意味着无论原始请求是什么方法（如 GET、POST、PUT 等），浏览器都会将重定向后的请求方法设置为 GET。

这是为了确保安全性和兼容性。使用 GET 方法的重定向可以避免一些潜在的安全风险，例如在重定向过程中暴露敏感信息或触发意外的副作用。

如果需要在重定向后继续使用原始请求方法，可以考虑使用其他状态码，如 307（Temporary Redirect）或 308（Permanent Redirect）。这些状态码会保留原始请求方法，并将其应用于重定向后的请求。

总结起来，301 重定向后，浏览器会自动使用 GET 方法发送重定向请求。如果需要保留原始请求方法，可以使用其他状态码来实现。
```
