**11.第二个场景题：给了两个函数①const api = () => {}，返回一个promise②const warning = () => {}发出一个警告**

**现在需要对这两个函数进行封装，不需要改这两个函数，在调用api之后5s内如果没有拿到返回的promise，那就要调用warning。**

前面那个题没搞出来就影响后面的思路了，这个一开始想着怎么改这俩函数呢，后来说不用改，就写了下面的

```js
function handler() {

  let timer = setTimeout(() => {

    warning();

  }, 5000)

  api().then(data => {

    clearTimeout(timer);

    console.log('success');

  })

}
```

**12.上面的思路是对的，如果用原生的promise api来写怎么改进？（当时没想出来，说了用Promise.all或Promise.race。。其实应该用resolve、reject最好吧）**

复盘了一下大概是这个思路：

```js
function handler() {

  return new Promise((resolve, reject) => {

    api().then(() => {

      clearTimeout(timer);

      resolve();

    }, () => {

      clearTimeout(timer);

      reject()

    });

    let timer = setTimeout(() => {

      reject(warning());

    }, 5000)

  })

}

function api() {

  return new Promise((resolve, reject) => {

    console.log("pending");

    reject();

  })

}

function warning() {

  console.log("warning");

}

handler().catch((err) => {});
```

14. WebSocket 是一种在 Web 应用程序中实现双向通信的协议。它提供了在客户端和服务器之间建立持久连接的能力，使得服务器可以主动向客户端推送数据，而不需要客户端频繁地发送请求。

与传统的 HTTP 请求不同，WebSocket 连接在建立后保持打开状态，双方可以通过发送消息来进行实时通信。WebSocket 使用标准的 HTTP 或 HTTPS 端口（80 或 443），因此可以通过防火墙和代理服务器。

WebSocket 具有以下特点：

- 双向通信：WebSocket 支持双向通信，服务器可以主动推送数据给客户端，而不需要客户端发送请求。
- 实时性：WebSocket 提供了低延迟的实时数据传输，适用于需要及时更新数据的应用场景。
- 较少的数据传输量：WebSocket 与传统的 HTTP 请求相比，减少了数据包的开销，因为在连接建立后只需要发送较小的消息头。
- 跨域支持：WebSocket 支持跨域通信，可以在不同域名或端口之间建立连接。

WebSocket 在以下情况下特别适用：

- 即时聊天应用：WebSocket 可以实现实时消息传递，适用于需要实时通信的即时聊天应用程序。
- 实时数据更新：当需要实时更新数据时，例如股票市场行情、实时游戏状态等，WebSocket 提供了有效的实时数据传输机制。
- 协同编辑和共享应用：WebSocket 可以实现多个用户之间的实时协同编辑和共享应用程序。

15. 在处理 WebSocket 不受支持的降级方案时，可以考虑以下方法：

1. 转换为轮询：如果某些平台不支持 WebSocket，可以回退到使用传统的轮询机制。客户端定期发送请求以获取更新，并在服务器端处理这些请求。尽管这种方法效率较低，但可以在不支持 WebSocket 的情况下实现基本的实时通信。

2. 使用长轮询（Long Polling）：长轮询是一种改进的轮询技术，它在客户端发送请求后，服务器会保持连接打开一段时间，直到有数据可发送或超时。如果没有数据可发送，客户端会重新发送请求。这种技术使得服务器可以更及时地响应数据更新，虽然仍然不如 WebSocket 高效，但在不支持 WebSocket 的情况下是一个可行的替代方案。

3. 使用第三方库或框架：在某些情况下，可以使用第三方库或框架来处理降级方案。这些库或框架提供了抽象层，可以根据客户端的支持情况选择最佳的通信方式，例如 Socket.IO。

在实际应用中，通常会根据目标平台和浏览器的支持情况来选择使用 WebSocket 还是降级方案。可以使用特性检测或用户代理字符串来确定客户端是否支持 WebSocket，并相应地选择合适的通信方式。
