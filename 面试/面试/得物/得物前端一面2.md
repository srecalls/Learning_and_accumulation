## 3. 说一下登陆流程JWT
JWT（JSON Web Token）是一种用于身份验证和授权的开放标准。下面是简要的 JWT 登录流程的说明：

1. 用户提供凭据：用户在客户端（例如 Web 应用程序）中提供他们的凭据，通常是用户名和密码。

2. 身份验证请求：客户端将凭据发送到服务器端（通常是通过 HTTP 请求）以进行身份验证。

3. 身份验证处理：服务器端接收到身份验证请求后，会验证用户提供的凭据的有效性。这可能涉及到检查用户名和密码的正确性，或者与数据库或身份验证服务进行交互来验证用户的身份。

4. 创建和签署 JWT：如果用户提供的凭据被验证为有效，服务器端会创建一个 JWT。JWT 由三个部分组成：头部（Header）、负载（Payload）和签名（Signature）。

   - 头部：包含指定 JWT 类型和所使用的签名算法的元数据。
   - 负载：包含有关用户或其他相关信息的声明，例如用户ID、角色等。
   - 签名：使用服务器端的秘钥对头部和负载进行签名，以确保 JWT 的完整性和真实性。

5. 发送 JWT 响应：服务器端将生成的 JWT 作为响应的一部分发送回客户端。

6. 客户端存储 JWT：客户端接收到 JWT 后，通常会将其存储在本地，例如在浏览器的本地存储（LocalStorage）或会话存储（SessionStorage）中，以备将来使用。

7. 后续请求中发送 JWT：在后续的请求中，客户端会将 JWT 包含在请求的头部（通常是 Authorization 头）或请求的参数中。

8. JWT 验证和授权：服务器端在接收到带有 JWT 的请求时，会验证 JWT 的签名以确保其完整性和真实性。然后，服务器端会解码 JWT 的负载部分以获取用户的相关信息，从而进行授权和权限验证。

JWT 登录流程的关键是在服务器端创建和签署 JWT，并在后续请求中使用 JWT 进行身份验证和授权。客户端负责存储和发送 JWT。使用 JWT 可以减少对服务器端状态的依赖，使得系统更加可扩展和分布式。


以下是一个示例的前端请求代码，使用 JavaScript 和 Fetch API 发送带有 JWT 的请求：

```javascript
// 假设您已经在客户端存储了 JWT，可以从本地存储或会话存储中获取
const jwtToken = 'your_jwt_token';

// 请求头部中包含 JWT
const headers = {
  'Authorization': `Bearer ${jwtToken}`,
  'Content-Type': 'application/json'
};

// 请求参数（如果有）
const payload = {
  // 请求的数据或其他参数
};

// 发送 GET 请求的示例
fetch('https://example.com/api/route', {
  method: 'GET',
  headers: headers,
})
  .then(response => {
    // 处理响应
    if (response.ok) {
      return response.json(); // 解析响应数据
    } else {
      throw new Error('请求失败');
    }
  })
  .then(data => {
    // 处理响应数据
    console.log(data);
  })
  .catch(error => {
    // 处理错误
    console.error(error);
  });

// 发送 POST 请求的示例
fetch('https://example.com/api/route', {
  method: 'POST',
  headers: headers,
  body: JSON.stringify(payload) // 将请求参数转换为 JSON 字符串
})
  .then(response => {
    // 处理响应
    if (response.ok) {
      return response.json(); // 解析响应数据
    } else {
      throw new Error('请求失败');
    }
  })
  .then(data => {
    // 处理响应数据
    console.log(data);
  })
  .catch(error => {
    // 处理错误
    console.error(error);
  });
```

在上述示例中，我们假设您已经在客户端存储了 JWT，并将其作为请求的 Authorization 头部的一部分发送。您可以根据实际情况修改请求的 URL、请求方法（GET、POST 等）、请求头部和请求参数。在处理响应时，您可以根据需要解析响应数据并执行相应的操作，或者处理请求失败的情况。

请注意，此示例使用 Fetch API 进行请求，您也可以使用其他库或工具（如 Axios）来发送请求，并在请求头部中包含 JWT。



## 5.哪些数据适合vuex状态管理，哪些适合请求接口  
在使用 Vuex 进行状态管理时，以下是一些一般的指导原则，可以帮助您确定哪些数据适合存储在 Vuex 状态管理中，而哪些数据适合通过请求接口获取：

适合存储在 Vuex 状态管理中的数据：

1. 全局共享的数据：如果多个组件需要访问和修改同一份数据，这些数据适合存储在 Vuex 中。例如，用户登录状态、当前主题、语言偏好等。

2. 缓存的数据：如果有一些数据在应用程序的生命周期中保持不变或很少变化，可以将其存储在 Vuex 中以避免重复请求。例如，用户配置、静态数据、菜单项等。

3. 异步操作的状态：如果有异步操作（如网络请求）需要跨多个组件进行状态管理，可以在 Vuex 中存储相关的状态。例如，正在加载数据、请求错误信息等。

4. 表单数据：如果多个组件需要共享相同的表单数据，可以将其存储在 Vuex 中。这样可以方便地在不同组件之间进行表单数据的读取和更新。

适合通过请求接口获取的数据：

1. 动态数据：对于频繁变化的数据，例如从服务器获取的实时数据、列表数据等，可以通过请求接口获取，并在需要时进行更新。

2. 个人用户数据：对于与特定用户相关的数据，例如用户个人资料、订单历史等，可以在用户登录后通过请求接口获取。

3. 大量数据：对于大量数据，特别是需要分页或按需加载的数据，可以通过请求接口进行分批获取，以减少初始加载时间和资源占用。

总体而言，Vuex 适用于存储全局共享的、跨组件的、需要频繁访问和修改的数据。而需要根据特定需求获取的、特定用户相关的或需要异步请求的数据，适合通过请求接口获取。根据具体的应用场景和需求，您可以灵活选择将哪些数据存储在 Vuex 中，哪些数据通过请求接口获取。


当涉及到购物车功能时，可以使用一个例子来说明哪些数据适合存储在 Vuex 状态管理中，哪些数据适合通过请求接口获取。

适合存储在 Vuex 状态管理中的数据：

1. 购物车商品列表：将用户添加到购物车的商品列表存储在 Vuex 中。这样可以确保购物车中的商品信息可以在多个组件间共享和同步更新，例如购物车页面、商品数量显示等组件都可以从 Vuex 中获取购物车商品列表。

2. 购物车总价：将购物车中商品的总价存储在 Vuex 中。这样可以方便在不同组件中进行计算和更新购物车的总价，并确保价格的一致性。

适合通过请求接口获取的数据：

1. 商品详情：当用户点击商品时，可以通过请求接口获取商品的详细信息（如名称、价格、描述等）。这样可以避免在每个组件中都重复请求相同的商品信息，而是在需要时通过接口获取最新的商品详情。

2. 用户信息：如果涉及到用户特定的购物车功能，例如保存购物车到用户账户，可以通过请求接口获取用户的个人信息，例如用户的姓名、地址等。

这个例子中，购物车商品列表和购物车总价是全局共享的数据，多个组件需要访问和修改它们，因此适合存储在 Vuex 中。而商品详情和用户信息是与特定的商品和用户相关的数据，可以通过请求接口获取，因为它们是动态的，需要根据具体情况进行获取和更新。

请注意，这只是一个示例，实际应用中根据具体需求和业务场景，您可以根据情况决定哪些数据适合存储在 Vuex 状态管理中，哪些数据适合通过请求接口获取。
