## 3.白屏事件first paint和可交互事件dom ready的关系
- [x] 先触发first paint ，后触发dom ready
- [ ] 先触发dom ready，后触发first paint
- [ ] 一起触发
- [ ] 没关系


		总加载时间 = 白屏时间(first paint) + 首屏时间 + 核心功能可用时间 + 页面可交互(DOM Ready).


页面的**性能指标**详解：

	白屏时间（first Paint Time）——用户从打开页面开始到页面开始有东西呈现为止

	首屏时间——用户浏览器首屏内所有内容都呈现出来所花费的时间

	用户可操作时间(dom Interactive)——用户可以进行正常的点击、输入等操作，默认可以统计domready时间，因为通常会在这时候绑定事件操作

	总下载时间——页面所有资源都加载完成并呈现出来所花的时间，即页面 onload 的时间

## 5.如何在 div 容器里展示 `<div></div>`这几个字符？
- [ ] `<div><div></div></div>`
- [ ] `<div>"<div></div>"</div>`            //    " "
- [x] `document.querySelector('div').innerText = "<div></div>"`
- [ ] `document.querySelector('div').innerHTML = "<div></div>"`

innerHTML：设置或获取标签所包含的HTML与文本信息。（不含标签本身）
innerText：设置或获取标签所包含的文本信息。（不含标签本身）
outerHTML：设置或获取标签本身以及所包含的HTML与文本信息。（包含标签本身）
outerText：设置或获取标签本身以及所包含的文本信息。（包含标签本身）

例如：

```js
<div id="div1">  
	<p id="p1">this is text</p>
</div>  

<script>  
	var div=document.getElementsByTagName("div");  
	console.log(div[0].innerHTML);      //  <p id="p1">this is text</p>  
	console.log(div[0].innerText);         //  this is text  
	console.log(div[0].outerHTML);     // <div id="div1"><p id="p1">this is text</p></div>  
	console.log(div[0].outerText);        //  this is text  
</script>
```


## 6.关于DOMContentLoaded和load事件说法正确的是？
- [x] DOMContentLoaded事件比load事件更早执行
- [ ] load事件比DOMContentLoaded事件更早执行
- [ ] 按监听代码从上到下先后执行
- [ ] dom文档完全加载完后执行load事件

		- DOMContentLoaded  
		    当纯HTML被完全加载以及解析时，DOMContentLoaded事件会被触发，而不必等待样式表，图片或者子框架完成加载。

		- Load  
		    当一个资源及其依赖资源已完成加载时，将触发load事件。

对于使用 `defer` 属性的脚本，它们会在文档的解析过程中下载，但是会延迟到文档解析完成后按照它们在文档中出现的顺序依次执行。因此，如果一个文档中包含有 `defer` 属性的脚本，那么 `DOMContentLoaded` 事件会在所有 `defer` 脚本执行完成后触发，而 `load` 事件会在所有资源（包括 `defer` 脚本）加载完成后触发。

对于使用 `async` 属性的脚本，它们会在下载完成后立即执行，并且不保证按照它们在文档中出现的顺序执行。因此，如果一个文档中包含有 `async` 属性的脚本，那么 `DOMContentLoaded` 事件会在所有非 `async` 脚本执行完成后触发，而 `load` 事件会在所有资源（包括 `async` 脚本）加载完成后触发。

总的来说，使用 `defer` 属性的脚本对 `DOMContentLoaded` 事件的触发时间影响较小，而使用 `async` 属性的脚本可能会对 `DOMContentLoaded` 事件的触发时间造成较大的影响。但是，无论使用哪种属性，`DOMContentLoaded` 事件仍然会比 `load` 事件先触发。

## 8.以下不是box-sizing的属性是？
- [ ] border-box
- [x] auto
- [ ] content-box
- [ ] inherit


1. content-box     
	这是由 CSS2.1 规定的宽度高度行为。
	宽度和高度分别应用到元素的内容框。
	在宽度和高度之外绘制元素的内边距和边框。

2. border-box     
	为元素设定的宽度和高度决定了 **元素** 的边框盒。
	就是说，为元素指定的任何内边距和边框都将在已设定的宽度和高度内进行绘制。
	通过从已设定的宽度和高度分别减去边框和内边距才能得到 **内容** 的宽度和高度。

3.  inherit
	规定应从父元素继承 box-sizing 属性的值。

## 11.关于 link 和 @import 区别说法错误的是（）
- [ ] link 是 XHTML 标签，无兼容问题
- [x] 两者均属于 CSS 范畴
- [ ] link 可以使用 JavaScript 控制 DOM 改变样式，@import 不支持
- [ ] link 引用 CSS 时，页面加载同时加载样式，@import 需要页面完全载入以后加载

		link是HTML方式， @import是CSS方式
		- link最大限度支持并行下载，@import过多嵌套导致串行下载，出现FOUC(文档样式短暂失效)
		- link可以通过rel="alternate stylesheet"指定候选样式
		- 浏览器对link支持早于@import，可以使用@import对老浏览器隐藏样式
		- @import必须在样式规则之前，可以在css文件中引用其他文件

1.link属于**HTML范畴**——除了加载CSS，还能支持其他事务，且在HTML页面加载的同时加载
2.@import属于**CSS范畴**——只能加载CSS


以下是一个例子，演示了如何在HTML文档中使用`link`标签和`@import`导入CSS样式表：

```html
<!DOCTYPE html>
<html>
<head>
	<title>Link vs. @import</title>
	<!-- 使用 link 标签引用外部 CSS 文件 -->
	<link rel="stylesheet" type="text/css" href="style.css">

	<style>
	/* 使用 @import 导入内部 CSS 样式 */
	@import url("https://fonts.googleapis.com/css2?family=Open+Sans:wght@300&display=swap");

	body {
		font-family: 'Open Sans', sans-serif;
	}
	</style>
</head>
<body>
	<h1>Link vs. @import</h1>
	<p>这是一个演示 link 和 @import 之间区别的页面。</p>
</body>
</html>
```

在上面的例子中，我们使用了`link`标签来引用名为`style.css`的外部样式表，并使用`@import`规则动态导入Google Fonts的字体样式。

请注意，`link`标签是HTML元素，可以在文档头部使用，而`@import`规则是CSS语法，必须在CSS样式表中使用。同时，`link`标签可以通过`rel`属性指定样式表的类型，还允许使用`media`属性来指定样式表的媒体类型，这些都是`@import`规则所不具备的功能。
