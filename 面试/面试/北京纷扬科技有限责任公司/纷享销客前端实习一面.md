3.自己写深拷贝函数
```js
function deepClone(obj) {
	if (!obj || typeof obj !== 'object') {
		return
	}
	let newObj = Array.isArray(obj) ? [] : {}
	for (let key in obj) {
		if (obj.hasOwnProperty(key)) {
			newObj[key] = typeof obj[key] === 'obj' ? deepClone(obj[key]) : obj[key]
		}
	}
	return newObj
}
```

## 3. HTTPS加密的方式：
3. HTTPS 采用了公钥加密和对称加密相结合的方式来保证通信的安全性。具体来说，HTTPS 通信的过程包括以下几个步骤：

- 客户端向服务器发起连接请求，并协商加密算法和会话密钥的生成。
- 服务器使用自己的私钥生成一份数字证书，包含了服务器的公钥、身份信息和数字签名等信息，并将其发送给客户端。
- 客户端使用服务器的公钥来加密一个新的随机数，并将其发送给服务器。
- 服务器使用自己的私钥来解密客户端发送的随机数，并使用该随机数和服务器自己生成的随机数来生成一个会话密钥，用于后续的加密通信。
- 客户端和服务器都使用会话密钥来进行对称加密通信，保证通信内容的私密性和完整性。



## 4. 为什么通过抓包还可以解析HTTPS：



4. HTTPS 通信过程中，虽然加密算法和会话密钥是保密的，但是通信的各个环节中都需要传输一些明文信息，例如数字证书、加密套件名称、随机数等。这些明文信息可以被中间人截获并篡改，从而导致通信的不安全。

为了解决这个问题，HTTPS 使用了一种叫做 TLS/SSL 中间人攻击的防御机制。具体来说，客户端和服务器之间的通信在建立连接时会进行证书验证，客户端会验证服务器的数字证书是否合法并与预期的服务器匹配，如果验证失败会中止连接。但是，如果中间人伪造了服务器的数字证书，并将自己的公钥替换为服务器的公钥，那么客户端将会认为它正在与真正的服务器通信，从而继续进行通信并将会话密钥发送给中间人。为了防止这种攻击，TLS/SSL 引入了一种叫做证书链的机制，即数字证书不仅包含了服务器的公钥和身份信息，还包含了证书颁发机构（CA）的公钥，客户端可以使用 CA 的公钥来验证服务器的数字证书是否真实有效，从而避免了中间人攻击。

然而，即使使用了这种防御机制，HTTPS 通信也可能受到其他类型的攻击，例如中间人攻击的变种攻击、会话劫持攻击等。因此，为了确保 HTTPS 的安全性，需要综合采用多种安全措施，例如使用安全的加密算法、加强身份验证、使用更安全的协议版本等。同时，也需要及时更新和修复可能存在的安全漏洞。
