8. cookie里存密码怎么保障安全性能  
```js
存储密码或其他敏感信息在 cookie 中是一个安全风险，因为 cookie 是在客户端（浏览器）上存储的，并且可能会受到各种安全威胁。为了保障安全性和性能，以下是一些推荐的做法：

1. **不要将密码直接存储在 cookie 中**：密码是敏感信息，应该避免以明文形式存储在任何地方，包括 cookie。密码应该在传输过程中进行加密，并在服务器端进行安全存储。
    
2. **使用安全的传输协议**：当用户登录时，确保使用安全的传输协议（如 HTTPS）来保护用户的密码和其他敏感信息在网络中的传输过程。这样可以防止中间人攻击和窃听。
    
3. **使用加密技术**：如果需要在 cookie 中存储一些标识符或令牌，可以使用加密技术对其进行保护。例如，可以使用加密算法（如 AES）对敏感信息进行加密，并在服务器端进行解密和验证。
    
4. **设置合适的过期时间**：为 cookie 设置适当的过期时间，确保敏感信息在合理的时间范围内有效，并及时失效。这有助于减少敏感信息被滥用的风险。
    
5. **使用 HTTP-only 和 Secure 标记**：通过设置 cookie 的 HTTP-only 标记，可以防止通过 JavaScript 访问 cookie，从而减少 XSS（跨站脚本）攻击的可能性。同时，使用 Secure 标记可以确保 cookie 只在通过 HTTPS 连接时传输。
    
6. **采用其他安全认证机制**：对于用户身份验证和访问控制，应采用更安全和可靠的机制，如使用基于令牌的身份验证（如 JWT）或单点登录（SSO）。
```
