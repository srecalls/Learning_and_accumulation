- 代码读起来更加同步，Promise虽然摆脱了回调地狱，但是then的链式调用也会带来额外的阅读负担
- Promise传递中间值非常麻烦，而async/await几乎是同步的写法，非常优雅
- 错误处理友好，async/await可以用成熟的try/catch
- Promise的错误捕获非常冗余
- 调试友好，Promise的调试很差，由于没有代码块，你不能在一个返回表达式的箭头函数中设置断点，如果你在一个.then代码块中使用调试器的步进(step-over)功能，调试器并不会进入后续的.then代码块，因为调试器只能跟踪同步代码的每一步。


异步编程中，Promise 和 async/await 都是常用的方式。以下是一个使用 Promise 和 async/await 实现的简单示例，用于异步获取用户信息：

```js
// 使用 Promise 实现异步获取用户信息
function getUserInfo() {
  return fetch('/api/user')
    .then(response => response.json())
    .then(data => {
      return {
        name: data.name,
        age: data.age,
        email: data.email
      };
    })
    .catch(error => {
      console.error('Fetch error:', error);
      throw error;
    });
}

// 使用 async/await 实现异步获取用户信息
async function getUserInfoAsync() {
  try {
    const response = await fetch('/api/user');
    const data = await response.json();
    return {
      name: data.name,
      age: data.age,
      email: data.email
    };
  } catch (error) {
    console.error('Fetch error:', error);
    throw error;
  }
}

// 调用函数并处理结果
getUserInfo().then(data => {
  console.log('User info (Promise):', data);
}).catch(error => {
  console.error('Error:', error);
});

getUserInfoAsync().then(data => {
  console.log('User info (async/await):', data);
}).catch(error => {
  console.error('Error:', error);
});
```

在这个例子中，`getUserInfo()` 函数使用 Promise 实现异步获取用户信息，`getUserInfoAsync()` 函数使用 async/await 实现异步获取用户信息。两个函数都会使用 `fetch()` 方法进行网络请求，并将响应转换为 JSON 格式。如果请求成功，则从响应中提取用户信息并返回；如果请求失败，则会抛出一个错误。在函数实现中，使用了不同的方式来处理 Promise 的链式调用和错误处理。

总的来说，async/await 比 Promise 更加易读、优雅和友好，使得异步编程更加接近同步编程的写法，同时也提供了更好的错误处理和调试体验。
