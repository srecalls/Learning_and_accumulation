## 什么是原型链
### 原型 (Prototype)

在JavaScript中，每个函数都会自动拥有一个 `prototype` 属性，这个属性是一个对象，被称为“原型对象”。当一个函数作为构造函数（使用 `new` 关键字调用）创建实例时，这个实例会**继承**原型对象上的所有属性和方法。

简单来说，原型对象就是所有实例共享的属性和方法的**模板**。

让我们看一个例子：

JavaScript

```
function Person(name, age) {
  this.name = name;
  this.age = age;
}

// 在Person的原型上添加一个方法
Person.prototype.sayHello = function() {
  console.log(`Hello, my name is ${this.name} and I am ${this.age} years old.`);
};

const person1 = new Person('Alice', 30);
const person2 = new Person('Bob', 25);

person1.sayHello(); // 输出: Hello, my name is Alice and I am 30 years old.
person2.sayHello(); // 输出: Hello, my name is Bob and I am 25 years old.

console.log(person1.sayHello === person2.sayHello); // 输出: true
```

在这个例子中：

- `Person.prototype` 就是 `Person` 函数的原型对象。
    
- `sayHello` 方法被添加到了 `Person.prototype` 上。
    
- `person1` 和 `person2` 这两个实例都通过原型继承了 `sayHello` 方法。
    
- `person1.sayHello === person2.sayHello` 为 `true`，证明它们共享的是同一个 `sayHello` 函数实例，而不是每个实例都有一份独立的副本，这可以节省内存。
    

### 原型链 (Prototype Chain)

原型链是JavaScript中实现继承的一种机制。当访问一个对象的属性时，如果这个对象本身没有这个属性，JavaScript会去它的原型对象上查找；如果原型对象也没有，就再往原型对象的原型上查找，直到找到这个属性或者查找到 `null` 为止。这个查找的过程就形成了一个“链条”，这就是原型链。

每个JavaScript对象都有一个内部属性 `[[Prototype]]`（在ES6之前可以通过 `__proto__` 访问，但现在推荐使用 `Object.getPrototypeOf()`）。这个 `[[Prototype]]` 指向的就是该对象的原型。

**完整的原型链链路：**

1. **实例对象**：
    
    - 例如 `person1`。
        
    - `person1.__proto__` 指向 `Person.prototype`。
        
2. **构造函数的原型对象 (Constructor's Prototype Object)**：
    
    - 例如 `Person.prototype`。

	Person.prototype = new Object() （错❌）
    - `Person.prototype.__proto__` 指向 `Object.prototype`。
        
    - `Person.prototype` 本身是一个普通对象，所以它的原型是 `Object.prototype`。
        
3. **Object.prototype**：
    
    - `Object.prototype` 是所有对象的最终原型。
        
    - `Object.prototype.__proto__` 指向 `null`。
        
    - `null` 是原型链的终点，表示没有再往上查找的原型了。
        

**总结一下就是：**

`实例对象` -> `其构造函数的原型对象` -> `Object.prototype` -> `null`

### 我可以理解为 Person.prototype = new Object()吗

这是一个非常好的问题，它能够帮助我们更深入地理解构造函数原型和 `Object.prototype` 的关系。

**答案是：不可以，或者说，在概念上等价，但在实际操作中存在一些重要的区别。**

### 1. 概念上的等价性 (为什么你会这样想)

`Person.prototype` **本质上就是一个对象**，而它作为对象，需要有一个原型，这个原型就是所有对象共同的终极原型：`Object.prototype`。

当你定义一个函数 `Person` 时：

JavaScript

```
function Person() {}
```

JavaScript 引擎自动创建了 `Person.prototype`，这个 `Person.prototype` **默认就继承自 `Object.prototype`**。

从原型链的角度看，下面两个关系是成立的：

1. `Person.prototype.__proto__` 等于 `Object.prototype`
    
2. `new Object().__proto__` 也等于 `Object.prototype`
    

因此，在**原型链的下一级指向**上，`Person.prototype` 和 `new Object()` 是等价的。

---

### 2. 实际操作中的区别 (为什么不能直接替换)

尽管它们都继承自 `Object.prototype`，但直接将 `Person.prototype` 赋值为 `new Object()` 会导致两个重要的副作用：

#### A. 丢失 `constructor` 属性

每个原型对象都有一个 `constructor` 属性，默认指向它关联的构造函数。

**默认情况：**

JavaScript

```
function Person() {}
console.log(Person.prototype.constructor === Person); // true
```

**替换之后：**

当你执行 `Person.prototype = new Object()` 时，你创建了一个全新的对象作为原型。这个新对象的 `constructor` 属性将指向 `Object`，而不是 `Person`。

JavaScript

```
function Person() {}
Person.prototype = new Object(); // 【错误操作示范】
console.log(Person.prototype.constructor === Person); // false
console.log(Person.prototype.constructor === Object); // true (新的原型对象是由 Object 构造的)
```

这会破坏实例对象通过 `constructor` 属性找到自己构造函数的引用。如果这样做，你需要手动修复它：

JavaScript

```
Person.prototype.constructor = Person;
```

#### B. `new Object()` 可能会有额外的自有属性

虽然 `new Object()` 创建的对象通常是空的，但从技术上讲，`new Object()` 可能会执行 `Object` 构造函数内部的一些初始化逻辑（尽管标准 `Object` 构造函数通常不会添加自有属性）。

而当你仅仅是声明一个函数时，引擎创建的 `Person.prototype` 是一个非常**纯净**的对象字面量 (`{}`)，它只包含一个指向 `Person` 的 `constructor` 属性。

### 总结

- **从继承关系上看：** `Person.prototype` 和 `new Object()` **都继承**自 `Object.prototype`。
    
- **从赋值操作上看：** 不应该用 `Person.prototype = new Object()` 来替代引擎的默认行为，因为这会**覆盖**原有的原型对象，**丢失**正确的 `constructor` 引用，从而可能导致继承关系混乱。
    

所以，正确的理解是：**`Person.prototype` 是一个对象，且它的原型是 `Object.prototype`**，但这并不意味着它是由 `new Object()` 创建的。

## Object.__proto__ === Function.prototype

构造函数原型对象的原型都是Object.prototype

构造函数的原型是Function.prototype吗

这是一个关于 JavaScript 中函数和对象的原型链的**关键性深入问题**，非常适合在面试中展现对细节的理解。

我们来逐一分析这三个要点：

### 1. `Object.__proto__`

- **结论：** `Object.__proto__` 指向 `Function.prototype`。
    
- **原因解释：**
    
    - 在 JavaScript 中，`Object` 是一个**函数**（它是一个内置构造函数）。
        
    - **所有函数都是 `Function` 构造函数的实例**。
        
    - 因此，`Object` 函数本身的原型（即 `Object.__proto__`）必须指向它的构造函数 `Function` 的原型对象，也就是 `Function.prototype`。
        

---

### 2. 构造函数原型对象的原型都是 `Object.prototype`

- **结论：** **正确**（对于自定义函数和大部分内置构造函数而言）。
    
- **原因解释：**
    
    - 假设我们有一个自定义构造函数 `Person`。
        
    - `Person.prototype` 是一个**普通对象**，它默认是通过对象字面量或类似 `new Object()` 的方式创建的。
        
    - 因此，`Person.prototype` 也会遵循所有普通对象的原型链规则，即它继承自 `Object.prototype`。
        
    - 链条是：`Person.prototype.__proto__ === Object.prototype`。
        
- **例外说明：** 唯一的例外是 `Object.prototype` 本身。
    
    - `Object.prototype` 是原型链的终点，它的原型是 `null`。
        
    - 即：`Object.prototype.__proto__ === null`。
        

---

### 3. 构造函数的原型是 `Function.prototype` 吗？

- **结论：** **正确**。这里问的是**构造函数本身**（例如 `Person` 函数）的原型，而不是它的 `prototype` 属性。
    
- **原因解释：**
    
    - 构造函数，例如 `Person`、`Array`、`String` 等，它们本质上都是函数。
        
    - 如第 1 点所述，所有函数都是 `Function` 的实例。
        
    - 因此，任何构造函数 `C` 的原型（即 `C.__proto__`）都指向 `Function.prototype`。
        

### 完整图示总结 (双重原型链)

为了避免混淆，我们需要区分两个原型链：

|**关系**|**符号表示**|**指向哪里？**|**作用是什么？**|
|---|---|---|---|
|**【函数链】**|**`构造函数.__proto__`**|`Function.prototype`|提供了函数才具有的方法（如 `call`, `apply`, `bind`）。|
|**【实例链】**|**`构造函数.prototype`**|自定义的**原型对象**|提供了该构造函数**实例**继承的方法（如 `sayHello`）。|

例如，对于 `Person` 构造函数：

- `Person.__proto__ === Function.prototype` (因为 `Person` 是函数)
    
- `Person.prototype.__proto__ === Object.prototype` (因为 `Person.prototype` 是对象)
    

您的这三个问题，完整地串联起了 JavaScript 中最复杂的原型链结构！


## 那我可以认为 const Object = new Function()吗

这是一个非常深刻且关键的思考！

从 **“所有函数都是 `Function` 的实例”** 这一原则出发，你的推断 **`const Object = new Function()`** 在某种程度上是**概念等价**的，但同样，在实际运行时和底层实现上，这种替换是**不成立的**。

### 为什么在概念上是等价的？

  * **原则：** 在 JavaScript 中，`Function` 是所有函数的**终极构造函数**。
  * **应用：**
      * `Object` 是一个内置的构造函数（一个函数）。
      * 因此，`Object` 必须是 `Function` 的一个实例。
      * 实例的原型链：`Object.__proto__` 必须指向 `Function.prototype`。
      * 如果你执行 `new Function(...)`，你创建的新函数 `F` 也会有 `F.__proto__ === Function.prototype`。

所以，从**原型继承关系**的角度来看，`Object` 这个内置函数和 `new Function()` 创建的任何函数，它们的原型链结构是**一致的**。

### 为什么在实际操作上不能等同？

直接将 `Object` 视为 `new Function()` 有几个核心问题：

#### 1\. 内部实现和原生性 (Native Code)

`Object` 是 JavaScript 语言本身就存在的**内置构造函数 (Built-in Constructor)**。它的实现是高度优化的，通常由引擎的 C++ 代码直接实现，拥有特殊的内部槽位和权限。

如果你执行 `const MyObject = new Function('/* Object的全部底层代码 */');`：

  * `new Function()` 创建的是一个**普通函数**，它只能通过字符串参数创建函数体，无法访问到语言底层的原生构造逻辑。
  * 你创建的 `MyObject` 只是一个普通的 JS 函数，它无法执行 `Object` 构造函数所拥有的**创建和初始化对象的原生能力**。例如，它无法原生处理 `{}` 字面量的创建。

#### 2\. 身份和名称 (`name` 属性)

内置的 `Object` 构造函数的身份是固定的。

  * `Object.name` 属性是 `"Object"`。

如果你用 `new Function()` 创建：

```javascript
const F = new Function();
console.log(F.name); // 输出通常是空字符串或 'anonymous'
```

#### 3\. 构造函数的功能性

`Object` 构造函数有特殊的行为，例如：

  * 当它被调用时，它会根据传入参数的类型返回不同的值，或者创建一个新的普通对象。
  * 它支持各种静态方法（如 `Object.keys`, `Object.create`）。

`new Function()` 只是创建了一个空壳函数，不具备这些特殊的内置功能。

### 总结

  * **面试/概念层面：** 你的理解是正确的——`Object` 是 `Function` 的一个实例，因此它们具有相同的原型链结构。这是理解函数链的关键。
  * **底层/运行层面：** `Object` 是一个拥有特殊身份、原生实现和底层权限的**语言基石**，不能通过执行 JS 代码（如 `new Function()`）来简单地创建或替换。
