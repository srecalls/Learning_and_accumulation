## (1)垃圾回收的概念
**垃圾回收**:JavaScript代码运行时，需要**分配内存空间**来**储存变量和值**。当**变量不在参与运行**时，就需要系**统收回被占用的内存空间**，这就是**垃圾回收**。

回收机制:
- Javascript 具有**自动垃圾回收机制**，会**定期**对那些**不再使用的变量、对象**所**占用的内存**进行**释放**
- 原理就是**找到不再使用的变量，然后释放掉其占用的内存.**
- JavaScript中存在两种变量:局部变量和全局变量。**全局变量的生命周期**会持续要**页面卸载**，而**局部变量**声明在**函数中**，它的生命周期**从函数执行开始，直到函数执行结束**，在这个过程中，局部变量会**在堆或栈中存储它们的值**，当函数执行结束后，这些局部变量不再被使用，**它们所占有的空间就会被释放**
- 不过，**当局部变量**被**外部函数使用时**，其中一种情况就是**闭包**，在函数执行结束后，**函数外部的变量依然指向函数内部的局部变量**，此时**局部变量**依然在被使用，所以**不会回收。**

## (2)垃圾回收的方法
浏览器通常使用的垃圾回收方法有两种:**标记清除**，**引用计数**
### (1)标记清除
- **标记清除**是浏览器**常见**的垃圾回收方式，当变量进入执行环境（执行上下文）时，就**标记这个变量“进入环境”**，**被标记**为“进入环境”的变量是**不能被回收的**，因为他们正在被使用。当变量**离开环境时**.就**会被标记为“离开环境”**，**被标记为“离开环境”的变量会被内存释放。**
- 垃圾收集器在运行的时候会给**存储在内存中的所有变量都加上标记**。然后，它会**去掉环境中的变量**以及**被环境中的变量引用的标记**。而在此**之后再被加上标记的变量将被视为准备删除的变量**，原因是环境中的变量已经无法访问到这些变量了。最后。垃圾收集器完成内存清除工作，销毁那些带标记的值，并回收他们所占用的内存空间。

##### 例子
当一个 JavaScript 函数执行时，会创建一个新的执行环境，这个执行环境会包含函数内部定义的变量、函数和参数等信息。当函数执行完毕后，执行环境就会被销毁，其中包含的变量、函数和参数等信息也会被回收。

让我们以一个简单的例子来说明标记清除算法的工作原理。考虑以下代码：

```js
function foo() {
  var a = 1;
  var b = 2;
  var c = { x: a, y: b };
  return c;
}

var result = foo();
```

当 JavaScript 引擎执行函数 `foo()` 时，会创建一个新的执行环境，其中包含了变量 `a`、`b` 和对象 `c`。此时，垃圾收集器会给这些变量加上标记，表示它们正在被使用。然后，函数 `foo()` 返回对象 `c`，并将其赋值给变量 `result`。

当函数 `foo()` 执行结束后，执行环境就会被销毁。此时，垃圾收集器会检查内存中的变量，发现变量 `a` 和 `b` 已经不在环境中了，因此将它们的标记清除。但是变量 `c` 中的对象还在被变量 `result` 引用着，因此它的标记会被保留。

如果后续代码中不再使用变量 `result`，那么对象 `c` 就成为了垃圾，可以被回收。此时，垃圾收集器会将对象 `c` 的标记清除，并回收它所占用的内存空间。这就是标记清除算法的基本工作原理。

##### 处理循环引用的原因
好的，让我们通过一个例子来说明标记清除算法如何处理循环引用的问题。

假设我们有两个对象 `obj1` 和 `obj2`，它们互相引用着对方：

```js
var obj1 = {};
var obj2 = {};

obj1.prop = obj2;
obj2.prop = obj1;
```

这样，我们就创建了一个循环引用的结构。如果我们使用标记清除算法进行垃圾回收，它会在标记阶段遍历所有存储在内存中的对象，并标记所有被引用的对象。在这个例子中，当垃圾收集器遍历到对象 `obj1` 时，它会标记对象 `obj2`，因为 `obj1` 引用了 `obj2`。接着，当垃圾收集器遍历到对象 `obj2` 时，它又会标记对象 `obj1`，因为 `obj2` 引用了 `obj1`。这样，对象 `obj1` 和 `obj2` 都被正确地标记了。

在清除阶段，垃圾收集器会遍历所有存储在内存中的对象，清除所有没有被标记的对象，也就是那些没有被引用的对象。由于对象 `obj1` 和 `obj2` 互相引用，它们都被标记了，因此它们不会被错误地清除。这样，通过标记清除算法，我们就正确地处理了循环引用的问题，保证内存中的所有垃圾都能被正确回收。

##### 引用计数错误原因
是的，引用计数法无法处理循环引用的问题，因为它只是简单地维护每个对象被引用的次数，当引用次数为0时就将其回收。在存在循环引用的情况下，两个对象互相引用，它们的引用计数永远不会变为0，因此它们都不会被回收，导致内存泄漏。

让我们以一个例子来说明引用计数法无法处理循环引用的问题：

假设我们有两个对象 `obj1` 和 `obj2`，它们互相引用着对方：

```
var obj1 = {};
var obj2 = {};

obj1.prop = obj2;
obj2.prop = obj1;
```

在引用计数法中，当我们创建对象 `obj1` 和 `obj2` 时，它们的引用计数都是0。然后，当我们将 `obj1` 的属性 `prop` 设置为 `obj2`，会使得 `obj2` 的引用计数加1。接着，当我们将 `obj2` 的属性 `prop` 设置为 `obj1`，会使得 `obj1` 的引用计数加1。此时，两个对象的引用计数都为1。

在这个例子中，对象 `obj1` 引用了 `obj2`，而 `obj2` 又引用了 `obj1`，它们的引用计数永远不会变为0。因此，即使这两个对象已经没有被任何其他对象引用，它们也不会被回收，导致内存泄漏。

综上所述，引用计数法无法处理循环引用的问题，而标记清除算法则可以正确处理循环引用的情况。

### (2)引用计数
另外一种垃圾回收机制就是**引用计数**，这个**用的相对较少**。引用计数就是**跟踪记录每个值被引用的次数**。当声明了一个变量并将一个引用类型赋值给该变量时，则这个值的**引用次数就是1**。相反，**如果包含对这个值引用的变量又取得了另外一个值**,则这个值的**引用次数就减**1。当这个**引用次数变为0时，说明这个变量已经没有价值**，因此，在在机回收期下次再运行时，这个变量所占有的内存空间就会被释放出来。

这种方法会引起循环引用的问题: 例如:obj1 和 obj2 通过属性进行相互引用，**两个对象的引用次数都是2**。当使用循环计数时，由于函数执行完后，两个对象都离开作用域，函数执行结束，obj1 和 obj2 还将会继续存在，因此它们的引用次数**永远不会是0，就会引起循环引用**
```js
function fun() {
	let obj1 = {}
	let obj2 = {}
	obj1.a = obj2 // obj1 引用 obj2
	obj2.a = obj1 // obj2 引用 obj1
}
```

这种情况下，就要手动释放变量占用的内存
```js
obj1.a = null
obj2.a = null
```

## (3)减少垃圾回收
虽然浏览器可以进行垃圾自动回收，但是当代码比较复杂时，垃圾回收所带来的代价比较大，**所以应该尽量减少垃圾回收**。
- 1. 对数组进行优化:**在清空一个数组时，最简单的方法就是给其赋值为`[]`**，但是与此同时**会创建一个新的空对象**，**可以将数组的长度设置为0**，以此来达到**清空数组**的目的。
- 2. 对 object 进行优化:对象**尽量复用**，对于不再使用的对象就将其设置为**null**，尽快被回收。
- 3. 对函数进行优化:在循环中的函数表达式，**如果可以复用，尽量放在函数的外面**



1. 对数组进行优化的例子：

```javascript
let myArray = [1, 2, 3, 4, 5];

// 通过赋值为[]的方式清空数组
myArray = [];

// 通过设置数组长度为0的方式清空数组
myArray.length = 0;
```

在这个例子中，我们可以看到两种清空数组的方法。第一种方法是将数组赋值为空数组，这将创建一个新的空对象并将其赋值给 `myArray` 变量，从而清空了原始数组。第二种方法是将数组的长度设置为0，这将直接清空数组而不会创建新的对象。

2. 对对象进行优化的例子：

```javascript
let myObject = { prop1: 'value1', prop2: 'value2' };

// 对象复用
let anotherObject = myObject;

// 对象设置为 null
myObject = null;
```

在这个例子中，我们首先创建了一个对象 `myObject`，然后将其复制给另一个变量 `anotherObject`，从而使得两个变量都指向同一个对象。这可以避免创建新的对象，从而减少垃圾回收的负担。最后，我们将 `myObject` 设置为 `null`，从而标记它为不再使用的对象，尽快被垃圾回收器回收。

3. 对函数进行优化的例子：

```javascript
function processArray(arr, processFn) {
  for (let i = 0; i < arr.length; i++) {
    const processedValue = processFn(arr[i]);
    console.log(processedValue);
  }
}

// 在循环之前定义函数
function someFunction(value) {
  // do some processing
  return processedValue;
}

const myArray = [1, 2, 3, 4, 5];

// 将函数作为参数传递
processArray(myArray, someFunction);
```

在这个例子中，我们定义了一个函数 `processArray`，它接受一个数组和一个处理函数作为参数，然后在循环中调用处理函数对数组元素进行处理。为了优化这个过程，我们将处理函数 `someFunction` 提取到循环之外，并将其作为参数传递给 `processArray` 函数。这样可以避免在每次循环迭代时都创建新的函数对象，从而减少垃圾回收的负担。


## version2
JavaScript 中的垃圾回收机制主要有两种方式：标记清除和引用计数。

1. 标记清除（Mark and Sweep）：标记清除算法的基本思想是通过标记不再使用的对象，然后将其回收。垃圾回收器会在内存中找到所有的变量和可访问的对象，然后将其标记为“存活”的对象。未被标记的对象就被认为是垃圾，可以被回收。标记清除算法的缺点是需要遍历整个对象，这会消耗一定的时间和计算资源。

2. 引用计数（Reference Counting）：在引用计数算法中，每个对象都有一个引用计数，记录有多少个地方引用了该对象。当引用计数为 0 时，对象就被认为是垃圾，可以被回收。引用计数算法的优点是实现简单，但是它的缺点是无法处理循环引用的情况。如果两个对象互相引用，它们的引用计数永远不为 0，导致它们永远不会被回收，这就会导致内存泄漏问题。

在现代浏览器中，一般会使用标记清除算法作为主要的垃圾回收机制，同时也会结合引用计数算法来处理一些特殊情况，例如处理循环引用的情况。此外，还有一些优化技术，例如分代回收和增量回收，可以提高垃圾回收的效率和性能。
