**一般使用字面量**的形式直接创建对象，但是这种创建方式对于**创建大量相似对象的时候**，会**产生大量的重复代码**。但 js和一般的面向对象的语言不同，在 ES6 之前它没有类的概念。但是可以使用函数来进行模拟，从而产生出**可复用的对象创建方式**，常见的有以下几种:

## 1.工厂模式
(1) 第一种是**工厂模式**，工厂模式的主要工作原理是**用函数来封装创建对象的细节**，从而通过**调用函数来达到复用**的目的。但是它有一个很大的问题就是**创建出来的对象无法和某个类型联系起来**，它只是简单的封装了复用代码，而没有建立起对象和类型间的关系。
```js
function createPerson(name, age, email) {
  return {
    name: name,
    age: age,
    email: email,
    sayHello: function() {
      console.log(`Hello, my name is ${this.name}, I'm ${this.age} years old.`);
    }
  };
}

const person1 = createPerson('Alice', 20, 'alice@example.com');
const person2 = createPerson('Bob', 25, 'bob@example.com');
person1.sayHello(); // 输出：Hello, my name is Alice, I'm 20 years old.
person2.sayHello(); // 输出：Hello, my name is Bob, I'm 25 years old.
```
上面的代码演示了工厂模式的实现。`createPerson` 函数封装了创建对象的细节，通过**调用函数可以创建新的对象**，从而达到**代码复用的目**的。但是由于工厂模式创建的对象没**有和某个类型建立联系**，因此**无法通过原型来识别对象的类型。**


## 2.构造函数模式
(2) 第二种是**构造函数模式**。js 中**每一个函数**都可以作为**构造函数**，只要**一个函数是通过 new 来调用**的，那么就可以把它称为**构造函数**。

	1.执行构造函数首先会创建一个对象
	2.然后将对象的原型指向构造函数的 prototype 属性
	3。然后将执行上下文中的 this 指向这个对象
	4.最后再执行整个函数，如果返回值不是对象，则返回新建的对象。
	
因为 this 的值指向了新建的对象，因此可**以使用 this** 给对象**赋值**。构造函数模式相对于工厂模式的优点是，**所创建的对象和构造函数建立起了联系**，因此可以通过**原型来识别对象的类型**。但是构造函数存在一个缺点就是，**造成了不必要的函数对象的创建**，因为在 js 中函数也是一个对象，因此如果**对象属性中如果包含函数**的话，那么每次都会**新建一个函数对象**，浪费了不必要的内存空间因为函数是所有的实例都可以通用的
```js
function Person(name, age, email) {
  this.name = name;
  this.age = age;
  this.email = email;
  this.sayHello = function() {
    console.log(`Hello, my name is ${this.name}, I'm ${this.age} years old.`);
  };
}

const person3 = new Person('Charlie', 30, 'charlie@example.com');
const person4 = new Person('David', 35, 'david@example.com');
person3.sayHello(); // 输出：Hello, my name is Charlie, I'm 30 years old.
person4.sayHello(); // 输出：Hello, my name is David, I'm 35 years old.
```
上面的代码演示了构造函数模式的实现。`Person` 函数作为构造函数，通过 `new` 关键字来创建新的对象。在构造函数内部使用 `this` 关键字来给对象赋值，从而达到复用的目的。但是由于**每次创建新的对象时，都会创建新的函数对象**，因此会造成不必要的内存浪费。

## 3.原型模式
(3)第三种模式是**原型模式**，因为每一个函数都有一个**prototype 属性**，这个属性是一个**对象**，它**包含了通过构造函数创建**的**所有实例都能共享的属性和方法**。因此可以使用原型对象来**添加公用属性和方法**，从而**实现代码的复用**。这种方式相对于构造函数模式来说，**解决了函数对象的复用问题**。
但是这种模式也存在一些问题，
一个是**没有办法通过传入参数来初始化值**
另一个是**如果存在一个引用类型如 Array** 这样的值，那么**所有的实例将共享一个对象**，**一个实例对引用类型值的改变会影响所有的实例**。
```js
function PersonPrototype() {}
PersonPrototype.prototype.name = '';
PersonPrototype.prototype.age = 0;
PersonPrototype.prototype.email = '';
PersonPrototype.prototype.sayHello = function() {
  console.log(`Hello, my name is ${this.name}, I'm ${this.age} years old.`);
};

const person5 = new PersonPrototype();
person5.name = 'Emma';
person5.age = 40;
person5.email = 'emma@example.com';
person5.sayHello(); // 输出：Hello, my name is Emma, I'm 40 years old.
```
上面的代码演示了原型模式的实现。在这种模式下，通过构造函数创建的所有实例都能共享原型对象的属性和方法，从而达到代码复用的目的。但是如果存在一个引用类型值，那么所有的实例将共享一个对象，一个实例但是这种模式也存在一些问题，
一个是**没有办法通过传入参数来初始化值**
另一个是**如果存在一个引用类型如 Array** 这样的值，那么**所有的实例将共享一个对象**，**一个实例对引用类型值的改变会影响所有的实例**。
```js
function PersonPrototype() {}
PersonPrototype.prototype.name = '';
PersonPrototype.prototype.age = 0;
PersonPrototype.prototype.email = '';
PersonPrototype.prototype.sayHello = function() {
  console.log(`Hello, my name is ${this.name}, I'm ${this.age} years old.`);
};

const person5 = new PersonPrototype();

person5.sayHello(); // 输出：Hello, my name is Emma, I'm 40 years old.

const person1 = new PersonPrototype();

person1.skills.push('JavaScript');
console.log(person1.skills); // 输出：['JavaScript']
console.log(person2.skills); // 也输出：['JavaScript']
```
上面的代码演示了**原型模式**的实现。在这种模式下，通过构造函数创建的**所有实例都能共享原型对象的属性和方法**，从而达到代码复用的目的。但是**如果存在一个引用类型值**，那么所有的实例将**共享一个对象**，**一个实例对引用类型值的改变会影响所有的实例。**


## 4.组合使用构造函数模式和原型模式
(4)第四种模式是**组合使用构造函数模式和原型模式**，这是**创建自定义类型的最常见方式**。因为**构造函数模式**和**原型模式**分开使用**都存在一些问题**，因此**可以组合使用这两种模式**，

通过**构造函数来初始化对象的属性**，通过**原型对象来实现函数方法的复用**。这种方法很好的解决了两种模式单独使用时的缺点，但是有一点不足的就是，因为**使用了两种不同的模式，所以对于代码的封装性不够好**
```js
function PersonCombine(name, age, email) {
  this.name = name;
  this.age = age;
  this.email = email;
  this.skills = []
}

PersonCombine.prototype.sayHello = function() {
  console.log(`Hello, my name is ${this.name}, I'm ${this.age} years old.`);
};

const person6 = new PersonCombine('Frank', 45, 'frank@example.com', [1, 2, 3]);
const person7 = new PersonCombine('Grace', 50, 'grace@example.com', [4, 5, 6]);
person6.sayHello(); // 输出：Hello, my name is Frank, I'm 45 years old.
person7.sayHello(); // 输出：Hello, my name is Grace, I'm 50 years old.
```
上面的代码演示了**组合使用构造函数模式和原型模式**的实现。这种模式通过**构造函数**来**初始化对象的属性**，通过**原型对象**来实现**函数方法的复用**。相对于单独使用构造函数模式和原型模式，这种模式可以更好地解决它们各自存在的问题。

## 5.动态原型模式
(5)第五种模式是**动态原型模式**，这一种模式**将原型方法赋值**的创建过程移动到了**构造函数的内部**，通过**对属性是否存在的判断**，可以实现**仅在第一次调用函数时对原型对象赋值一次的效果**。这一种方式很好地对上面的混合模式进行了封装。
```js
function PersonDynamic(name, age, email) {
 this.name = name;
  this.age = age;
  this.email = email;
  if (typeof this.sayHello !== 'function') {
    PersonDynamic.prototype.sayHello = function() {
      console.log(`Hello, my name is ${this.name}, I'm ${this.age} years old.`);
    };
  }
}

const person8 = new PersonDynamic('Henry', 55, 'henry@example.com');
const person9 = new PersonDynamic('Ivy', 60, 'ivy@example.com');
person8.sayHello(); // 输出：Hello, my name is Henry, I'm 55 years old.
person9.sayHello(); // 输出：Hello, my name is Ivy, I'm 60 years old.
```
上面的代码演示了动态原型模式的实现。这种模式**在构造函数内部**通过**检测方法**是否存在来**动态地初始化原型对象**，从而解决了原型模式存在的问题。这种模式的代码比较简洁，但是有些开发者可能会觉得难以理解

## 6.寄生构造函数模式
(6)第六种模式是**寄生构造函数模式**，这一种模式和**工厂模式的实现基本相同**，我对这个模式的理解是，它主要是**基于一个已有的类型**，在**实例化时对实例化的对象进行扩展**。这样既**不用修改原来的构造函数**，也达到了**扩展对象的目**的。它的一个缺点和工厂模式样，**无法实现对象的识别**
```js
function createPersonObject(name, age, email) {
  const obj = new Object();
  obj.name = name;
  obj.age = age;
  obj.email = email;
  obj.sayHello = function() {
    console.log(`Hello, my name is ${this.name}, I'm ${this.age} years old.`);
  };
  return obj;
}

const person10 = createPersonObject('Jack', 65, 'jack@example.com');
const person11 = createPersonObject('Kate', 70, 'kate@example.com');
person10.sayHello(); // 输出：Hello, my name is Jack, I'm 65 years old.
person11.sayHello(); // 输出：Hello, my name is Kate, I'm 70 years old.
```
上面的代码演示了寄生构造函数模式的实现。这种模式在工厂模式的基础上**加入了构造函数**的特点，通过**创建一个新的对象**并为其**添加方法和属性来实现代码复用**的目的。但是由于它**仍然存在创建新的函数对象的问题**，因此不如组合使用构造函数模式和原型模式更为优秀。

## 工厂模式和寄生构造函数模式的区别
工厂模式和寄生构造函数模式的实现方法基本相同，都是通过函数来封装创建对象的细节，从而达到代码复用的目的。它们的主要区别在于，寄生构造函数模式是基于一个已有的类型，在实例化时对实例化的对象进行扩展，而工厂模式则是简单地封装了复用代码，创建出来的对象没有和某个类型建立联系。

具体来说，工厂模式创建对象时，使用的是一个自定义的函数来封装对象的创建过程，返回的是**一个新的对象字面量**，这个对象字面量**包含了创建对象时需要的属性和方法**。而寄生构造函数模式创建对象时，**先创建一个新的对象**，然后再**为这个新对象添加需要的属性和方法**，最后返回**这个新对象。**

例如，在上面的代码示例中，`createPerson` 和 `createPersonObject` 函数的实现基本相同，但是它们的返回值不同。`createPerson` 函数返回的是一个新的对象字面量，这个对象字面量包含了 `name`、`age`、`email` 和 `sayHello` 属性和方法。而 `createPersonObject` 函数返回的是一个新的对象，这个新对象通过 `new Object()` 创建，然后为这个新对象添加了 `name`、`age`、`email` 和 `sayHello` 属性和方法，最后返回这个新对象。

总之，工厂模式和寄生构造函数模式都是通过函数来封装创建对象的细节，从而达到代码复用的目的。它们的主要区别在于，**工厂模式创建出来的对象没有和某个类型建立联系**，而**寄生构造函数模式是基于一个已有的类型**，在**实例化时对实例化的对象进行扩展。**
