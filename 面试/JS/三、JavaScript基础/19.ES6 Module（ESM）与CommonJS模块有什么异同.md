ES6模块与CommonJS模块的区别
- CommonJS是对模块的**浅拷贝**，ES6 Module是对**模块的引用**，即ES6Module只存只读，不能改变其值，也就是指针指向不能变，类似const
- import的接口是read-only (只读状态)，不能修改其变量值。 即不能修改其变量的指针指向，但可以改变变量内部指针指向，可以对commonJS对重新赋值 (改变指针指向)，但是对ES6 Module赋值会编译报错

ES6 Module和CommonJS模块的共同点:

- CommonJS和ES6 Module都可以对引入的对象进行赋值，即对对象内部属性的值进行改变。


##### 例子

好的，让我来举个例子来说明 ES6 Module 和 CommonJS 模块的区别。

首先，我们来看一下 CommonJS 模块的例子。假设我们有两个模块 `a.js` 和 `b.js`，其中 `a.js` 导出了一个对象，`b.js` 导入了这个对象，并修改了其中的属性值，如下所示：

```javascript
// a.js
let obj = { value: 1 };
module.exports = obj;

// b.js
let obj = require('./a');
obj.value = 2;
console.log(require('./a').value); // 输出 2
```

在这个例子中，我们可以看到，`b.js` 导入了 `a.js` 导出的对象，然后修改了其中的 `value` 属性的值，最后再次输出了 `a.js` 中的 `value` 属性的值，发现已经被修改为了 2。

接下来，我们来看一下 ES6 Module 的例子。同样假设有两个模块 `a.js` 和 `b.js`，其中 `a.js` 导出了一个对象，`b.js` 导入了这个对象，并尝试修改其中的属性值，如下所示：

```javascript
// a.js
let obj = { value: 1 };
export default obj;

// b.js
import obj from './a.js';

// 修改内部属性值
obj.value = 2;
console.log(obj); // { value: 2 }

// 修改指针指向
obj = { value: 3 };
console.log(obj); // { value: 3 }
```


在这个例子中，我们首先尝试修改了 `a.js` 中导出的对象的属性值，这是允许的，因为在 ES6 Module 中，我们可以修改导入的对象的内部属性的值，而不会影响到原始导出的对象。因此，我们可以看到控制台输出的对象 `{ value: 2 }`。

然后，我们尝试修改了导入的对象的指针指向，即将其重新赋值为一个新的对象 `{ value: 3 }`。但是，这样的操作会导致编译错误，因为在 **ES6 Module 中，导入的变量是只读的**，我们不能修改其指针指向，即不能重新赋值为其他的对象。因此，这里会抛出一个编译错误，导致下面的控制台输出语句不会被执行。

总之，在 ES6 Module 中，导入的变量是只读的，我们不能修改其指针指向，即不能重新赋值为其他的对象，但是我们可以修改其内部属性的值。

因此，ES6 Module 和 CommonJS 模块在对导入模块对象的属性进行修改时是有区别的。在 CommonJS 模块中，我们可以直接修改导入的对象的属性值，而在 ES6 Module 中，我们只能修改其内部属性的值，但不能修改其指针指向。



## Cannot use import statement outside a module`
在 JavaScript 中，当我们使用 ES6 Module 的语法进行模块导入时，需要将相关代码保存为 `.mjs` 或 `.js` 文件，并且需要在对应的 HTML 或 JavaScript 文件中添加 `type="module"` 属性。

如果我们在一个没有添加 `type="module"` 属性的 HTML 或 JavaScript 文件中使用 ES6 Module 的语法进行模块导入，就会出现 `Cannot use import statement outside a module` 的错误提示。

例如，假设我们有一个 `index.html` 文件和一个 `app.js` 文件，且在 `app.js` 中使用 ES6 Module 的语法进行模块导入：

```html
<!-- index.html -->
<html>
  <head>
    <title>ES6 Module Demo</title>
    <!-- 没有添加 type="module" 属性 -->
  </head>
  <body>
    <script src="app.js"></script>
  </body>
</html>
```

```javascript
// app.js
import { add } from './math.js';
console.log(add(1, 2));
```

这样的代码会导致 `Cannot use import statement outside a module` 的错误提示，因为我们没有在 `index.html` 中添加 `type="module"` 属性，导致 JavaScript 引擎无法识别这个文件是一个 ES6 Module。要解决这个问题，我们需要在 `index.html` 中添加 `type="module"` 属性：

```html
<!-- index.html -->
<html>
  <head>
    <title>ES6 Module Demo</title>
    <script type="module" src="app.js"></script>
  </head>
  <body>
  </body>
</html>
```

这样就可以正确地加载 ES6 Module，并且不会出现 `Cannot use import statement outside a module` 的错误提示了。



要在 HTML 中测试 ES6 Module，你需要将你的代码保存为 `.mjs` 或 `.js` 文件，并且需要在 HTML 文件中添加 `type="module"` 属性。同时，你需要使用一个能够支持 ES6 Module 的浏览器来运行你的代码。

下面是一个简单的例子，假设你有一个 `a.js` 和 `b.js` 文件，以及一个 `index.html` 文件，你需要在 `index.html` 文件中添加 `type="module"` 属性，然后在其中导入和使用 `a.js` 和 `b.js` 文件中的模块：

```html
<!-- index.html -->
<!DOCTYPE html>
<html>
  <head>
    <title>ES6 Module Demo</title>
    <script type="module" src="./a.js"></script>
    <script type="module" src="./b.js"></script>
  </head>
  <body>
  </body>
</html>
```

```javascript
// a.js
let obj = { value: 1 };
export default obj;
```

```javascript
// b.js
import obj from './a.js';
console.log(obj);
```

在这个例子中，我们在 `index.html` 文件中添加了两个 `<script>` 标签，分别引入了 `a.js` 和 `b.js` 文件中的模块，并在 `b.js` 中使用 `import` 语法导入了 `a.js` 文件中导出的默认对象，并在控制台输出了这个对象的值。

注意，在这个例子中，我们没有使用 `src` 属性来指定 `type="module"` 的脚本文件，而是直接在 `<script>` 标签中写入了脚本代码。这是因为大多数浏览器不允许在 `type="module"` 的脚本文件中使用 `inline script`，所以我们需要将代码保存为独立的 `.mjs` 或 `.js` 文件，并通过 `src` 属性来引入它们。

需要注意的是，由于浏览器对文件协议 (`file://`) 的限制，如果你直接在浏览器中打开 HTML 文件进行测试，可能会出现 `Access to script at 'file://...' has been blocked by CORS policy` 的错误提示。你可以使用一个本地服务器（如 Node.js 中的 `http-server` 模块）来启动一个本地服务器，并访问 `http://localhost:port` 来测试你的代码。



ES6 模块（ESM）和 CommonJS 模块是 JavaScript 中两种不同的模块系统，它们在语法和使用方式上有一些异同之处。

异同点：

1. 语法差异：ES6 模块使用 `import` 和 `export` 关键字来导入和导出模块，而 CommonJS 模块使用 `require()` 和 `module.exports` 来实现相同的功能。

2. 加载时机：ES6 模块是在编译时进行静态分析和加载的，这意味着模块的依赖关系在代码执行之前就已经确定。而 CommonJS 模块是在运行时动态加载的，模块的依赖关系可以根据代码的逻辑和条件进行动态加载。

3. 导入和导出方式：ES6 模块支持命名导入和导出，可以选择性地导入和导出模块中的特定成员，也可以使用默认导出。CommonJS 模块只支持默认导出和整体导入，不能进行选择性导入。

4. 导入的值的引用方式：ES6 模块的导入是基于值的引用，也就是说，导入的值是只读的，无法修改导入值的属性。而 CommonJS 模块的导入是基于拷贝的，导入的值可以被修改，修改后的值不会影响到原始模块。

5. 动态导入：ES6 模块支持动态导入，可以在代码的任意位置根据条件或需要动态加载模块。而 CommonJS 模块不支持动态导入，导入的模块在运行时确定。

6. 浏览器兼容性：ES6 模块是 ECMAScript 官方标准的一部分，现代浏览器对其有原生支持。而 CommonJS 模块最初是为 Node.js 开发的，不是浏览器原生支持的模块系统，需要使用工具进行转换或者使用打包工具如 webpack 进行处理。

需要注意的是，ES6 模块和 CommonJS 模块虽然有一些差异，但可以通过使用工具或者转换库来在不同的环境中进行互相转换和兼容。例如，可以使用 Babel 转换 ES6 模块为 CommonJS 模块，或者使用 webpack 提供的功能将 CommonJS 模块打包为 ES6 模块。这样可以在不同的环境中共享和使用模块。


1. 语法差异：CommonJS使用require语法引入模块，而ESM使用import语法引入模块。
2. 加载方式：CommonJS使用同步加载方式，即遇到require就执行代码，并等待结果返回后再继续执行；而ESM使用异步加载方式，它是通过Promise的方式异步加载模块，遇到import不会阻止程序继续执行。
3. 动态导入：ESM支持动态导入，在运行时根据需要加载模块，而这在CommonJS中是不可行的。
4. 延迟执行：ESM在导入模块时会自动进行tree-shaking，只会导入当前模块需要的部分，而CommonJS则会导入整个模块。这意味着，在ESM中可以在编译时进行优化（如DCE），但是在CommonJS中只能在运行时进行优化。
