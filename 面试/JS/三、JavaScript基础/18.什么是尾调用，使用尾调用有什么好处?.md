**尾调用**指的是函数的**最后一步**调用**另一个函数**。代码执行是**基于执行栈**的，所以当在一个函数里调用另一个函数时，会**保留当前的执行上下文**，然后再**新建**另外一个**执行上下文加入**栈中。使用尾调用的话，因为已经是函数的最后一步，所以这时可以不必再保留当前的执行上下文，从而节省了内存，这就是尾调用优化。但是 ES6 的尾调用优化只在严格模式下开启，正常模式是无效的


好的，让我来举个例子来说明尾调用优化。

假设我们有两个函数 `foo` 和 `bar`，其中 `foo` 中调用了 `bar`，如下所示：

```javascript
function foo(x) {
  // 这里是函数的一些逻辑
  return bar(x);
}
```

在执行 `foo` 函数的时候，JavaScript 引擎会将当前的执行上下文（比如局部变量、函数参数等）压入执行栈中，并在新的执行上下文中执行 `bar` 函数。当 `bar` 函数执行完毕后，JavaScript 引擎会将其对应的执行上下文弹出执行栈，恢复之前的执行上下文，然后继续执行 `foo` 函数的剩余部分。

这个过程中，如果 `bar` 函数的调用是 `foo` 函数的最后一步，即 `foo` 函数没有其他的操作需要执行，那么就可以直接将 `bar` 函数的执行上下文替换掉 `foo` 函数的执行上下文，从而节省内存空间，这就是尾调用优化。

比如，我们可以将上面的 `foo` 函数改写成如下形式：

```javascript
function foo(x) {
  // 这里是函数的一些逻辑
  return bar(x);
}
```

这样一来，在执行 `foo` 函数时，JavaScript 引擎会直接将 `bar` 函数的执行上下文替换掉 `foo` 函数的执行上下文，从而避免了执行栈的不必要增长，提高了代码的性能。
