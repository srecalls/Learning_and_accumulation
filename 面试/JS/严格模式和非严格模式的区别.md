JavaScript的"严格模式"（strict mode）是2009年ECMAScript 5（ES5）引入的一个重要的特性。它的主要目的是帮助开发人员避免一些常见的错误。

以下是非严格模式和严格模式之间的一些主要差异：

1. 变量必须声明：在严格模式下，如果你尝试在声明变量之前使用它，JavaScript会抛出错误。在非严格模式下，如果你在声明变量之前使用它，JavaScript会自动为你创建一个全局变量。

2. `this`的值：在非严格模式下，当一个函数独立于任何对象上下文（比如，它不是一个对象的方法或构造函数）被调用时，`this`的值将是全局对象（在浏览器中为`window`）。而在严格模式下，`this`的值将是`undefined`。

3. 不允许重复的参数名称：在严格模式下，函数参数不能有重复的名称，否则JavaScript会抛出错误。非严格模式下不会有这种限制。

4. 不允许删除变量、函数或函数参数：在严格模式下，尝试删除变量、函数或函数参数将会抛出错误。在非严格模式下，这样的尝试将被忽略。

5. 对`eval()`的限制：在严格模式下，`eval()`的行为有一些限制。最重要的是，在`eval()`中创建的任何变量或函数都不能在`eval()`的外部代码中访问。

6. 八进制字面量：在严格模式下，八进制字面量（如 `0123`）是不允许的。

7. `with`语句：严格模式中禁止使用 `with` 语句，因为 `with` 语句在JavaScript中可能会引起一些混淆和问题。

开启严格模式的方法是在你的脚本的顶部添加这个字符串字面量：`"use strict";`。这个指令被 JavaScript 引擎识别，并且在该脚本或函数中启用严格模式。



当使用严格模式时，以下是每个差异的详细解释和示例：

## 1. 变量必须声明：
在严格模式下，如果你尝试在声明变量之前使用它，JavaScript会抛出错误。这有助于捕获并修复潜在的变量声明错误。

```javascript
"use strict";

console.log(x); // 抛出 ReferenceError: x is not defined 的错误
var x = 10;
```

在非严格模式下，如果你在声明变量之前使用它，JavaScript会自动为你创建一个全局变量。

```javascript
console.log(x); // 输出 undefined
var x = 10;
console.log(x); // 输出 10
```

## 2. `this`的值：
在非严格模式下，当一个函数独立于任何对象上下文被调用时，`this`的值将是全局对象（在浏览器中为`window`）。而在严格模式下，`this`的值将是`undefined`。这有助于避免意外的全局对象引用。

```javascript
"use strict";

function myFunction() {
  console.log(this);
}

myFunction(); // 输出 undefined
```

```javascript
function myFunction() {
  console.log(this);
}

myFunction(); // 输出全局对象（例如，在浏览器中为 window）
```

## 3. 不允许重复的参数名称：
在严格模式下，函数参数不能有重复的名称，否则JavaScript会抛出错误。这有助于防止函数参数之间的命名冲突。

```javascript
"use strict";

function myFunction(x, x) { // 重复的参数名称
  console.log(x);
}

myFunction(1, 2); // 抛出 SyntaxError: Duplicate parameter name not allowed in this context 的错误
```

在非严格模式下不会有这种限制。

```javascript
function myFunction(x, x) { // 重复的参数名称
  console.log(x);
}

myFunction(1, 2); // 输出 2
```

## 4. 不允许删除变量、函数或函数参数：
在严格模式下，尝试删除变量、函数或函数参数将会抛出错误。这有助于防止意外的删除操作。

```javascript
"use strict";

var x = 10;
delete x; // 抛出 TypeError: Cannot delete variable 'x' 的错误

function myFunction() {
  delete myFunction; // 抛出 TypeError: Cannot delete variable 'myFunction' 的错误
}
```

在非严格模式下，这样的尝试将被忽略。

```javascript
var x = 10;
delete x; // 不会引发错误，x 仍然存在

function myFunction() {
  delete myFunction; // 不会引发错误，myFunction 仍然存在
}
```

## 5. 对`eval()`的限制：
在严格模式下，`eval()`的行为有一些限制。最重要的是，在`eval()`中创建的任何变量或函数都不能在`eval()`的外部代码中访问。这有助于提高代码的可读性和安全性。

```javascript
"use strict";

eval("var x = 10;");
console.log(x); // 抛出 ReferenceError: x is not defined 的错误
```

在非严格模式下，通过`eval()`创建的变量或函数可以在`eval()`之后的代码中访问。

```javascript
eval("var x = 10;");
console.log(x); // 输出 10
```

## 6. 八进制字面量：
在严格模式下，八进制字面量（如 `0123`）是不允许的。这是为了避免与十进制数产生混淆。

```javascript
"use strict";

var x = 0123; // 抛出 SyntaxError: Octal literals are not allowed in strict mode.
```

在非严格模式下，八进制字面量是有效的。

```javascript
var x = 0123; // 八进制字面量
console.log(x); // 输出 83（十进制）
```

## 7. `with语句：
严格模式中禁止使用 `with` 语句，因为 `with` 语句在JavaScript中可能会引起一些混淆和问题。`with` 语句允许在代码块中创建一个临时的作用域，其中对象的属性可以直接访问，而无需显式引用对象。

```javascript
"use strict";

var obj = { x: 10 };

with (obj) { // 在严格模式下使用 with 语句将抛出 SyntaxError 的错误
  console.log(x); // 输出 10
}
```

在非严格模式下，`with` 语句是有效的。

```javascript
var obj = { x: 10 };

with (obj) {
  console.log(x); // 输出 10
}
```

请注意，严格模式对其他方面的JavaScript语义也有一些微妙的变化，但这些是主要的差异。启用严格模式可以帮助开发人员捕获潜在的错误，并使代码更加健壮和可靠。
