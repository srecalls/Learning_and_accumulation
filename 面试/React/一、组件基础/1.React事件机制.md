```js
<div onClick={this.handleClick.bind(this)}>点我</div>
```
React并不是**将click事件绑定到了div的真实DOM**( 顶层事件代理机制 )上，而是在**document**（React16是document、React17是root容器）处监听了所有的事件，当事件发生并且冒泡到document处的时候，React将事件内容封装并交由真正的处理函数运行。这样的方式不仅仅减少了内存的消耗，还能在组件挂在销毁时统一订阅和移除事件。

除此之外，冒泡到document上的事件也**不是原生的浏览器事件**，而是由react自己实现的**合成事件**( SyntheticEvent )。因此如果不想要是事件冒泡的话应该调用 **event.preventDefault()** 方法，而不是调用**event.stopPropagation()** 方法。（17以后发生变化, 直接调用 stopPropagation 即可）

JSX 上写的事件并没有绑定在对应的真实 DOM 上，而是通过事件代理的方式，将所有的事件都统一绑定在` document `  上。这样的方式不仅减少了内存消耗，还能在组件挂载销毁时**统一订阅和移除事件**。

另外冒泡到 ` document ` 上的事件也不是原生浏览器事件，而是 React 自己实现的合成事件(SyntheticEvent)。因此我们如果不想要事件冒泡的话，调用 ` event.stopPropagation ` 是无效的，而应该调用` event.preventDefault `

**实现合成事件的目的如下**:
- 合成事件首先抹平了浏览器之间的兼容问题，另外这是一个跨浏览器原生事件包装器，赋予了跨浏览器开发的能力 **( 合成事件和virtual dom，都具有跨平台作用 )**
- 对于**原生浏览器事件**来说，浏览器会给**监听器**创建一个**事件对象**。如果你有很多的事件监听，那么就需要分配很多的事件对象，造成高额的内存分配问题。但是对于合成事件来说，有一个**事件池**专门来**管理它们的创建和销毁**，当事件需要被使用时，就会从池子中**复用对象**，事件回调结束后，就会**销毁事件对象上的属性**从而便于下次**复用事件对象**。


当使用 JSX 编写事件时，React 会通过事件代理的方式将事件统一绑定在 `document` 上，而不是直接绑定在对应的真实 DOM 元素上。这种方式有以下几个好处：

1. **减少内存消耗**：将事件统一绑定在 `document` 上可以避免为每个元素都绑定事件处理程序，从而减少内存占用。

1. **统一订阅和移除事件**：通过在 `document` 上绑定事件，可以确保在组件挂载和销毁时统一订阅和移除事件，避免内存泄漏和其他潜在的问题。

需要注意的是，冒泡到 `document` 上的事件并不是原生浏览器事件，而是由 React 自己实现的合成事件（SyntheticEvent）。这些合成事件对象包含了与原生事件相似的属性和方法，但实际上是 React 根据浏览器事件模型自己实现的。

如果你想阻止事件冒泡，调用 `event.stopPropagation()` 是无效的，因为合成事件并不是真实的浏览器事件。相反，你应该调用 `event.preventDefault()` 来阻止默认行为的发生。

下面是一个示例，演示如何在 JSX 中使用事件处理程序：

```jsx
import React from 'react';

class MyComponent extends React.Component {
  handleClick = (event) => {
    event.preventDefault();
    console.log('Button clicked!');
  }

  render() {
    return (
      <button onClick={this.handleClick}>Click me</button>
    );
  }
}
```

在上面的例子中，我们在 `<button>` 元素上使用了 `onClick` 属性来指定点击事件的处理程序。当按钮被点击时，`handleClick` 方法会被调用，并且事件对象会作为参数传递给该方法。在 `handleClick` 方法内部，我们调用了 `event.preventDefault()` 来阻止默认行为（例如按钮的提交行为），并输出一条消息到控制台。

请注意，由于事件是通过事件代理的方式绑定在 `document` 上的，所以即使你在组件树中嵌套了多个组件，事件仍然会正确地冒泡到父组件或更高层级的组件。



React合成事件的设计目的可以通过以下两个例子来具体说明：

### 一、跨浏览器兼容性示例
假设你在原生JavaScript中需要实现点击事件：
```javascript
// 原生事件需要考虑浏览器差异（如IE的attachEvent）
if (element.addEventListener) {
  element.addEventListener('click', handler);
} else if (element.attachEvent) { // 旧版IE的特殊处理
  element.attachEvent('onclick', handler);
}
```
但在React中只需：
```jsx
<button onClick={handleClick}>按钮</button>
```
React内部会将所有事件统一挂载到document节点（见网页3），并通过事件委托机制自动处理浏览器差异。例如旧版IE的事件名`onclick`会被自动转换为标准`click`事件，开发者无需编写条件判断代码。

### 二、事件池内存优化示例
假设你有一个高频触发的点击事件：
```jsx
function handleClick(e) {
  // 若异步访问事件属性，需调用e.persist()保留对象
  setTimeout(() => {
    console.log(e.target); // 若不调用persist()，这里会得到null
  }, 100);
}
```
由于React的事件池机制，事件对象`e`在回调结束后会被重置属性（如`e.target`置为null）。当用户连续点击按钮时：
1. 第一次点击：从池中取出空闲的事件对象，填充当前点击数据
2. 点击回调结束后：清空该事件对象的属性（如`target`）
3. 第二次点击：直接复用同一个事件对象，避免重复创建新对象

这种机制使得1万次点击仅需创建约10个事件对象（根据池容量动态调整），相比原生事件减少99%的内存分配（见网页1的组件案例）。

### 对比总结
| 场景                | 原生事件                          | React合成事件                     |
|--------------------|---------------------------------|---------------------------------|
| 浏览器兼容处理         | 需手动判断浏览器类型                  | 自动统一为W3C标准事件模型               |
| 高频事件内存消耗        | 每次创建新事件对象（内存占用线性增长）       | 固定数量对象循环复用（内存占用恒定）           |
| 事件传播控制           | 需调用不同API（如stopPropagation）     | 统一使用`e.stopPropagation()`        |
| 事件对象访问           | 直接访问原生对象                    | 通过`e.nativeEvent`获取原生事件对象  |
