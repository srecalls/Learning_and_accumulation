## HTTP 1.0和 HTTP 1.1 有以下区别:
### 连接方面
- **连接方面**，http1.0 默认使用**非持久连接**，而 http1.1 默认使用持久连接.http1.1 通过使用持久连接来使多个 http 请求复用同一个 TCP 连接，以此来避免使用非持久连接时每次需要建立连接的**时延**。

### 资源请求方面
- **资源请求方面**，在 http1.0 中，存在一些浪费带宽的现象，例如客户端只是需要某个对象的一部分，而服务器却将整个对象送过来了，并且不支持断点续传功能，http1.1 则在请求头引入了 range 头域，它允许只请求资源的某个部分，即返回码是 206 (Partial Content)，这样就方便了开发者自由的选择以便于充分利用带宽和连接。

### 缓存方面
- **缓存方面**，在 http1.0 中主要使用 header 里的 `lf-Modified-Since`、`Expires`来做为缓存判断的标准，http1.1 则引入了更多的缓存控制策略，例如 `Etag`、`cache-control`、`lf-Unmodified-Since`、`lf-Match`、`If-None-Match` 等更多可供选择的缓存头来控制缓存策略。

### http1.1 新增了host字段
- http1.1 中**新增了 host 字段**，用来指定服务器的域名。http1.0 中认为每台服务器都绑定一个唯一的 IP 地址，因此，请求消息中的 URL 并没有传递主机名(hostname)。但随着虚拟主机技术的发展，在一台物理服务器上可以存在多个虚拟主机，并且它们共享一个IP地址。因此有了 host 字段，这样就可以将请求发往到同一台服务器上的不同网站。

假设有一台物理服务器的 IP 地址为 192.168.1.100，在一台物理服务器上运行着两个不同的网站，一个是 `www.example.com`，另一个是 `www.test.com`。假设它们的根目录分别是 `/var/www/example` 和 `/var/www/test`。

`www.example.com` 和 `www.test.com` 可以看作是两个不同的 Web 服务，它们分别运行在同一台物理主机上的两个虚拟主机中，并且共享同一个 IP 地址。

在 HTTP/1.0 中，浏览器发送请求时只需要指定资源的路径，例如 `/index.html`，不需要指定主机名。这样服务器无法区分请求是来自哪个网站的，因此会默认返回第一个匹配到的资源，或者返回错误。

在 HTTP/1.1 中，浏览器发送请求时需要在请求头中添加 `Host` 字段，例如：

```http
GET /index.html HTTP/1.1
Host: www.example.com
```

或者

```http
GET /index.html HTTP/1.1
Host: www.test.com
```

这样服务器就可以根据 `Host` 字段来区分请求是来自哪个网站的，从而返回相应的资源。例如，如果请求头中的 `Host` 字段为 `www.example.com`，那么服务器会在 `/var/www/example` 目录中查找对应的资源，如果为 `www.test.com`，则会在 `/var/www/test` 目录中查找对应的资源。这样就能保证不同的网站之间的资源不会相互冲突，从而实现了虚拟主机的功能。

### http1.1 新增了请求方法
- http1.1 相对于 http1.0 还新增了很多**请求方法**，如 PUT、HEAD、OPTIONS等。

HTTP/1.1 相较于 HTTP/1.0 新增了一些请求方法，包括 PUT、HEAD、OPTIONS 等等，下面是它们的作用介绍：

1. PUT：用于向指定资源上传更新内容，如果资源存在则更新，不存在则创建。通常用于更新或创建静态资源，例如上传图片、文本文件等。
2. HEAD：与 GET 方法类似，但是服务器不返回实际的资源内容，只返回请求头，用于获取资源的元数据信息，例如资源的大小、类型、修改时间等，可以用于检查资源是否存在或是否发生变化。
3. OPTIONS：用于获取目标资源所支持的通信选项，例如支持的请求方法、支持的编码方式、支持的语言等等，可以用于通信协议的协商和客户端与服务器之间的交互。
4. DELETE：用于删除指定的资源，通常用于删除静态资源，例如删除图片、文本文件等。
除此之外，HTTP/1.1 还新增了一些其他的请求方法，例如 PATCH 用于更新部分资源、TRACE 用于追踪请求-响应的传输路径等。这些方法的具体使用场景和作用各不相同，需要根据实际情况进行选择和使用。


##### 例子

以下是一些常见的使用场景和示例：

1. PUT：用于更新或创建静态资源，例如上传图片、文本文件等。例如一个博客网站使用 PUT 方法来更新或创建文章，用户可以通过 PUT 请求将文章内容上传到服务器上。

2. HEAD：用于获取资源的元数据信息，例如资源的大小、类型、修改时间等，可以用于检查资源是否存在或是否发生变化。例如浏览器在发送 GET 请求之前，可以先发送 HEAD 请求获取资源的元数据信息，以便根据资源的更新时间或大小等信息判断是否需要重新获取资源内容。

3. OPTIONS：用于获取目标资源所支持的通信选项，例如支持的请求方法、支持的编码方式、支持的语言等等，可以用于通信协议的协商和客户端与服务器之间的交互。例如浏览器在向服务器发送请求之前，可以先发送 OPTIONS 请求获取服务器支持的通信选项，以便根据服务器的响应来选择最合适的通信方式。

4. DELETE：用于删除静态资源，例如删除图片、文本文件等。例如一个云盘网站使用 DELETE 方法来删除用户上传的文件，用户可以通过 DELETE 请求删除指定的文件。
