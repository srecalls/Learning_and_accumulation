不完全正确。Chrome浏览器默认的持久连接数是6，这意味着在同一时间内，Chrome可以同时从同一域名下最多建立6个持久连接。

然而，将JavaScript文件添加为`<script>`标签的`async`属性并不会增加浏览器的持久连接数。`async`属性指示浏览器在下载和执行JavaScript文件时，不会阻塞HTML解析和其他资源的加载，但并不会影响浏览器的持久连接数。

当浏览器解析HTML文档时，它会按照顺序逐个加载`<script>`标签中的JavaScript文件，无论是否使用了`async`属性。如果你在HTML中有6个带有`async`属性的`<script>`标签，浏览器仍然会按照顺序加载这些文件，并且可能会同时下载多个文件，但并不会超过浏览器的持久连接数限制。

要同时获取多个JavaScript文件，你可以使用以下方法：

1. 合并文件：将多个JavaScript文件合并为一个文件，然后在单个`<script>`标签中引用合并后的文件。这样可以减少HTTP请求的数量，提高加载性能。

2. 使用模块加载器：使用模块加载器（例如RequireJS、Webpack、Parcel等）来管理模块依赖关系和并行加载。模块加载器可以根据依赖关系并行加载多个模块，从而提高加载效率。

3. 使用服务器推送（Server Push）：如果你的服务器支持HTTP/2协议，你可以使用服务器推送功能，将多个JavaScript文件一次性推送到客户端，从而避免多次请求。

综上所述，`async`属性的使用不会直接影响浏览器的持久连接数。要同时获取多个JavaScript文件，需要考虑其他优化策略，如合并文件、使用模块加载器或服务器推送等。

如果在HTML中不加 `async` 属性的 `<script>` 标签，浏览器在加载这些文件时会使用一个持久连接。也就是说，每个不带 `async` 属性的 `<script>` 标签会占用一个持久连接，直到该文件下载完成并执行完毕。

根据浏览器的默认行为，Chrome 浏览器在同一时间内可以建立最多6个持久连接到同一域名下的资源。这意味着，如果你在 HTML 中有多个不带 `async` 属性的 `<script>` 标签，浏览器会按顺序加载这些文件，并且每个文件会使用一个持久连接。当达到持久连接的上限（默认为6）时，浏览器会等待其中一个连接释放后再建立新的连接。

需要注意的是，持久连接数可能会受到服务器配置、浏览器版本以及其他因素的影响。某些浏览器可能会对持久连接数进行优化或调整，以提高性能或安全性。

综上所述，如果不加 `async` 属性的 `<script>` 标签，浏览器默认情况下会使用一个持久连接来加载每个文件，而持久连接的最大数量可能受到浏览器和服务器的配置限制。
