
HPACK 是 HTTP/2 中定义的一种压缩算法，用于压缩 HTTP/2 协议中的请求和响应头部，从而减少协议头部的传输大小，提高传输效率。HPACK 的核心思想是使用一个静态表和一个动态表来存储常用的头部字段，同时使用 Huffman 编码来压缩字符串，从而达到高效压缩的目的。

HPACK 算法的原理如下：

1. 静态表和动态表

HPACK 使用一个静态表和一个动态表来存储常用的头部字段。静态表包含了一些常用的头部字段，例如请求方法、状态码等，这些字段是预先定义好的，不会被修改。动态表则是在通信过程中动态生成的，用于存储一些不在静态表中的头部字段。

2. Huffman 编码

HPACK 使用 Huffman 编码来压缩字符串，从而减小传输的大小。Huffman 编码是一种变长编码，可以将高频出现的字符用短编码表示，低频字符用长编码表示，从而达到压缩的目的。

3. 压缩过程

HPACK 压缩头部字段的过程如下：

- 首先，将头部字段分为静态头部字段、动态头部字段和字面量头部字段三种类型。
- 对于静态头部字段，直接使用静态表中的索引值表示该字段。
- 对于动态头部字段，首先在动态表中查找该字段，如果找到则使用动态表中的索引值表示该字段，否则将该字段添加到动态表中，并使用动态表中的索引值表示该字段。
- 对于字面量头部字段，分为无索引、增量索引和静态索引三种类型。无索引表示该字段不会被存储到静态表或动态表中，增量索引表示该字段会被存储到动态表中，静态索引表示该字段会被存储到静态表中。
- 对于所有的头部字段，使用 Huffman 编码来压缩字符串，从而减小传输的大小。

4. 解压过程

HPACK 解压头部字段的过程与压缩过程相反，具体如下：

- 首先，根据索引值查找静态表或动态表中对应的头部字段。
- 如果索引值为零，表示该字段为字面量头部字段，需要根据类型来判断该字段是否需要被存储到静态表或动态表中。
- 如果索引值不为零，表示该字段为静态头部字段或动态头部字段，需要直接使用静态表或动态表中的字段来表示该字段。
- 对于所有的头部字段，使用 Huffman 解码来恢复原始的字符串。

通过使用静态表、动态表和 Huffman 编码，HPACK 算法可以将 HTTP/2 协议中的请求和响应头部进行高效压缩，从而减小传输的大小，提高传输效率。


##### huffman编码
假设我们要对字符串"hello world"进行 Huffman 编码压缩，以下是压缩过程的示例：

首先，我们需要构建 Huffman 树，以便进行编码。Huffman 树是一种特殊的二叉树，它的叶子节点对应于输入字符串中的字符，而非叶子节点则对应于合并的字符。

下面是构建 Huffman 树的步骤：

1. 统计字符串中每个字符出现的次数，然后将它们作为叶子节点插入到一个优先队列中，其中优先级为字符出现的次数。

2. 从优先队列中取出两个具有最小优先级的节点，并将它们合并成一个新的节点。新节点的优先级为两个节点的优先级之和，并且新节点的左右子节点分别是原来被合并的两个节点。

3. 将新节点插入到优先队列中。

4. 重复步骤 2 和 3，直到优先队列中只剩下一个节点，这个节点就是 Huffman 树的根节点。

下面是 "hello world" 的字符出现次数统计结果：

| 字符 | 出现次数 |
|------|----------|
|  h   |     1    |
|  e   |     1    |
|  l   |     3    |
|  o   |     2    |
|  w   |     1    |
|  r   |     1    |
|  d   |     1    |

接下来，我们按照上述步骤构建 Huffman 树。首先将字符及其出现次数插入到优先队列中：

|    节点   | 优先级 |
|-----------|--------|
| 'h'(1)    |     1  |
| 'e'(1)    |     1  |
| 'w'(1)    |     1  |
| 'r'(1)    |     1  |
| 'd'(1)    |     1  |
| 'o'(2)    |     2  |
| 'l'(3)    |     3  |

然后，我们依次从优先队列中取出两个优先级最小的节点，并合并它们，直到只剩下一个节点：

|    节点   | 优先级 |
|-----------|--------|
| 'h'(1)    |     1  |
| 'e'(1)    |     1  |
| 'w'(1)    |     1  |
| 'r'(1)    |     1  |
| 'd'(1)    |     1  |
| 'o'(2)    |     2  |
| 'l'(3)    |     3  |
| 'o,d'(3)  |     3  |
| 'r,w'(2)  |     2  |
| 'o,d,l,r,w,e,h'(6) | 6 |

最后，我们得到了如下的 Huffman 树：

```
            6
           / \
          /   \
         /     \
        3       3
       / \     / \
      1   2   1   2
     / \ / \ / \ / \
    h  e o d l r w
```

从根节点开始，向左走表示编码为 0，向右走表示编码为 1。因此，'h' 的编码为 000，'e' 的编码为 001，'o' 的编码为 01，'d' 的编码为 100，'l' 的编码为 101，'r' 的编码为 110，'w' 的编码为 1110。

将编码后的字符串连接起来，得到压缩后的结果为：

```
1010010111111100010101111001101001111000
```

这个压缩后的结果可以看出大大减少了原字符串的长度。

根据以上编码表，可以将原始字符串"hello world"进行 Huffman 编码压缩，压缩后的结果为"11001101000011110111100010010"。可以发现，压缩后的字符串比原始字符串短了许多，这是因为 Huffman 编码使用变长编码来表示字符，将高频出现的字符用短编码表示，低频字符用长编码表示，从而达到压缩的目的。
