HTTP/2.0 的多路复用（Multiplexing）是一种新的流量控制机制，可以让客户端与服务器之间的多个请求和响应之间在同一个 TCP 连接上进行并发交错传输，以提高网络传输效率。

在 HTTP/1.x 中，每个 HTTP 请求都需要建立一个独立的 TCP 连接，这种方式会导致以下问题：

1. 连接数量受限：每个浏览器都有一定的连接数限制，如果需要请求的资源过多，就会出现连接数不足的情况，导致请求被阻塞。

2. 队头阻塞：每个请求必须按照顺序依次发送和接收，如果前面的请求因为某些原因被延迟，那么后面的请求也需要等待，会造成队头阻塞。

而 HTTP/2.0 的多路复用机制可以解决上述问题，其主要优点如下：

1. 单一连接：HTTP/2.0 采用多路复用机制，所有请求和响应都在同一个 TCP 连接上进行，而不需要像 HTTP/1.x 那样为每个请求建立单独的连接，这可以减少连接数，降低服务器压力。

2. 并发交错：HTTP/2.0 允许多个请求和响应同时传输，每个请求和响应都会被拆分成一个或多个数据帧，这些数据帧可以交错传输，避免了队头阻塞的问题，提高了资源利用率。

3. 流量控制：HTTP/2.0 可以对每个流进行流量控制，防止某个流占用过多的带宽，导致其他流的传输速度变慢。同时，HTTP/2.0 还支持优先级设置，可以优先处理一些重要的请求和响应。

总之，HTTP/2.0 的多路复用机制可以提高网络传输效率，减少资源浪费，改善用户体验。


对于 HTTP/2.0 中的多路复用机制，虽然每个请求和响应都会被拆分成一个或多个数据帧进行传输，但这些数据帧并不会阻塞。

这是因为在 HTTP/2.0 中，每个数据帧都有一个对应的流（Stream）标识符，一个流可以包含多个数据帧，而不同的流之间是可以并发传输的。由于每个数据帧都有对应的流标识符，因此可以灵活地对不同的流进行流量控制，防止某个流占用过多的带宽，导致其他流的传输速度变慢。

此外，在 HTTP/2.0 中，还有一个流控制（Flow Control）机制，用于控制每个流可以发送和接收的数据量，以防止接收方处理不过来而导致数据阻塞。流控制的机制是通过设置窗口大小（Window Size）来实现的，发送方会根据接收方发送过来的窗口大小来控制发送的数据量，从而避免了数据阻塞的问题。

因此，HTTP/2.0 的多路复用机制通过使用流和流控制机制，可以实现数据的并发传输，避免了数据阻塞的问题，从而提高了网络传输效率。

## 同一个TCP链接，怎么并发传输？
在 HTTP/2.0 中，通过多路复用（Multiplexing）机制可以在同一个 TCP 连接上实现并发传输。具体来说，多路复用机制可以将一个 TCP 连接分成多个虚拟的流（Stream），每个流可以承载一个或多个 HTTP 请求和响应，并且这些流之间可以并发传输。

在 HTTP/2.0 中，每个流都有一个唯一的标识符（Stream Identifier），这个标识符用于区分不同的流，并且在传输过程中，每个流都被拆分成一个或多个数据帧（Data Frame）。这些数据帧可以交错传输，以实现多个流之间的并发传输。

具体来说，在 HTTP/2.0 中，客户端和服务器之间的通信流程如下：

1. 客户端与服务器建立 TCP 连接，并发送 SETTINGS 帧，用于协商一些参数，如最大帧大小、流量控制等。

2. 客户端和服务器可以同时发送和接收多个流，每个流都有一个唯一的标识符。客户端可以通过一个流发送一个或多个 HTTP 请求，服务器可以通过一个流发送一个或多个 HTTP 响应。

3. 每个流都被拆分成一个或多个数据帧进行传输，这些数据帧可以交错传输，以实现多个流之间的并发传输。每个数据帧都有一个对应的流标识符，以便接收方将数据帧重新组装成完整的流。

4. 流控制机制可以控制每个流可以发送和接收的数据量，以防止接收方处理不过来而导致数据阻塞。这个机制是通过设置窗口大小来实现的，发送方会根据接收方发送过来的窗口大小来控制发送的数据量，从而避免了数据阻塞的问题。

总之，HTTP/2.0 中的多路复用机制可以在同一个 TCP 连接上实现并发传输，提高了网络传输效率。
