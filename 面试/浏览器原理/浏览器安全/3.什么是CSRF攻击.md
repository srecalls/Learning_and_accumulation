## CSRF
### （1）概念
CSRF攻击指的是**跨站请求伪造攻击**，攻击者诱导用户进入一个第三方网站，然后该网站向被攻击网站发送跨站请求。如果用户在被攻击网站中保存了登录状态，那么攻击者就可以利用这个登录状态，绕过后台的用户验证，冒充用户向服务器执行一些操作。

CSRF 攻击的**本质是利用cookie 会在同源请求中携带发送给服务器的特点，以此来实现用户的冒充。**

### （2）攻击类型
常见的CSRF攻击有三种:
- GET类型的CSRF 攻击，比如在网站中的一个img标签里构建一个请求，当用户打开这个网站的时候就会自动发起提交。
- POST类型的CSRF 攻击，比如构建一个表单，然后隐藏它，当用户进入页面时，自动提交这个表单。
- 链接类型的CSRF 攻击，比如在a标签的 href属性里构建一个请求，然后诱导用户去点击。

举个简单的 CSRF 攻击例子：

假设有一个银行网站，它有一个转账功能，用户需要在页面中输入收款人姓名和转账金额，并点击“提交”按钮来完成转账操作。这个网站的后台会检查用户是否已经登录，如果已经登录，就会根据用户的身份信息来执行转账操作。

攻击者在另一个网站上构造一个页面，其中包含一个隐藏的表单，表单中包含了银行网站的转账功能的地址和参数，以及攻击者指定的收款人姓名和金额等信息。然后，攻击者通过诱导用户点击某个链接或者自动提交的方式，让用户访问这个构造好的页面。当用户访问这个页面时，浏览器会自动向银行网站发送一个转账请求，由于用户在银行网站中的登录状态仍然有效，所以银行网站会认为这个请求是合法的，执行了转账操作。这样，攻击者就成功地冒充了用户，完成了一次 CSRF 攻击。

为了防止这种攻击，银行网站可以在转账功能中添加一个随机的 token 值，每次转账时都会生成一个新的 token 值，并将它添加到表单中。当用户提交表单时，银行网站会检查这个 token 值的有效性，如果无效，就拒绝这个请求。这样，即使攻击者构造了一个包含银行网站转账地址和参数的表单，也无法生成有效的 token 值，从而无法完成 CSRF 攻击。
