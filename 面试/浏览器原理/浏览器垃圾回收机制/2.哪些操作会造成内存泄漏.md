## 1. 由于使用未声明的变量，而意外的创建了一个全局变量，使其一直留在内存中无法被回收。

```javascript
function foo() {
  bar = "hello"; // 意外地创建了一个全局变量bar
}
foo();
```
在这个例子中，由于 `bar` 变量没有被声明，它会被自动创建为一个全局变量。即使 `foo()` 函数执行完毕后，由于 `bar` 变量是全局变量，它仍然会一直存在于内存中，直到程序结束或手动删除它。

## 1. 未声明的变量意外创建了全局变量：

```javascript
function foo() {
  bar = 'hello'; // 未声明变量，创建了全局变量 bar
}

foo();
console.log(bar); // 'hello'
bar = null // 取消引用从而回收
```

在上面的代码中，`foo` 函数中使用了未声明的变量 `bar`，这样就会创建一个全局变量 `bar`，并赋值为 `'hello'`。这个变量会一直存在于内存中，无法被回收。

## 1. 使用未声明的变量

```javascript
function foo() {
  bar = "hello"; // 未声明的变量，会创建全局变量 bar
}

foo();
```

在上述代码中，由于在函数 `foo` 中使用了未声明的变量 `bar`，JavaScript 会将其当作全局变量来处理，因此会创建一个全局变量 `bar`，并将其赋值为字符串 "hello"。当函数执行完毕后，变量 `bar` 仍然存在于全局作用域中，导致它所占用的内存无法被回收，从而出现内存泄漏的情况。

要避免这种情况，我们应该在使用变量之前先声明它们，以避免意外创建全局变量。

```javascript
function foo() {
  let bar = "hello"; // 声明并赋值变量
}

foo();
```

## 2. 设置了 `setInterval` 定时器，而忘记取消它，导致循环函数有对外部变量的引用留在内存中无法被回收。

```javascript
function foo() {
  let count = 0;
  setInterval(() => {
    console.log(count);
    count++;
  }, 1000);
}
foo();
```

在这个例子中，我们设置了一个定时器来每秒钟输出 `count` 变量的值。由于 `count` 变量是在 `foo()` 函数中定义的，但是由于定时器的回调函数对 `count` 变量有引用，所以 `count` 变量会一直存在于内存中，即使 `foo()` 函数执行完毕后也是如此。

为了避免这种情况，我们应该在不需要定时器时及时清除它，例如：

```javascript
function foo() {
  let count = 0;
  let timer = setInterval(() => {
    console.log(count);
    count++;
    if (count > 10) {
      clearInterval(timer); // 在 count 大于 10 后清除定时器
    }
  }, 1000);
}
foo();
clearInterval(timer); // 取消定时器 从而取消count引用
```

## 3. 获取一个 `DOM` 元素的引用，而后面这个元素被删除，由于我们一直保留了对这个元素的引用，所以它也无法被回收。

```html
<div id="myDiv"></div>
```

```javascript
let myDiv = document.getElementById("myDiv");
myDiv.remove(); // 删除 myDiv 元素
console.log(myDiv) // <div id="myDiv"></div>
```

在这个例子中，我们获取了 `id` 为 `myDiv` 的 `DOM` 元素的引用，然后删除了这个元素。由于我们仍然保留对这个元素的引用，即 `myDiv` 变量，所以这个元素不会被回收。

为了避免这种情况，我们应该在删除元素后及时清除对它的引用，例如：

```javascript
let myDiv = document.getElementById("myDiv");
myDiv.remove();
myDiv = null; // 清除对 myDiv 元素的引用
```

## 3. 引用被删除的 DOM 元素


```javascript
let div = document.getElementById("myDiv"); // 获取 DOM 元素的引用
```

在上述代码中，我们先获取了一个 `div` 元素的引用，然后将其从 DOM 树中删除。然而，由于我们仍然持有对 `div` 元素的引用，它无法被回收，从而出现内存泄漏的情况。

要避免这种情况，我们应该在不需要使用 DOM 元素时及时释放对它们的引用，例如将变量赋值为 `null`。

```javascript
let div = document.getElementById("myDiv"); // 获取 DOM 元素的引用

// 删除 DOM 元素
let parent = div.parentNode;
parent.removeChild(div);

div = null; // 及时释放对 DOM 元素的引用
```

## 4. 不合理的使用闭包，从而导致某些变量一直被留在内存当中。

```javascript
function foo() {
  let count = 0;
  setInterval(() => {
    console.log(count);
    count++;
  }, 1000);
  return function() {
    console.log("Hello");
  };
}
let bar = foo();
bar();
```

在这个例子中，我们定义了一个闭包函数 `foo()`，它返回另一个函数，即 `bar` 变量。由于 `bar` 变量是闭包函数 `foo()` 的返回值，它保留了对 `foo()` 函数中变量 `count` 的引用。因此，即使 `foo()` 函数执行完毕后，由于 `bar` 变量仍然存在，变量 `count` 也会一直存在于内存中。

为了避免这种情况，我们应该避免在闭包函数中保留对不必要变量的引用，或者在不需要时及时清除对它们的引用。例如，在上面的例子中，我们可以将 `bar` 变量设为 `null`，以清除对 `count` 变量的引用：

```javascript
function foo() {
  let count = 0;
  setInterval(() => {
    console.log(count);
    count++;
  }, 1000);
  return function() {
    console.log("Hello");
  };
}
let bar = foo();
bar();
bar = null; // 清除对 count 变量的引用
```

## 4. 不合理的使用闭包

```javascript
function foo() {
  let count = 0;
  setInterval(function() {
    console.log(++count);
  }, 1000);
}

foo();
```

在上述代码中，我们定义了一个函数 `foo`，其中设置了一个定时器，每隔一秒钟就会输出一个数字。由于定时器的回调函数中使用了闭包，它持有对变量 `count` 的引用，导致这个变量无法被回收。因此，每次定时器回调函数执行时，都会创建一个新的执行上下文，并在其中创建一个新的变量 `count`，导致内存泄漏的情况。

要避免这种情况，我们应该合理地使用闭包，尽量避免在闭包中持有对外部变量的引用，或者在不需要使用闭包时及时释放对其的引用。例如，可以使用立即执行函数来创建一个新的作用域，从而避免在闭包中持有对外部变量的引用。

```javascript
function foo() {
  (function() {
    let count = 0;
    setInterval(function() {
      console.log(++count);
    }, 1000);
  })();
}

foo();
```

在上述代码中，我们将定时器的回调函数放在一个立即执行函数中，这样它就不会持有对外部变量的引用，从而避免了内存泄漏的情况。
