## （1）Cookie
Cookie是最早被提出来的本地存储方式，在此之前，服务端是无法判断网络中的两个请求是否是同一用户发起的，为解决这个问题，Cookie就出现了。Cookie的大小只有4kb，它是一种纯文本文件，每次发起HTTP请求都会携带Cookie。

Cookie的特性:

	- Cookie一旦创建成功，名称就无法修改
	- Cookie是无法跨域名的，也就是说a域名和b域名下的cookie是无法共享的，这也是由Cookie的隐私安全性决定的，这样就能够阻止非法获取其他网站的Cookie
	 - 每个域名下Cookie的数量不能超过20个，每个Cookie的大小不能超过4kb
	- 有安全问题，如果Cookie被拦截了，那就可获得session的所有信息，即使加密也于事无补，无需知道cookie的意义，只要转发cookie就能达到目的
	- Cookie在请求一个新的页面的时候都会被发送过去

如果需要域名之间跨域共享Cookie，有两种方法:

	1.使用Nginx反向代理
	2.在一个站点登陆之后，往其他网站写Cookie。服务端的Session存储到一个节点，Cookie存储sessionld


Cookie的使用场景:

	- 最常见的使用场景就是Cookie和session结合使用，我们将sessionId存储到Cookie中，每次发请求都会携带这个sessionId，这样服务端就知道是谁发起的请求，从而响应相应的信息。
	- 可以用来统计页面的点击次数

#### 使用场景例子
好的，以下是使用JavaScript实现上述两种场景的示例代码：

1. 使用Cookie和session实现身份验证

```javascript
// 发送登录请求
function login(username, password) {
  // 发送POST请求
  fetch('/login', {
    method: 'POST',
    body: JSON.stringify({ username: username, password: password }),
    headers: { 'Content-Type': 'application/json' }
  })
  .then(response => {
    if (response.ok) {
      // 从响应中获取sessionId，并存储到Cookie中
      const sessionId = response.headers.get('sessionId');
      document.cookie = `sessionId=${sessionId}`;
      // 跳转到主页
      window.location.href = '/home';
    } else {
      // 登录失败
      alert('Login failed!');
    }
  });
}

// 发送带有sessionId的请求
function sendRequest(url, options) {
  // 从Cookie中获取sessionId
  const sessionId = document.cookie.replace(/(?:(?:^|.*;\s*)sessionId\s*\=\s*([^;]*).*$)|^.*$/, "$1");
  if (sessionId) {
    // 添加sessionId到请求头部
    options.headers = Object.assign(options.headers || {}, { 'sessionId': sessionId });
  }
  // 发送请求
  return fetch(url, options);
}
```

在上面的代码中，login函数会发送登录请求，将用户名和密码以JSON格式发送到服务端。如果登录成功，服务端会生成一个sessionId，并将其存储到session中，并将sessionId作为响应头部的sessionId字段返回给客户端。客户端收到响应后，将sessionId存储到Cookie中。

sendRequest函数可以在发送请求时携带sessionId，并将sessionId添加到请求头部。这样，服务端就可以根据sessionId来查找与该用户相关的信息。

2. 使用Cookie统计页面的点击次数

```javascript
// 获取点击次数
function getClickCount() {
  // 从Cookie中获取点击次数
  const clickCount = parseInt(document.cookie.replace(/(?:(?:^|.*;\s*)clickCount\s*\=\s*([^;]*).*$)|^.*$/, "$1")) || 0;
  return clickCount;
}

// 增加点击次数
function incrementClickCount() {
  // 获取当前点击次数
  const clickCount = getClickCount();
  // 将点击次数加1，并存储到Cookie中
  document.cookie = `clickCount=${clickCount + 1}`;
}

// 绑定点击事件
const button = document.querySelector('button');
button.addEventListener('click', () => {
  incrementClickCount();
  alert(`Clicked ${getClickCount()} times!`);
});
```

在上面的代码中，getClickCount函数会从Cookie中获取点击次数，如果Cookie中不存在clickCount字段，则默认点击次数为0。incrementClickCount函数会将点击次数加1，并将新的点击次数存储到Cookie中。每次点击按钮时，会调用incrementClickCount函数来增加点击次数，并弹出一个包含当前点击次数的提示框。

## （2）LocalStorage
LocalStorage是HTML5新引入的特性，由于有的时候我们存储的信息较大，Cookie就不能满足我们的需求，这时候LocalStorage就派上用场了。

LocalStorage的优点:

	- 在大小方面，LocalStorage的大小一般为5MB，可以储存更多的信息
	- LocalStorage是持久储存，并不会随着页面的关闭而消失，!除非主动清理，不然会永久存在。
	- 仅储存在本地，不像Cookie那样每次HTTP请求都会被携带

LocalStorage的缺点:

	- 存在浏览器兼容问题，IE8以下版本的浏览器不支持
	- 如果浏览器设置为隐私模式，那我们将无法读取到LocalStorage
	- LocalStorage受到同源策略的限制，即端口、协议、主机地址有任何一个不相同，都不会访问

LocalStorage的常用API
```js
// 保存数据到 localStorage
localStorage.setItem('key', 'value')

// 从 localStorage 获取数据
let data = localStorage.getItem('key')

// 从 localStorage 删除保存到数据
localStorage.removeItem('key')

// 从 localStorage 删除所有保存到数据
localStorage.clear()

// 获取某个索引的key
localStorage.key(index)
```

LocalStorage的使用场景:

	- 有些网站有换肤的功能，这时候就可以将换肤的信息存储在本地的LocalStorage中，当需要换肤的时候，直接操作LocalStorage即可
	- 在网站中的用户浏览信息也会存储在LocalStorage中，还有网站的一些不常变动的个人信息等也可以存储在本地的LocalStorage中

#### 使用场景例子
好的，以下是一个换肤功能的例子：

假设我们有一个网站，希望提供多个主题供用户选择。可以通过使用LocalStorage来存储当前主题，并在需要时更新页面样式。

首先，在页面加载时，我们需要检查LocalStorage中是否存在主题设置，如果存在，则加载该主题，否则默认加载一个主题。可以使用以下代码来实现：

```javascript
// 获取当前主题
function getCurrentTheme() {
  return localStorage.getItem('theme') || 'default';
}

// 设置当前主题
function setCurrentTheme(theme) {
  localStorage.setItem('theme', theme);
  updatePageStyle();
}

// 更新页面样式
function updatePageStyle() {
  const theme = getCurrentTheme();
  if (theme === 'default') {
    document.body.style.backgroundColor = '#ffffff';
    document.body.style.color = '#000000';
  } else if (theme === 'dark') {
    document.body.style.backgroundColor = '#000000';
    document.body.style.color = '#ffffff';
  }
}

// 检查LocalStorage中是否存在主题设置
if (localStorage.getItem('theme')) {
  updatePageStyle();
}
```

然后，我们可以在页面中添加一个切换主题的按钮，并绑定一个点击事件。在点击按钮时，我们可以调用setCurrentTheme函数来切换当前主题。例如，以下代码实现了切换主题的功能：

```javascript
// 获取切换主题的按钮
const button = document.querySelector('button');

// 绑定点击事件
button.addEventListener('click', () => {
  const theme = getCurrentTheme() === 'default' ? 'dark' : 'default';
  setCurrentTheme(theme);
});
```

在上面的代码中，我们使用getCurrentTheme函数获取当前主题，然后根据当前主题来切换到另一个主题。切换主题后，我们调用setCurrentTheme函数来更新LocalStorage中的主题设置，并更新页面样式。

通过使用LocalStorage，我们可以实现各种各样的功能，例如保存用户偏好设置、缓存数据、记录浏览历史等。需要注意的是，LocalStorage中存储的数据只能被同一域名下的页面访问，不同域名之间无法共享LocalStorage中的数据。

## （3）SessionStorage

SessionStorage和LocalStorage都是在HTML5才提出来的存储方案，SessionStorage 主要用于临时保存同一窗口(或标签页)的数据，刷新页面时不会删除，关闭窗口或标签页之后将会删除这些数据。


SessionStorage与LocalStorage对比:

	- SessionStorage和LocalStorage都在本地进行数据存储:
	- SessionStorage也有同源策略的限制，但是SessionStorage有一条更加严格的限制，SessionStorage只有在同一浏览器的同一窗口下才能够共享;

	这句话的意思是，与LocalStorage类似，SessionStorage也受到同源策略的限制，只有在同一域名、同一端口、同一协议下的页面才能够共享SessionStorage中的数据。但是，与LocalStorage不同的是，SessionStorage中的数据只有在同一浏览器的同一窗口下才能够共享。
	换句话说，如果在同一浏览器的不同窗口或不同标签页中打开同一域名下的页面，它们之间的SessionStorage是相互独立的，无法共享SessionStorage中的数据。这是因为每个窗口或标签页都有自己独立的会话上下文，它们之间的会话状态是相互隔离的。

	- LocalStorage和SessionStorage都不能被爬虫爬取;

SessionStorage的常用API
```js
// 保存数据到 sessionStorage
sessionStorage.setItem('key', 'value')

// 从 sessionStorage 获取数据
let data = sessionStorage.getItem('key')

// 从 sessionStorage 删除保存到数据
sessionStorage.removeItem('key')

// 从 sessionStorage 删除所有保存到数据
sessionStorage.clear()

// 获取某个索引的key
sessionStorage.key(index)
```

SessionStorage的使用场景

	由于SessionStorage具有时效性，所以可以用来存储一些网站的游客登录的信息，还有临时的浏览记录的信息。当关闭网站之后，这些信息也就随之消除了。重点在游客

#### 使用场景例子
好的，以下是一个使用SessionStorage存储游客登录信息和浏览记录的例子：

假设我们有一个博客网站，允许游客在不登录的情况下浏览文章，并提供一个“收藏”按钮，让游客可以将自己喜欢的文章加入收藏列表。由于游客没有登录账号，我们需要使用SessionStorage来存储他们的收藏记录。

首先，我们可以在页面加载时检查SessionStorage中是否存在收藏列表，如果存在，则加载收藏列表。如果不存在，则创建一个新的收藏列表。可以使用以下代码来实现：

```javascript
// 获取收藏列表
function getFavorites() {
  return JSON.parse(sessionStorage.getItem('favorites') || '[]');
}

// 添加文章到收藏列表
function addFavorite(articleId) {
  const favorites = getFavorites();
  if (!favorites.includes(articleId)) {
    favorites.push(articleId);
    sessionStorage.setItem('favorites', JSON.stringify(favorites));
  }
}

// 绑定收藏按钮点击事件
const favoriteButton = document.querySelector('.favorite-button');
favoriteButton.addEventListener('click', () => {
  const articleId = favoriteButton.dataset.articleId;
  addFavorite(articleId);
});
```

在上面的代码中，getFavorites函数会从SessionStorage中获取收藏列表，如果SessionStorage中不存在收藏列表，则返回一个空数组。addFavorite函数会将指定的文章ID添加到收藏列表中，并将收藏列表存储到SessionStorage中。

然后，我们可以在页面中显示收藏列表，并提供一个清空收藏列表的按钮。例如，以下代码可以显示收藏列表：

```javascript
// 获取显示收藏列表的元素
const favoritesList = document.querySelector('.favorites-list');

// 显示收藏列表
function showFavorites() {
  const favorites = getFavorites();
  favoritesList.innerHTML = '';
  for (const articleId of favorites) {
    const article = getArticleById(articleId);
    if (article) {
      const articleElement = createArticleElement(article);
      favoritesList.appendChild(articleElement);
    }
  }
}

showFavorites();
```

在上面的代码中，我们使用getFavorites函数获取收藏列表，然后遍历收藏列表中的文章ID，使用getArticleById函数获取每篇文章的详细信息，然后使用createArticleElement函数创建文章元素，并将其添加到收藏列表中。

通过使用SessionStorage，我们可以在游客访问网站时提供收藏功能，并在游客关闭网站后自动清除收藏记录。
