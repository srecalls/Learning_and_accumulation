## Cookie由以下字段组成
##### Name
	- Name: cookie的名称

##### Value
	- Value: cookie的值，对于认证cookie，value值包括web服务器所提供的访问令牌;

##### Size
	- Size:cookie的大小

##### Path
	- Path: 可以访问此cookie的页面路径。比如domain是abc.com，path是|/test)，那么只有 /test 路径下的页面可以读取此cookie。

##### Secure
	- Secure: 指定是否使用HTTPS安全协议发送Cookie。使用HTTPS安全协议，可以保护Cookie在浏览器和Web服务器间的传输过程中不被窃取和篡改。该方法也可用于Web站点的身份鉴别，即在HTTPS的连接建立阶段，浏览器会检查Web网站的SSL证书的有效性。但是基于兼容性的原因 (比如有些网站使用自签署的证书)在检测到SSL证书无效时，浏览器并不会立即终止用户的连接请求，而是显示安全风险信息，用户仍可以选择继续访问该站点。

##### Domain
	- Domain: 可以访问该cookie的域名，Cookie 机制并未遵循严格的同源策略，允许一个子域可以设置或获取其父域的 Cookie。当需要实现单点登录方案时，Cookie 的上述特性非常有用，然而也增加了 Cookie受攻击的危险，比如攻击者可以借此发动会话定置攻击因而，浏览器禁止在 Domain 属性中设置.org、.com 等通用顶级域名、以及在国家及地区顶级域下注册的二级域名，以减小攻击发生的范围。

##### HTTP
	- HTTP: 该字段包含 HTTPOnly 属性 ，该属性用来设置cookie能否通过脚本来访问，默认为空，即可以通过脚本访问。在客户端是不能通过js代码去设置一个httpOnly类型的cookie的，这种类型的cookie只能通过服务端来设置。该属性用于防止客户端脚本通过 document.cookie 属性访问Cookie，有助于保护Cookie不被跨站脚本攻击窃取或篡改。但是，HTTPOnly的应用仍存在局限性，一些浏览器可以阻止客户端脚本对Cookie的读操作，但允许写操作;此外大多数浏览器仍允许通过XMLHTTP对象读取HTTP响应中的Set-Cookie头。

##### Expires/Max-size
	- Expires/Max-size : 此cookie的超时时间。若设置其值为一个时间，那么当到达此时间后，此cookie失效。不设置的话默认值是Session，意思是cookie会和session一起失效。当浏览器关闭(不是浏览器标签页，而是整个浏览器)后，此cookie失效。

## 总结:

	服务器端可以使用 Set-Cookie 的响应头部来配置 cookie 信息。一条cookie 包括了5个属性值expires、domain、path、secure、HttpOnly。其中 expires 指定了 cookie 失效的时间，domain是域名、path是路径，domain 和 path 一起限制了 cookie 能够被哪些 url 访问。secure 规定了cookie 只能在确保安全的情况下传输，HttpOnly 规定了这个 cookie 只能被服务器访问，不能使用js 脚本访问。

## cookie使用场景

Cookie 是一种在客户端（通常是浏览器）存储数据的机制，它在 Web 开发中有多种使用场景。下面是一些常见的 Cookie 使用场景：

1. 身份认证和会话管理：通过在 Cookie 中存储用户的身份标识或会话令牌，服务器可以跟踪用户的登录状态并维护会话。用户在登录后，服务器会在响应中设置包含用户身份信息的 Cookie，在后续的请求中，浏览器会自动发送该 Cookie，以便服务器识别用户并提供相应的个性化内容。

2. 用户首选项和记住我功能：Cookie 可以用于存储用户的偏好设置，如语言偏好、主题选择、字体大小等。此外，"记住我" 功能通常使用 Cookie 实现，以便在用户下次访问网站时自动登录。

3. 购物车和电子商务功能：在电子商务网站中，Cookie 可用于存储用户的购物车信息，包括所选商品、数量和价格等。这样，当用户浏览其他页面或重新访问网站时，购物车中的商品信息可以保持不变。

4. 追踪和分析用户行为：通过在 Cookie 中存储跟踪标识符或访问统计信息，网站可以分析用户的行为，例如记录用户访问的页面、点击的链接、停留时间等。这些数据可以用于改进网站的用户体验和个性化推荐等功能。

5. 广告定向和广告商跟踪：Cookie 可以用于存储广告商提供的标识符，用于广告定向和跟踪用户的广告点击和转化。广告商可以根据 Cookie 中的信息投放个性化广告，并评估广告效果。

需要注意的是，Cookie 存储在客户端，并且有大小限制（通常为几KB），因此不适合存储敏感信息或大量数据。对于敏感信息，应使用安全的方式进行存储，如使用加密技术或将其存储在服务器端的会话中。另外，由于隐私保护的考虑，应遵守相关的隐私政策和法规，明确告知用户并获得其同意。


当需要使用 Cookie 存储用户的偏好设置时，可以使用 JavaScript 的 `document.cookie` 属性来设置和读取 Cookie 值。下面是一个简单的代码示例，演示如何使用 Cookie 存储和读取用户的偏好设置：

```javascript
// 设置用户偏好设置的函数
function setUserPreference(preferenceName, preferenceValue, expirationDays) {
  var cookieString = encodeURIComponent(preferenceName) + "=" + encodeURIComponent(preferenceValue);

  if (expirationDays) {
    var expirationDate = new Date();
    expirationDate.setDate(expirationDate.getDate() + expirationDays);
    cookieString += "; expires=" + expirationDate.toUTCString();
  }

  document.cookie = cookieString;
}

// 获取用户偏好设置的函数
function getUserPreference(preferenceName) {
  var name = encodeURIComponent(preferenceName) + "=";
  var cookieArray = document.cookie.split(";");

  for (var i = 0; i < cookieArray.length; i++) {
    var cookie = cookieArray[i].trim();
    if (cookie.indexOf(name) === 0) {
      return decodeURIComponent(cookie.substring(name.length, cookie.length));
    }
  }

  return null;
}

// 示例使用
setUserPreference("theme", "dark", 30); // 设置主题偏好为 "dark"，有效期为 30 天
setUserPreference("fontSize", "16px", 30); // 设置字体大小偏好为 "16px"，有效期为 30 天

var themePreference = getUserPreference("theme");
var fontSizePreference = getUserPreference("fontSize");

console.log(themePreference); // 输出: "dark"
console.log(fontSizePreference); // 输出: "16px"
```

在上述代码中，`setUserPreference()` 函数用于设置用户偏好设置的 Cookie。它接受三个参数：偏好设置名称、偏好设置值和可选的过期天数。函数首先构建一个包含偏好设置名称和值的字符串，然后根据过期天数设置过期时间，最后将 cookie 字符串设置到 `document.cookie` 属性中。

`getUserPreference()` 函数用于获取用户偏好设置的 Cookie 值。它接受偏好设置名称作为参数，并通过遍历 `document.cookie` 字符串来查找对应的 Cookie 值。

在示例中，我们设置了两个偏好设置，分别是主题（"theme"）和字体大小（"fontSize"），并为它们设置了过期时间为 30 天。然后，通过调用 `getUserPreference()` 函数来获取对应的偏好设置值，并将其打印输出。

请注意，由于 Cookie 存储在客户端，调用 `setUserPreference()` 函数后，Cookie 将在用户的浏览器中保存，并在后续的请求中自动发送到服务器。在下次访问网站时，可以通过调用 `getUserPreference()` 函数来获取用户的偏好设置值。

#### 记住我

"记住我" 功能通常是通过在用户登录时创建一个长期有效的持久性 Cookie 来实现的。当用户勾选了 "记住我" 复选框并成功登录后，服务器会生成一个唯一的标识符（例如用户的身份令牌或加密后的用户 ID），然后将该标识符存储在持久性 Cookie 中，设置一个较长的过期时间。

以下是一个简单的示例，演示如何实现 "记住我" 功能：

```javascript
// 用户登录成功后设置 "记住我" Cookie
function setRememberMeCookie(userId) {
  var expirationDays = 30; // Cookie 过期时间为 30 天
  var token = generateUniqueToken(); // 生成唯一的标识符

  // 将标识符保存在 Cookie 中
  setUserPreference("rememberMeToken", token, expirationDays);

  // 将用户 ID 和标识符关联存储在服务器端，以便在下次登录时进行验证
  saveRememberMeToken(userId, token);
}

// 记住我 Cookie 存在时，自动登录
function autoLoginWithRememberMe() {
  var token = getUserPreference("rememberMeToken");

  if (token) {
    // 根据标识符从服务器端获取用户 ID
    var userId = getUserIdByRememberMeToken(token);

    if (userId) {
      // 执行自动登录操作
      performAutoLogin(userId);
    }
  }
}

// 用户登出时清除 "记住我" Cookie
function clearRememberMeCookie() {
  setUserPreference("rememberMeToken", "", -1); // 设置过期时间为过去的时间，即立即过期
}
```

在上述示例中，`setRememberMeCookie()` 函数在用户登录成功后被调用。它生成一个唯一的标识符 `token`，然后将其存储在持久性 Cookie 中，设置过期时间为较长的天数。同时，它还将用户 ID 和标识符关联存储在服务器端。

`autoLoginWithRememberMe()` 函数用于在用户访问网站时检查是否存在 "记住我" Cookie。如果存在，它会根据标识符从服务器端获取用户 ID，并执行自动登录操作，以实现免密登录。

最后，`clearRememberMeCookie()` 函数在用户登出时被调用，它会将 "记住我" Cookie 设置为过期，从而清除该 Cookie。

请注意，这只是一个简化的示例，实际应用中还需要进行安全性的考虑，如使用加密技术保护标识符，验证标识符的有效性，处理过期和撤销等。此外，对于敏感数据，如用户密码等，不建议存储在 "记住我" Cookie 中，而应采用更安全的方式进行处理。
