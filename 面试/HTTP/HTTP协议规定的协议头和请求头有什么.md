## 1.请求头信息:
Accept:浏览器告诉服务器所支持的数据类型
Host:浏览器告诉服务器我想访问服务器的哪台主机
Referer:浏览器告诉服务器我是从哪里来的(防盜链)
User-Agent:浏览器类型、版本信息
Date:浏览器告诉服务器我是什么时候访问的
Connection:连接方式
Cookie
X- Request-With:请求方式

这个请求包含了多个头部信息，下面对每个头部信息的作用进行说明：

1.  `Accept`：用于告知服务器请求方可接受的响应类型，这里指明了可以接受的三种类型，分别是 `application/json`、`text/plain` 和 `*/*`。

		这三个是 MIME 类型（Multipurpose Internet Mail Extensions，多用途互联网邮件扩展类型）中的媒体类型（Media Type），用于指定数据的格式和类型。具体来说：
		
		1.  `application/json`：表示数据的格式是 JSON（JavaScript Object Notation），是一种轻量级的数据交换格式，常用于前后端的数据交互。这个类型指定了响应体的数据格式为 JSON 格式。
		2.  `text/plain`：表示数据的类型是纯文本，没有格式和样式，通常用于简单文本的传输。这个类型指定了响应体的数据类型为纯文本。
		3.  `*/*`：表示可以接受任意类型的数据，通配符 `*` 表示匹配任意类型。这个类型通常用于指定客户端可以接受的所有数据类型，包括文本、图片、音频、视频等。
		4.  `application`：表示数据的类型为应用程序数据，常用于指定二进制数据和结构化数据的类型，如 JSON、XML、PDF 等。
		5.  `json`：表示数据的格式为 JSON 格式，是一种轻量级的数据交换格式，常用于前后端的数据交互。
		6.  `text`：表示数据的类型为文本，常用于指定纯文本数据的类型。
		7.  `plain`：表示数据的格式为纯文本格式，没有格式和样式。
		`/` 是 MIME 类型中类型和子类型之间的分隔符。在 MIME 类型中，类型和子类型之间使用 `/` 进行分隔，例如 `application/json` 中的 `/` 就是类型和子类型之间的分隔符。
		
		`application` 是 MIME 类型的主类型（或称为顶级类型），表示数据的类型为应用程序数据；而 `json` 是 MIME 类型的子类型，表示数据的格式为 JSON 格式。因此，`application/json` 表示数据的类型为应用程序数据，格式为 JSON 格式。		
		总的来说，`/` 是 MIME 类型中类型和子类型之间的分隔符，可以用于指定数据的类型和格式。不同的 MIME 类型用于满足不同的数据交互需求。	
		因此，`application/json` 表示数据的类型为应用程序数据，格式为 JSON 格式；而 `text/plain` 表示数据的类型为文本，格式为纯文本格式。
		在 HTTP 协议中，客户端通过在请求头部信息中指定 `Accept` 字段来告知服务器可以接受哪些媒体类型的数据。服务器在响应头部信息中通过 `Content-Type` 字段来告知客户端响应体的数据类型和格式。当客户端和服务器协商后，确定了数据的类型和格式，就可以进行数据的传输和解析。


2.  `Accept-Encoding`：用于告知服务器请求方可接受的压缩方式，这里指明了可以接受的两种压缩方式，分别是 `gzip` 和 `deflate`。
3.  `Accept-Language`：用于告知服务器请求方可接受的自然语言，这里指明了可以接受的三种语言类型，分别是 `zh`、`zh-CN` 和 `en`。
4.  `Host`：用于指定请求的服务器地址和端口号，这里指定了请求的主机地址为 `211.66.96.30`。
5.  `Proxy-Connection`：用于指定是否需要使用代理连接，这里指定了需要保持代理连接。
6.  `Referer`：用于指定当前请求是从哪个页面跳转过来的，这里指定了请求的来源页面为 `http://211.66.96.30/`。
7.  `User-Agent`：用于告知服务器请求方的操作系统和浏览器信息，这里指定了请求方使用的操作系统和浏览器类型和版本。
8.  `token`：用于在请求中携带身份验证信息，这里携带了一个名为 `token` 的字符串，可能是用于验证用户身份的 token。

这几个内容是 HTTP/2 协议中的伪首部字段，用于指定请求或响应的基本信息。具体来说：

1.  `Authority`：用于指定请求的目标服务器的网络位置，包括主机名和端口号。对于 HTTP/2 协议来说，这个字段通常会替代 HTTP/1.x 协议中的 `Host` 头部信息。
2.  `Method`：用于指定 HTTP 请求方法，包括 `GET`、`POST`、`PUT`、`DELETE` 等常见的方法。这个字段与 HTTP/1.x 协议中的请求方法是一致的。
3.  `Path`：用于指定请求的路径，即请求的资源在服务器上的相对路径。
4.  `Scheme`：用于指定请求或响应的协议方案，通常是 `http` 或 `https`。

这些伪首部字段是 HTTP/2 协议中引入的新特性，在 HTTP/1.x 协议中是不存在的。它们的作用是为了简化 HTTP 头部信息的传输，避免头部信息的重复和冗余，提高网络传输效率。在 HTTP/2 协议中，这些伪首部字段被视为 HTTP 头部信息的一部分，但是在实际传输过程中，它们并不会被作为独立的头部信息进行传输，而是会和其他头部信息一起被打包成帧进行传输。

Server:告诉浏览器服务器的类型
Content-Type:告诉浏览器返回的数据类型
Refresh:控制了的定时刷新

这些是 HTTP 协议中的响应头部信息，下面对每个头部信息的作用进行说明：

1.  `HTTP/1.1 200`：表示服务器成功处理了请求，并返回了响应结果。其中的 `200` 是 HTTP 响应状态码，表示请求成功。
2.  `Transfer-Encoding: chunked`：表示响应体采用分块传输编码方式进行传输。这种编码方式可以把响应体分成若干个块，每个块都包含一个长度和数据，可以在传输过程中动态生成和传输响应体，提高传输效率。
3.  `Access-Control-Allow-Methods: GET,POST,OPTIONS,PUT,DELETE`：表示服务器支持的跨域请求方法。这个头部信息通常在跨域请求时使用，用于告知浏览器哪些请求方法是被允许的。
4.  `Connection: keep-alive`：表示客户端和服务器之间的连接将被保持打开状态，以便后续的请求和响应可以复用这个连接，减少连接建立和断开的开销。
5.  `Content-Type: application/json`：表示响应体的类型是 JSON 格式。这个头部信息通常用于告知客户端如何解析响应体。
6.  `Date: Sun, 14 May 2023 20:39:29 GMT`：表示服务器响应的时间。
7.  `Keep-Alive: timeout=4`：表示客户端和服务器之间的连接可以保持打开状态的最长时间，这里设置为 4 秒。
8.  `Proxy-Connection: keep-alive`：表示客户端和代理服务器之间的连接将被保持打开状态，以便后续的请求和响应可以复用这个连接，减少连接建立和断开的开销。
9.  `Server: nginx/1.22.1`：表示服务器的软件和版本信息。
10.  `Set-Cookie: rememberMe=deleteMe; Path=/; Max-Age=0; Expires=Sat, 13-May-2023 20:39:29 GMT; SameSite=lax`：表示服务器要在客户端设置一个名为 `rememberMe` 的 cookie，这里的设置是把这个 cookie 删除。这个头部信息通常在需要在客户端设置 cookie 时使用。
11.  `Vary: Origin`、`Vary: Access-Control-Request-Method`、`Vary: Access-Control-Request-Headers`：表示响应体的内容可能因请求头中的不同字段而有所不同。这个头部信息通常在缓存策略中使用，用于告知缓存服务器如何缓存和更新响应内容。

## general

在网络请求中，`General` 通常是指请求的基本信息，包括请求的方法、地址、协议版本等。在浏览器中发起网络请求时，可以通过打开浏览器开发者工具来查看请求的详细信息。在开发者工具中，请求信息通常会被分成不同的标签页，其中 `General` 标签页用于显示请求的基本信息。

具体来说，`General` 标签页通常会包含以下信息：

-   Request URL：请求的 URL 地址；
-   Request Method：请求的方法，通常是 GET 或 POST；
-   Status Code：请求的状态码，表示请求是否成功；
-   Remote Address：请求的远程地址，即服务器的 IP 地址；
-   Referrer Policy：请求的引用策略，即浏览器发送请求时是否发送来源信息等。

除了 `General` 标签页之外，还有一些其他的标签页用于显示请求的详细信息，如 `Headers`、`Response`、`Preview` 等。这些标签页可以用于查看请求的请求头、响应头、响应体等详细信息，帮助开发者诊断和调试网络请求问题。
