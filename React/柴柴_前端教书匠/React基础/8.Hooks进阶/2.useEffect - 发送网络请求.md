`本节任务:`  能够掌握使用useEffect hook发送网络请求

**使用场景**

如何在useEffect中发送网络请求，并且封装同步 async await操作

**语法要求**

不可以直接在useEffect的回调函数外层直接包裹 await ，因为**异步会导致清理函数无法立即返回**

```js
useEffect(async ()=>{    
    const res = await axios.get('http://geek.itheima.net/v1_0/channels')   
    console.log(res)
},[])
```

这是因为在 JavaScript 中，`async` 函数返回的是一个 Promise 对象。当在 `useEffect` 的回调函数外部直接使用 `await`，实际上是在等待这个 Promise 对象的完成。而在 `useEffect` 中，清理函数需要立即返回以进行组件的清理工作，但由于 `await` 的存在，清理函数将无法立即返回。

为了解决这个问题，我们需要确保清理函数可以立即返回，而不会被异步操作阻塞。一种解决方法是将异步操作放在一个内部的函数中，然后在 `useEffect` 的回调函数中调用这个函数，以避免直接在外部使用 `await`。

另外，`useEffect` 的回调函数可以返回一个清理函数，用于在组件卸载或下一次回调触发之前执行必要的清理操作。因此，清理函数的返回值应该是一个函数或 `undefined`，而不是一个 Promise 对象。


**正确写法**

在内部单独定义一个函数，然后把这个函数包装成同步

```jsx
useEffect(()=>{   
    async function fetchData(){      
       const res = await axios.get('http://geek.itheima.net/v1_0/channels')                            console.log(res)   
    } 
},[])
```

 或
 
在 `useEffect` 的回调函数外部直接使用 `await` 可能会导致清理函数无法立即返回，从而引发一些意外的行为。为了解决这个问题，你可以将 `await` 放在一个内部的异步函数中。下面是一个示例：

```js
useEffect(() => {
  const fetchData = async () => {
    try {
      const res = await axios.get('http://geek.itheima.net/v1_0/channels');
      console.log(res);
    } catch (error) {
      console.error(error);
    }
  };

  fetchData();

  return () => {
    // 清理函数
    // ...
  };
}, []);
```

在上述示例中，我们将 `await` 包装在名为 `fetchData` 的内部异步函数中。然后，我们在 `useEffect` 的回调函数中调用 `fetchData()` 来获取数据。这样，清理函数就能够立即返回，并且在异步操作完成之前不会被调用。

请注意，我们还添加了错误处理部分（`try-catch`）来捕获可能的异步错误。这有助于在发生错误时提供适当的反馈或执行其他操作。

使用这种方式，你就可以在 `useEffect` 中正确地处理异步操作，并确保清理函数能够立即返回。
