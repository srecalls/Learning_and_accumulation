### 1. 手写Promise

```js
/*
 1. 初始化
 2. 状态不可变
 3. 异常处理
 4. 确保参数是函数
 5. 回调保存
 6. 微任务
 7. 链式调用
*/
class myPromise {
    constructor(executor) {
        this.PromiseState = 'pending';
        this.PromiseResult = null;
        this.onFulfilledCallbacks = [];
        this.onRejectedCallbacks = [];
        try {
            executor(this.resolve.bind(this), this.reject.bind(this));
        } catch (error) {
            this.reject(error);
        }
    }
    resolve(result) {
        if (this.PromiseState === 'pending') {
            this.PromiseState = 'fulfilled';
            this.PromiseResult = result;
            this.onFulfilledCallbacks.forEach(callback => {
                callback(result);
            })
        }
    }
    reject(reason) {
        if (this.PromiseState === 'pending') {
            this.PromiseState = 'rejected';
            this.PromiseResult = reason;
            this.onRejectedCallbacks.forEach(callback => {
                callback(reason);
            })
        }
    }
    then(onFulfilled, onRejected) {
        return new myPromise((resolve, reject) => {
            let fulfilled = () => {
                queueMicrotask(() => {
                    try {
                        if (typeof onFulfilled !== 'function') {
                            resolve(this.PromiseResult);
                        } else {
                            const x = onFulfilled(this.PromiseResult);
                            return x instanceof myPromise ? x.then(resolve, reject) : resolve(x);
                        }
                    } catch (error) {
                        reject(error);
                    }
                })
            }
            let rejected = () => {
                queueMicrotask(() => {
                    try {
                        if (typeof onRejected !== 'function') {
                            reject(this.PromiseResult);
                        } else {
                            const x = onRejected(this.PromiseResult);
                            return x instanceof myPromise ? x.then(resolve, reject) : reject(x);
                        }
                    } catch (error) {
                        reject(error);
                    }
                })
            }
            switch (this.PromiseState) {
                case 'pending':
                    this.onFulfilledCallbacks.push(fulfilled);
                    this.onRejectedCallbacks.push(rejected);
                    break;
                case 'fulfilled':
                    fulfilled();
                    break;
                case 'rejected':
                    rejected();
                    break;
            }
        })
    }
}
```

### 2. 手写promise的各式方法

```js
myPromise.resolve = (value) => {
    return value instanceof myPromise ? value : new myPromise((resolve => resolve(value)));
}

myPromise.reject = (reason) => {
    return new myPromise((resolve,reject) => {
        reject(reason);
    }) 
}

myPromise.all = (promises) => {
    return new myPromise((resolve, reject) => {
        if (Array.isArray(promises)) {
            if (promises.length === 0) {
                return resolve(promises);
            }
            let result = [];
            let count = 0;
            promises.forEach((item, index) => {
                myPromise.resolve(promises[index]).then(
                    value => {
                        count++;
                        result[index] = value;
                        count === promises.length && resolve(result);
                    },
                    error => {
                        reject(error)
                    }
                )
            })
        } else {
            return reject(new TypeError('error'))
        }
    })
}

myPromise.race = (promises) => {
    return new myPromise((resolve, reject) => {
        if(Array.isArray(promises)){
            promises.forEach(item => {
                myPromise.resolve(item).then(resolve,reject);
            })
        }else{
            return reject(new TypeError('error'))
        }
    })
}
```

### 5. for和forEach的区别

1. for循环写得比较麻烦，forEach写起来比较舒服，可读性更好；
2. for循环可以灵活控制循环的进程，你可以从2开始，也可以从3跳到1，forEach做不到，但是forEach会跳过稀疏数组中的空位，而for循环不会，如[1,,,4]；
3. for循环使用continue跳过当次循环，break中断循环，forEach使用return跳过当次循环，try catch中断循环；
4. for循环效率高于forEach，因为for循环是直接使用下标，而forEach需要创建一个新的函数，并且通过函数调用进行迭代。

### 6. setTimeout和setInterval的原理

js是门单线程的语言，如果把计时放在js引擎线程上会阻塞代码执行，所以浏览器有一个定时器触发线程专门用来计时，时间一到它就把它的回调函数放到任务队列里，等js引擎线程取出来执行，所以他只是定时的把回调函数放到任务队列里，如果此时执行栈或任务队列不为空，那这个回调函数还得排队；setInterval它是有个原则的，在向队列添加回调函数时，如果上一次的回调函数还存在在队列中未被执行，就会放弃添加，还有就是如果我们希望两个函数间隔一秒执行，那么定时器计时就设置为一秒，但如果回调函数比较复杂执行了0.9秒，这样两次函数执行的间隔是0.1秒，可以使用setTimeout模拟setInterval去解决；还有一个细节就是传入的延迟时间为0，浏览器至少也会在4ms后执行。

### 8. XSS攻击

XSS是一种代码注入攻击，攻击者注入恶意脚本进目标网站，用户访问网站时会执行恶意脚本，可以盗取用户的cookie；

1.  存储型

   攻击者输入一段js脚本提交到服务端的数据库中，当浏览器请求数据时，存储的脚本会返回并执行；比如有块留言板，你留言一段js脚本上传服务器，别人访问这块留言时，你留言的js脚本就会被返回并执行；

2.  反射型

   也叫非持久型，它是攻击者构造出包含恶意代码的url，诱使用户点击，服务端会把url参数拼接到HTML中后返回给浏览器，浏览器拿到后就会解析执行，比如在参数后拼一块；

3.  DOM型

   攻击者通过一些劫持手段，在页面资源传输的过程中劫持并修改数据，插入恶意代码；

如何防范：

1. 对输入框的内容进行过滤或转义；
2. 添加http-only，不让js脚本取到cookie；
3. 使用csp，也就是白名单，告诉浏览器哪些外部资源可以加载执行，让恶意代码插入后也无法执行，两种方法开启白名单，一种是设置http头部的Content-Security-Policy，一种是使用meta标签<meta http-equiv="Content-Security-Policy">

### 9. CSRF攻击

CSRF攻击是跨站请求伪造攻击，主要是利用用户的登录状态发起跨站请求，欺骗服务端，发起CSRF攻击的条件有二，第一是用户登录过目标网站并保持登陆状态，第二是用户需要打开攻击者的网站；比如恶意网站里有一个img标签，src为目标网站的接口，访问这个恶意网站后会自动向这个接口发起请求，或者是有一条链接，点了也会发起请求，而cookie又会自动携带，这样服务端就会误以为是用户发起的请求。

如何防范：

1. 验证码，用户必须与应用交互才能完成请求；

2. 验证请求的来源，请求头有Origin和Referer属性，判断是否为允许访问的站点，对请求进行过滤，优先判断Origin，Referer会携带请求的路径信息，不太安全，Origin没有具体路径信息；

3. token；

### 10. http的无状态

无状态是指http不会为了下次连接所需要到的信息而维护这次连接；就是当浏览器发送一次请求给服务器，服务器响应后，下次浏览器再发请求给服务器，服务器还是会响应，但是服务器不会去记住你，就是不知道你上次来过。可以使用cookie和session去解决，session是服务器开辟的一块内存空间，可以用来记录用户信息，它有一个sessionId，这个id可以放到cookie传输到浏览器，浏览器保存cookie，下次发请求的时候就会携带cookie。

### 11. 为什么基本数据类型存在栈中，引用数据类型存在堆中

栈是一段连续紧凑的空间，存储CPU缓存中，堆内存结构不连续，每个对象地址可能是随机的，存储在物理内存中，读取速度比栈慢，因此选择把基本数据类型和引用数据类型的引用地址存在栈中，等你要找一个对象的时候先去栈中快速找到它的引用地址，然后再去堆中，这样比较快；有一个注意点，如果一个基本数据类型非常大，或者有非常多的基本数据类型，超过了CPU缓存容量的大小，那么访问栈的速度就会变得非常慢，可以把一些改成对象存在堆中。

### 15. 硬件加速的原理

先说一下CPU与GPU：CPU能执行各种复杂的逻辑和运算，而GPU有成百上千个核心用于并行计算，适合去计算那些计算量大却简单的，3D的渲染中有大量简单的计算，适合交给GPU；

页面中元素的布局和渲染一般是通过CPU去完成的，当页面中的元素更新时，可能会触发重排，重排是很费性能的，而硬件加速是交给GPU进行计算渲染，减轻CPU的压力，他会生成一个全新的合成层，该合成层中的动画会单独绘制，其他层就避免了重排，它不仅能提升性能，还能提高动画的渲染帧数，但注意不能过多的使用，过多的使用可能导致内存问题；

如果你不想使用3D动画却又想开启硬件加速：transform:translateZ(0)。

### 16. cookie自动携带问题

新版chrome浏览器有一个SameSite，它有三个值：第一个是Strict，是最严格的，完全禁止第三方cookie，跨站点时不会发送cookie，只有当前网页与请求目标一致时才会带上cookie，设置用户体验不好，跳转链接的时候由于不会自动携带cookie，所以到新链接总是未登陆的状态；第二个是Lax，默认是这个值，它大多数情况也不会发送cookie，但是跳转到目标网址的get请求允许携带cookie；设置了Strict或Lax就基本杜绝了CSRF攻击；第三个是none，它允许第三方cookie，但必须使用https协议并设置Secure属性，否则不生效。

### 17. package.json和package-lock.json的区别

package.json记录了你下载了哪些包，以及这些包大版本号，package-lock.json记录的更为详细，会有包的具体版本号，以及你下载的包的依赖包（package.json只记录了你下载的包，下载的包的依赖包不会记录），当你执行npm install的时候它会读取package.json中所有的包，并与node_modules中安装的依赖进行对比，存在的话就根据package-lock.json检查更新，没有则通过package-lock.json获取相应的版本号，接着看一下这个版本号与package.json里是否兼容，兼容就安装，不兼容就按照package.json里的安装，并更新package.lock.json。

### 19. setTimeout和requestAnimationFrame的区别

1. 流畅：setTimeout回调函数是放到任务队列去执行的，执行时间是不确定的，而且不同屏幕的刷新频率也可能不一致，因此setTimeout做动画可能会丢帧，出现闪屏，而requestAnimationFragment执行时间是根据系统的刷新频率，做动画比较流畅；
2. 性能：requestAnimationFragment还会把每一帧的DOM操作集中起来，在一次回流中完成，减少回流，性能更好；
3. 优化：当页面被隐藏时（tab页面切换），requestAnimationFragment的回调函数会暂停执行，即有动画的话动画会停止，而setTimeout会继续执行。

```js
class eventsEmitter {
	constructor() {
		this.events = {};
    }
    on(type, callback) {
        if (!this.events[type]) {
			this.events[type] = [callback];
        } else {
            this.events[type].push(callback);
        }
    }
    emit(type, ...rest) {
		this.events[type] && this.events[type].forEach(callback => callback.apply(this, rest));
    }

        this.events[type] = this.events[type].filter(item => item !== callback);
    }
}
```

### 30. HTTPS原理

对称加密：只有一个密钥，数据传输的时候用这个密钥来加密和解密；如果这个密钥被别人劫持到手，之后他就能用密钥解开双方传输的数据了；

非对称加密：服务器与浏览器各有一对公私钥，传输的时候双方交换公钥，用对方的公钥加密后再传输，各自就能拿自己的私钥解密了，加密后的数据被劫持或者公钥被拿到都没有关系，因为他们各自的私钥都是自己保存，没有拿出来传输，攻击者没有他们私钥解不了密；这种方法看似安全，但有一种中间人攻击，下面的对称加密+非对称加密模式也会受到中间人攻击，等会一起讲；

对称加密+非对称加密：因为非对称加密算法非常耗时，特别是对比较大的数据进行加密时，而对称加密快很多，但对称加密在传输密钥的时候有可能被劫持，没有非对称加密安全，所以采用这种方法，用非对称加密去传输对称加密的密钥，保证对称密钥的传输安全，之后传输数据使用对称加密；上面说到这个方法并不安全，因为有中间人攻击，中间人攻击就是中间人先生成一对自己的公私钥，服务器传公钥给浏览器的时候被劫持，替换成自己的公钥，浏览器拿到公钥并不知情已经被调包了，浏览器就生成一个对称密钥，用传过来的公钥加密，传回给服务器，中间人又劫持到，把加密的内容用自己的私钥去解密，解密完拿到此后他们要用来传输的对称密钥，再把这个密钥用之前劫持到的服务的公钥加密，传还给服务器，服务器拿到这个东西，可以用自己的私钥解密，就以为没问题，后续他们都用这个对称密钥去传输，但这个对称密钥已经被中间人拿到了，后续传输内容被劫持到的中间人都能解密；

上面说的中间人攻击就是掉包了公钥，那我们就是要确保这个公钥不被掉包，就得说到下面的CA机构，服务器可以去申请证书，机构就会给你颁发一个数字证书（要钱的），数字证书就能保证服务器传过来的公钥不被中间人掉包，浏览器会预存CA机构的公钥，证书是包含了服务的公钥以及域名等一些服务器的信息，CA机构拿出私钥对这些东西进行一个签名，在传输的时候先传这个证书，浏览器拿到证书就用CA机构的公钥进行解密，如果签名被篡改了，攻击者没有私钥进行签名，传给浏览器，浏览器用公钥也解不开，所以保证不被篡改。如果证书被掉包成另一个合法的证书，浏览器解开后拿自己的请求的地址与解密后拿到的地址一对比，也就知道被掉包了。

简单的握手过程：浏览器发请求，服务传证书，浏览器验证证书是否被篡改或者掉包，验证通过就生成一个密钥，用证书传过来的服务器的公钥进行加密，传给服务器，服务器接受拿私钥进行解密，存到session里，并且把session ID给浏览器，本次和之后的传输就用这个浏览器生成的密钥进行加密。

### 36. TCP是如何保证可靠传输的

1. 三次握手：建立连接时会三次握手，保证双方具有发送和接收能力；
2. 检验和：没懂，检验数据传输是否有误，有误则丢弃重传；
3. 应答机制和超时重传：每个数据都有一个序列号，当发送一个数据包，接收方在收到之后都需要回一个ACK包，表示确认收到这个ACK包了，如果没有收到就会进行重传，也就是超时重传；
4. 流量控制：使用是滑动窗口，当接收方来不及处理发送方的数据时，能通过滑动窗口提示接收方降低发送速率，减少丢包概率；
5. 拥塞控制：慢启动，先发少量数据，摸清当前网络拥堵状况，再决定按照多大速度传送数据，

### 37. vue-router的路由原理

两种模式都是改变url，更新视图，但不向服务器请求网页，也不会刷新页面；

hash模式：使用了hashChange事件监听地址栏hash的变化，使用window.location.hash获取hash值；

history：使用pushState和replaceState去修改浏览器的历史记录栈，router-link本质是个a标签，它会禁用a标签的默认行为，点击router-link后会去调用pushState，再判断url上的路由去加载组件，同时监听popState事件去实现点击浏览器前进后退按钮切换路由；

pushState与replaceState的区别：pushState会添加新的历史记录，而replaceState不会，它只替换当前历史记录；

history与hash模式的区别：

1. 直观的体现是hash模式会带#，而history模式不会；

2. history模式比hash模式更利于seo；

   （hash模式带有#，搜索引擎的爬虫难以理解这种URL的含义，而history不会带#，搜索引擎能更好的理解站点结构和页面之间的关系）

3. history模式直接地址栏去访问路由或者刷新会导致404，需要服务器去配置，而hash模式是不用的；

   （因为你平时切换路由是不会向服务器发送请求的，直接去输入地址栏或者刷新页面是会的，hash模式下发起请求服务器会不管#后面的内容，但是history模式下是没有#的，服务器就会去找相应的资源，但肯定是找不到，因为路由只是在前端使用，所以就会返回404页面，需要服务器设置找不到资源时重定向到index.html页面，再走路由的配置获取对应页面，但这里有个问题是找不到资源不会返回404页面，这就需要前端配置路由，将未匹配到的路由重定向到404页，这个要放在最后）

4. hash兼容更好，如果你使用history模式，vue-router里面也会先判断浏览器是否支持history模式，如果不支持就自动切换成hash模式。

```js
    this.monaco.languages.registerFoldingRangeProvider('json', {
        provideFoldingRanges: function(model, context, token) {
            const foldingRanges = []
            const stack = []
            for (let lineNumber = 1; lineNumber <= model.getLineCount(); lineNumber++) {
                const lineText = model.getLineContent(lineNumber)
                if (lineText.trim().startsWith('{') || lineText.trim().startsWith('[') || lineText.endsWith('{') || lineText.endsWith('[')) {
                    stack.push(lineNumber)
                } else if (lineText.trim().startsWith('}') || lineText.trim().startsWith(']')) {

                        start: startLineNumber,
                        end: lineNumber - 1
                    })
                }
            }
            return foldingRanges
        }
    })
```
