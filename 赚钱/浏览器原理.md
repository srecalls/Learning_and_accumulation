### 1. 浏览器缓存的全过程

浏览器第一次从服务器请求资源时，会缓存资源和响应头，再次请求这个资源时会判断响应头中的Expires和Cache-Control，Expires是到期日期，Cache-Control是指定资源多少秒过期，如没有过期则直接使用缓存，不向服务器发请求，这就是强缓存。两者的优先级是Cache-Control更高，Expires是为了兼容浏览器不认识Cache-Control。如果资源已经过期，则开始协商缓存，先判断是否存在ETag，有则向服务器发送带有If-None-Match字段的请求，服务器在接受该请求时，将ETag与If-None-Match对比，一致则命中协商缓存，返回304，不一致则返回200和请求的资源加上新的ETag，没有ETag则判断有没有Last-Modified，有则向服务器发送带If-Modified-Since字段的请求，服务器在接受该请求时，将Last-Modified和If-Modified-Since对比，一致则命中协商缓存，也是返回304，不一致则返回200和请求的资源加上新的Last-Modified。同时使用ETag与Last-Modified时，ETag的优先级更高，ETag感知文件的精准度比Last-Modified高，但是ETag性能上弱于Last-Modified，因此不能完全替代它。

对于频繁变动的资源：使用Cache-Control: no-cache（使用协商缓存），这样虽然不能节省请求的数量，但能显著减少响应数据的大小；

对于不频繁变动的资源：可以给Cache-Control的max-age配置一个很大的数，这样去命中强缓存，但为了解决更新的问题，需要在文件名上添加hash，更新的时候改动文件名，从而让之前的强缓存失效。

### 2. 浏览器缓存的位置

1. Service Worker：它是运行于js主线程之外的，无法访问DOM，相当于一个代理服务器，可以拦截修改用户的请求，或者直接回应用户，不去联系服务器。可以完成离线缓存、消息推送、网络代理等功能，使用它时必须使用https协议，因为涉及到拦截请求，需要https协议保障安全。当Service Worker没有命中缓存时，会调用fetch函数去其它缓存中查找，但是后续不管是从缓存中还是从网络请求中获取的数据，浏览器都会显示是从 Service Worker 中获取的内容。
2. Memory Cache：它是内存缓存，效率最高，但是缓存持续时间很短，关闭tab页面，内存中的缓存就释放了。
3. Disk Cache：它是硬盘缓存，读取速度慢些，相比Memory Cache容量更大，时效更久。
4. Push Cache：它是HTTP/2的内容，以上三种缓存都没有命中时，它才会被使用，缓存时间很短，一旦会话结束就被释放，而且Push Cache只能被使用一次。

### 3. 几种刷新和回车的区别

1. 浏览器输入URL回车、跳转链接、前进后退等，强制缓存有效，协商缓存有效。
2. 使用F5刷新时、点击刷新按钮，强制缓存失效，协商缓存有效。
3. 使用Ctrl+F5刷新时，本地缓存文件过期，强缓存和协商缓存都失效，直接请求服务器。

### 4. Cookie、SessionStorage、LocalStorage

三者都是存储在浏览器本地的。

1. Cookie：大小为4k，由服务器端写入，可以指定时间，没指定时间则关闭窗口就失效，可以在同源的所有标签页中访问到。
2. SessionStorage：大小为5M，由前端写入，页面关闭时自动清除，只可以在当前标签页中访问到。（同源的不同标签页访问不到！）
3. LocalStorage：大小为5M，由前端写入，会一直保存除非手动清除，可以在同源的所有标签页中访问到。

### 6. V8垃圾回收机制

V8采用分代垃圾回收算法，将内存分为新生代和老生代两个内存空间，新生代中对象存活时间短，使用基于Scavenge算法的垃圾回收策略，老生代中对象存活时间长，使用基于标记清除、标记整理、增量标记等算法的垃圾回收策略。

在新生代中，V8将内存分为两个相等的空间，分别为From空间和To空间，当From空间将要被占满的时候，V8会将存活的对象复制到To空间，再将From空间清空，然后将From空间和To空间交换，这样就完成了一次垃圾回收。

当一个对象在经过多次复制依旧存活，则会被转移到老生代中，老生代早期使用标记清除，现在使用标记整理。标记清除是对所有对象进行标记，去掉被引用对象的标记，仍有标记的对象将会被清除。此方法会产生很多内存碎片，因此出现了标记整理。标记整理是先标记所有活动对象和非活动对象，移动整理它们的内存位置，清除非活动对象。接着由于垃圾回收的时候应用程序会暂停，应用长时间的暂停会导致用户糟糕的体验，那么为了减少全停顿的时间，V8对标记进行了优化，使用了增量标记，将一次停顿进行标记的过程分为了很多小步。增量标记是进行三色标记，一色是未搜索的对象，一色是正在搜索的对象，一色是搜索完成的对象。

我们能做些什么：尽可能少创建全局变量，手动清除定时器，少用闭包。

### 9. 事件委托的理解 （也称事件代理）

利用浏览器的事件冒泡机制，把子节点的监听函数绑在父节点上，由父节点去处理，子委托给父。

优点：不用一个一个子节点绑定监听函数，节省内存空间。在创建和删除子节点时不用再绑定或解除事件。

缺点：最底层元素与绑定事件元素层级相差过多时，事件的传播链会很长，会耗时，所以尽量就近委托。

### 10. 事件循环

js是一门单线程的语言，但当我们需要调用接口或进行延时操作时，会阻塞整个进程，所以就需要事件循环。

首先先执行同步代码，遇到的异步任务则放到任务队列里，待同步代码执行完毕，执行任务队列中的微任务，微任务执行完毕后开启下一轮事件循环，执行宏任务，直到任务队列为空，简而言之就是一次宏任务一次微任务交替。

宏任务有：script脚本的执行，三个定时器：setTimeout、setInterval、setImmediate，ajax请求，I/O操作和UI渲染，微任务有：promise.then、MutationObserver，node.js中的process.nextTick，

### 11. 宏任务和微任务

宏任务：script脚本的执行，三个定时器：setTimeout、setInterval、setImmediate，ajax请求、还有I/O操作和UI渲染。

微任务：promise.then、MutationObserver，和node.js中的process.nextTick

### 12. 浏览器渲染的过程

解析html生成dom树的同时解析css生成css规则树，生成的dom树和css规则树构建出渲染树，根据渲染树生成布局，再进行绘制，呈现出页面。

### 13. 浏览器渲染过程中遇到js文件

在遇到非defer和async的script标签时，它会阻塞渲染过程，直到该js脚本加载执行完毕。如果是含有defer属性，加载js文件的时候不会阻塞渲染过程，待渲染完毕之后再执行js脚本内容。如果是含有async属性，也是加载js文件的时候不会阻塞渲染过程，但加载完毕之后渲染还未结束的话会被阻塞，去执行js脚本内容。

### 14. 回流（重排）与重绘

回流：当页面中的元素发生结构上的改变，比如改变元素的大小、位置、内容等，就会触发浏览器重新计算页面元素的位置和几何结构，然后重新布局整个页面，这个过程叫回流，回流必定发生重绘；

重绘：当页面中元素的样式改变，而不影响在页面中的位置时，会使用新的样式重绘这个元素，而不需要重新布局，这个过程叫重绘，重绘不一定回流。

以下是一些避免回流与重绘的方法：

1. 避免频繁的操作DOM，可以使用批量更新的方法，一次性对多个DOM进行修改；
2. 避免频繁的操作样式，可以使用class一次性更新样式；
3. 如果需要设置动画效果，可以使用绝对定位让它脱离文档流；
4. 使用CSS3动画代替JS动画；
5. 可以先为元素设置为不可见，displya:none，操作完再将它显示出来。

### 17. 进程和线程

1. 根本区别：进程是操作系统进行资源分配的基本单位，也就是说进程可以单独运行一段程序，而线程是操作系统进行运算调度的最小单位；

2. 从属关系：一个进程可以包含至少一个线程，线程只能属于进程；

3. 拥有资源不同：进程拥有独立的内存空间，同一个进程下的线程可以共享资源；

4. 影响能力：进程下的线程挂掉，可能会导致整个进程挂掉，而进程之间是不会相互影响的。

5.  开销不同：一个进程可以并发多个线程，每个线程执行不同的任务，虽然多进程也可以实现并发，但线程比进程更加轻量，在创建、销毁、调度时的开销线程小于进程；

Chrome浏览器的进程（至少需要四个进程）：

一个浏览器进程：负责浏览器界面显示与用户交互，如前进和后退，负责各个页面的管理，创建和销毁其它进程，同时还负责提供存储功能；

一个网络进程：主要负责页面网络资源的加载，之前是作为一个模块运行在浏览器进程中，直到最近才独立出来，成为一个单独的进程；

一个GPU进程：GPU的使用初衷是为了实现3DCSS的效果，只是后来Chrome的UI界面都选择采用GPU来绘制，最后Chrome在其多进程架构上也引入了GPU进程；

多个渲染进程：负责将HTML、CSS、JavaScript转化为用户可交互的页面；

多个插件进程：负责插件的运行，因插件容易崩溃，所以需要通过进程来隔离，以保证插件进程崩溃不会对浏览器页面造成影响。

### 18. Chrome浏览器多进程的优势

更高的容错性：如果是单进程的话，某个tab页面或插件崩溃了就会影响到整个浏览器，使用多进程各个页面相互之间不受影响；

更高的安全性：浏览器经常会遇到些恶意代码，针对这一问题，浏览器对不同进程限制了不同权限，使其更安全可靠；

更高的响应速度：多进程分开处理速度会更快，但相应的内存等资源也会消耗更大，有点空间换时间的意思。

### 19. 浏览器渲染进程的线程有哪些

js引擎线程：用来解析和运行js脚本程序，在运行代码时会生成一个执行栈，一个浏览器的渲染进程只有一个js引擎线程在运行，即js是单线程的；

事件触发线程：管理着任务队列，用来控制事件循环，异步任务的回调函数会被放入其中，待js引擎线程中的执行栈中的任务执行完毕，再来读取其中的任务执行；

定时器触发线程：即setTimeout、setInterval所在的线程，定时器并不是由js引擎线程来计数的，因为js引擎是单线程，如果处于阻塞线程的状态下就会影响计时的准确性，所以需要使用单独的线程来计时并触发定时器，计时完毕之后，会将事件添加到任务队列里，待js引擎空闲时执行，所以定时器不一定准时，它只是准时的把任务放到任务队列中，还有就是规定要求setTimeout中低于4ms的时间间隔算为4ms；

GUI渲染线程：负责解析HTML生成DOM树，解析CSS生成CSS规则树，构建渲染树和绘制页面，当界面需要重绘或回流时，该线程就会执行；

异步http请求线程：HTTP请求连接时，会执行这个线程，状态更改时，如果有回调函数，这个回调函数会添加到任务队列，等待js引擎线程执行。

### 19. js引擎线程与GUI渲染线程互斥

由于js引擎线程是可操作DOM的，如果在操作DOM的同时渲染界面，那么渲染开始到结尾获得的元素数据可能不一致，因此为了防止渲染的时候出现不可预期的结果 ，浏览器设置js引擎线程与GUI渲染线程为互斥的，即当js引擎线程运行时，GUI渲染线程会被挂起，GUI更新会被保存在一个队列中，等待js引擎线程空闲时立即被执行，GUI渲染线程执行时同理。

运行机制是：宏任务->微任务->GUI渲染进程->宏任务->微任务->...

浏览器的刷新频率一般为60HZ，也就是16.6ms，那么比如js引擎正在进行巨量的运算，一次事件循环用时超出了16.6ms，那么这次刷新就没有时间进行样式的布局和绘制，就会造成页面的卡顿。

### 20. WebWorker

上面提到js的执行时间过长会造成页面卡顿，如进行巨量计算，这个时候我们可以使用HTML5支持的WebWorker，它是js引擎向浏览器申请开一个子线程，这个子线程不能操作DOM，而且完全受主线程的控制，与主线程通过postMessage API进行通信，在进行耗时的操作时可以使用它，这样不管这个线程进行了什么操作都不会影响到js引擎线程，只待计算结果出来之后将结果返回给主线程。

WebWorker与ShareWorker：WebWorker是线程，只属于当前的tab页面，ShareWorker是进程，是浏览器所以tab页面共享的。

### 21. 孤儿进程和僵尸进程

孤儿进程是父进程退出，而它的子进程还在运行，这些子进程都会成为孤儿进程，孤儿进程会被init进程接管，并由init进程对它们完成状态收集工作，因为孤儿进程会被init进程接管，所以孤儿进程是没有危害的；

僵尸进程是子进程退出，父进程又没有回收释放子进程的资源，这个进程就会成为僵尸进程，在内存资源上僵尸进程不会占用多少资源，但是通常系统的进程数是有限的，如果大量的僵尸进程占用进程号，导致新的进程无法创建，这个危害类似占着个坑不办事。

### 22. 正向代理和反向代理

1. 正向代理：用户想访问某一接口时，用户先访问代理服务器，让代理服务器去替用户访问目标接口，再将拿到的数据返回给用户。

   正向代理可以用来解决跨域问题，还有隐藏用户真实ip，代理服务器还提供一个缓冲区用来缓存，再次访问直接取缓存，能提高访问速度。

2. 反向代理：流程基本跟正向代理一样，不同的是，正向代理知道自己访问的是代理服务器，反向代理用户是不知道自己访问的是代理服务器的。

   反向代理可以实现负载均衡，还有隐藏服务器真实ip，也有缓冲区缓存，也能提高访问速度，同时还能当防火墙，提供安全保障。

### 23. 硬件加速的原理

浏览器3D的动画会交给GPU进程去处理，GPU有成百上千个计算核心，适合去处理计算量大却简单的计算，3D渲染中有大量简单的计算，适合交给GPU去做，GPU还会为这个3D动画单独创建一个合成层，该合成层中的动画单独绘制，其它层就避免了重排，它不仅能提升性能，还能提升动画的帧数，但注意不能过多的使用，否则会导致内存问题。

如果你想使用3D动画却想开启硬件加速：`transfrom: translateZ(0)`
