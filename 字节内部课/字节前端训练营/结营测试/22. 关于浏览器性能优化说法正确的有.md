- [x] 给dom元素增加will-change属性，启动GPU加速
- [ ] 构建时尽量将资源合并，减少网络请求
- [ ] 在requestldleCallback回调里做上报操作


关于浏览器性能优化，说法正确的是：

-    给 DOM 元素增加 will-change 属性，启动 GPU 加速。

解析：

给 DOM 元素增加 will-change 属性可以启动 GPU 加速，提高页面渲染性能。will-change 属性告诉浏览器该元素将要被改变，浏览器可以提前将该元素加入 GPU 渲染流水线，加速页面渲染。

选项 B“构建时尽量将资源合并，减少网络请求”是一个优化方法，但是它并不是完全正确的，因为构建时有时候需要权衡资源合并和缓存的利弊。如果合并后的文件过大，会增加首次加载的时间。因此，这个说法并不是绝对的。

选项 C“在 requestIdleCallback 回调里做上报操作”是错误的，requestIdleCallback 是一个用于延迟执行任务的 API，用于在主线程空闲时执行任务，主要用于优化性能。在 requestIdleCallback 回调里执行耗时操作会影响页面的交互性能，因此不建议在回调里执行上报操作。

因此，选项 A“给 DOM 元素增加 will-change 属性，启动 GPU 加速”是正确的。
