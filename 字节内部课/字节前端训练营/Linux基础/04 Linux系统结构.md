# Linux基本组成
Linux系统一般由4个主要部分组成
- 内核 （提供操作系统的一些底层能力，内存管理，进程管理，硬件资源的管理）
- shell （命令解释器）
- 文件系统 （负责管理持久数据的子系统，负责把用户文件存在磁盘硬件中）
- 应用程序 （Vim，vscode）

# Linux体系结构
- 用户空间 （ 应用程序，C Library（ 封装好的系统标准调用库 ））
- 内核空间  （ 系统调用，内核，平台架构的相关代码）

安全方面讲，用户空间崩溃了，内核空间也不会崩溃）
权限角度讲：
内核程序运行于内核空间，拥有最高的权限，比如访问硬件设备的权限和对系统资源管理的权限。
应用程序运行于用户空间，拥有较低的权限，不能直接访问内存和硬件设备
(资源分配和管理的可控)

# 进程管理

- 进程是正在执行的一个程序或命令
- 进程有自己的的地址空间，占用一定的系统资源
- 一个CPU核同一事件只能运行一个进程
- 进程由它的进程ID（PID）和它父进程的进程ID（PPID）唯一识别
通过fork父进程拉起一个子进程，通过父进程模板创建子进程，不是通过接口创建出一个全新的进程

## 进程调度
通过进程调度的方法实现同一时间运行这么多的程序
（就是CPU将其进程时间做切分）
![[Pasted image 20230506154342.png]]

进程关闭时会进入僵死状态，然后发生消息给父进程，通过父进程关闭子进程
## 进程调度原则
- 一个CPU核同一时间只能运行一个进程
- 每个进程有近乎相等的执行时间
- 对应逻辑CPU而言进程调度使用轮询的方式执行，当轮询完成则回到第一个进程反复（所有的进程都被调用完了，就是回到下一轮的操作）
保证了所有的进程都能被执行到
- 进程执行消耗时间和进程量成正比

## 文件读取流程
![[Pasted image 20230506165104.png]]

以Nginx为例
读取：去用户缓冲区寻找数据缓存，如果命中的话，就返回，如果没有命中，就发一次系统调用也就是系统IO，当IO系统调用发起，就从用户态转换为内核态，然后再内核缓冲区寻找，命中的话就返回给用户缓存区，如果没有，就通过DMA（直接存储访问）然后拷贝到内核缓冲区，然后发信息给CPU，返回给用户缓冲区

DMA可以直接与磁盘进行交互
