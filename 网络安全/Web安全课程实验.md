## 2）参考https://cloud.tencent.com/developer/article/1041046；完成SQL注入攻击实验；需要至少完成一个low级别和一个medium级别的实验。

**SQL Injection（SQL注入）概念**

	通过把SQL命令插入到Web表单提交或输入域名或页面请求的查询字符串，最终达到欺骗服务器执行恶意的SQL命令。具体来说，它是利用现有应用程序，将（恶意）的SQL命令注入到后台数据库引擎执行的能力，它可以通过在Web表单中输入（恶意）SQL语句得到一个存在安全漏洞的网站上的数据库，而不是按照设计者意图去执行SQL语句。

**手工注入常规思路**
1.判断是否存在注入，注入是字符型还是数字型
2.猜解SQL查询语句中的字段数
3.确定回显位置
4.获取当前数据库
5.获取数据库中的表
6.获取表中的字段名
7.得到数据

#### （2）猜解SQL查询语句中的字段数
```sql
1' order by 2#
```

	对查询结果按照第二个列进行排序，并且排序顺序默认为升序（即从小到大）。"#"符号后面的部分可能是一种注释，用于注释掉查询语句的剩余部分。如果这个查询语句后面还有其他部分，那么这个符号就会忽略后面的内容，使其不被执行。

![[Pasted image 20230619043205.png]]

```sql
1' order by 3#
```

`对查询结果按照第三个列进行排序，并且排序顺序默认为升序。与之前的查询语句类似，"#"符号后面的部分可能是一种注释，用于注释掉查询语句的剩余部分`
![[Pasted image 20230619043228.png]]


#### （3）确定回显位置（为第二个位置）
```mysql
1' union select 1,2#
```

	- 第一个查询语句返回的结果集合是空的（因为"1'"这个字符串是无效的），但是"UNION"关键字告诉数据库将它和后面的查询结果合并在一起。
	- 第二个查询语句返回了两个列的结果集合，其中第一列包含了值"1"，第二列包含了值"2"。
	如果这个查询语句被执行成功，那么最终的结果集合将会包含两个行，每行有两个列。

![[Pasted image 20230619043357.png]]


#### （4）获取当前数据库

```sql
1' union select 1,database()#
```

	- 第一个查询语句返回的结果集合是空的（因为"1'"这个字符串是无效的），但是"UNION"关键字告诉数据库将它和后面的查询结果合并在一起。
	- 第二个查询语句返回了两个列的结果集合，其中第一列包含了值"1"，第二列包含了当前数据库的名称（使用了MySQL的内置函数database()）。
	如果这个查询语句被执行成功，那么最终的结果集合将会包含两个行，每行有两个列。第一个行的第一列是"1"，第二列是空的；第二个行的第一列是"1"，第二列是当前数据库的名称。
	
![[Pasted image 20230619043427.png]]3

#### （5）获取数据库中的表
```sql
1' union select 1,group_concat(table_name) from information_schema.tables where table_schema=database()#
```

	- 第一个查询语句返回的结果集合是空的（因为"1'"这个字符串是无效的），但是"UNION"关键字告诉数据库将它和后面的查询结果合并在一起。
	- 第二个查询语句返回了两个列的结果集合，其中第一列包含了值"1"，第二列包含了当前数据库中所有表的名称（使用了MySQL的内置函数group_concat()和information_schema.tables表）。
	如果这个查询语句被执行成功，那么最终的结果集合将会包含两个行，每行有两个列。第一个行的第一列是"1"，第二列是空的；第二个行的第一列是"1"，第二列是当前数据库中所有表的名称，这些表的名称用逗号分隔。
	

![[Pasted image 20230619045435.png]]


#### （6） 获取表中的字段名

```sql
1' union select 1, group_concat(column_name) from information_schema.columns where table_name='users'#
```

	第一个查询语句返回的结果集合是空的（因为"1'"这个字符串是无效的），但是"UNION"关键字告诉数据库将它和后面的查询结果合并在一起。
	第二个查询语句返回了两个列的结果集合，其中第一列包含了值"1"，第二列包含了名为"users"的表中所有列的名称（使用了MySQL的内置函数group_concat()和information_schema.columns表）。
	如果这个查询语句被执行成功，那么最终的结果集合将会包含两个行，每行有两个列。第一个行的第一列是"1"，第二列是空的；第二个行的第一列是"1"，第二列是名为"users"的表中所有列的名称，这些列的名称用逗号分隔。

![[Pasted image 20230619045444.png]]]]

#### （7）获取字段中的数据
```sql
1' union select user,password from users#
```

	- 第一个查询语句返回的结果集合是空的（因为"1'"这个字符串是无效的），但是"UNION"关键字告诉数据库将它和后面的查询结果合并在一起。
	- 第二个查询语句返回了两个列的结果集合，其中第一列包含了名为"user"的表中所有行的用户名，第二列包含了对应的密码（假设数据库中存在名为"users"的表）。
	
	如果这个查询语句被执行成功，那么最终的结果集合将会包含两个行，每行有两个列。第一个行的第一列是空的，第二列也是空的；第二个行的第一列是名为"user"的表中第一个用户的用户名，第二列是对应的密码。如果表中有多个用户，则第二个行的列的数量和值会随着查询结果的变化而变化。

## 3）参考https://cloud.tencent.com/developer/article/1517634；完成XSS攻击实验；也需要至少完成一个low级别和一个medium级别的实验。

**XSS漏洞概念**

	跨站脚本攻击（Cross Site Scripting），为了不和层叠样式表（Cascading Style Sheets，缩写：CSS）混淆，所以架构跨站脚本攻击缩写为XSS。XSS就是攻击者在web页面插入恶意的Script代码，当用户浏览该页面时，嵌入其中的js代码会被执行，从而达到恶意攻击的目的。某种意义上也是一种注入攻击，是指攻击者在页面中注入恶意的脚本代码，当受害者访问该页面时，恶意代码会在其浏览器上执行，需要强调的是，XSS不仅仅限于JavaScript，还包括flash等其它脚本语言。

**XSS的类型**

1.反射型XSS

	反射型XSS只是简单的把用户输入的数据“反射”给浏览器，也就是需要诱使用户“点击”一个恶意链接，才能攻击成功。反射型XSS也叫作“非持久性XSS”

2.存储型XSS

	存储型XSS会把用户输入的数据“存储”在服务器端。如果没有过滤或者过滤不严，那么这些恶意代码被服务器端接收并存储，用户访问该页面的时候触发代码执行。这种XSS具有很强的稳定性，当再次访问页面时会被执行。<持久化>.这种XSS比较危险，容易造成蠕虫，盗窃cookie等。
	存储型XSS和反射型XSS、DOM型XSS相比，具有更高的隐蔽性，危害性也更大。它们之间最大的区别在于反射型XSS与DOM型XSS执行都必须依靠用户手动去触发，而存储型XSS却不需要。

3.DOM Based XSS

	DOM的全称为Document Object Model，即文档对象模型，DOM通常用于代表在HTML、XHTML和XML中的对象。使用DOM可以允许程序和脚本动态低访问和更新文档的内容、结构和样式。
	实际上，这种类型的XSS并非按照“数据是否保存在服务器端”来划分的，从效果上来说也是反射型XSS单独划分出来的，因为DOM Based XSS的形成原因比较特别。这是由于客户端脚本自身解析不正确导致的安全问题。
	这种利用也需要受害者点击链接来触发，DOM型XSS是前端代码中存在了漏洞（DOM型的XSS是不需要与服务器交互的，它只发生在客户端处理数据阶段），而反射型是后端代码中存在了漏洞。
	反射型和存储型xss是服务器端代码漏洞造成的，payload在响应页面中，在dom xss中，payload不在服务器发出的HTTP响应页面中，当客户端脚本运行时（渲染页面时），payload才会加载到脚本中执行。
